# Ошибки заполнения форм

`shared/ui/form-validation` — общий контекст ошибок формы, не хранилище её значений. Значения и запросы остаются в существующих моделях, React Hook Form и TanStack Query.

- `ValidatedForm` проверяет HTML-ограничения и зарегистрированные составные поля перед отправкой. Показывает сводку с переходами к полям; переводит фокус к первой ошибке. Данные ввода не сбрасываются.
- `ValidatedTextField` связывает `name` с путём входной схемы API, например `data.description` или `contacts.0.name`. Ошибка отображается рамкой и текстом, доступна скринридеру. Для нового поля обязательно указывать имя, соответствующее API.
- `ValidationField` связывает составные поля (выбор ЕКП, набор карточек, признаки) с проверкой и сообщением. `false` — полноценный ответ; обязательность определяется активной веткой ЕКП. Генератор допускает случайные значения.
- `getApiFieldErrors` разбирает структурированные `detail[].loc` ответа сервера, исключая `body`. Серверные `input` и произвольный текст валидации не выводятся. Общие ошибки сети/прав доступа/конфликтов показываются сообщением формы: они не приписываются случайному полю.
- `FieldErrors` использует то же оформление в АРМ без замены его разметки на HTML-форму. Фокус меняется после попытки отправки, а не при каждом вводимом символе. Незавершённый черновик разрешён. Проверка полноты не сверяет работу с эталоном и не сообщает правильный ответ.

Подключено: библиотечные карточки, генератор, сценарии, назначение занятий, ручная оценка и публикация разбора, пользователи и причина отключения, группы, сообщения преподавателя, правила ЕКП/профили/службы, телефония, статусы ДДС, карточка ученика 112. Вход/смена пароля сохраняют уже существующие полевые ошибки React Hook Form.

Проверки: модульные тесты ограничений, обязательных признаков, ошибки 422 и сохранения черновика; `e2e/form-validation.spec.ts` проверяет реальные DOM/focus/submit на API-фикстурах. Скриншоты в `docs/screenshots/form-validation`. Проверка клиента дополняет валидацию backend, не заменяет её.
