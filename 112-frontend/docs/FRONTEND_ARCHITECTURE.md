# Архитектура frontend

**FSD обязателен для всех изменений.** Компоненты, модели, типы и стили должны
оставаться в своих сегментах. Размер страницы не является поводом помещать в неё
новую независимую форму, контракт API или бизнес-логику.

## Слои и публичный API

Направление зависимостей: `app → pages → widgets → features → entities → shared`.
Слой может пропускать промежуточные слои, но не импортировать верхние.
Соседние слайсы `pages`, `widgets`, `features`, `entities` не импортируют друг друга.
Связывать их следует на верхнем слое: например, страница соединяет feature разбора
результата с виджетом АРМ через props/слот. `app` и `shared` состоят из сегментов.

Другой слайс импортируется через его корневой `index.ts`; внутри слайса используйте
относительные импорты. Не переэкспортируйте feature из entity ради старого пути.
Общий код не должен знать об учебных сценариях и ролях пользователя.

## Сегменты

- `ui/` — компоненты и разметка. Независимые диалоги и формы — отдельные файлы.
- `model/` — состояние, хуки процесса, вычисления и константы предметной области.
- `api/` — запросы и преобразование ответов сервера.
- `lib/` — чистые вспомогательные функции слайса.
- `types/` — именованные типы, DTO, интерфейсы и props; никаких runtime-констант.
- `styles/` — SCSS, типизированные объекты MUI `sx`/React `CSSProperties` и функции
  динамических стилей. Не создавайте объекты `sx={{…}}` / `style={{…}}` в JSX.

Локальный тип можно выводить из существующего контракта через `Pick`, `ReturnType`
или `typeof`; не дублируйте DTO. Простая аннотация callback или generic не требует
отдельного файла. Тесты располагаются рядом с проверяемым модулем; их фикстуры могут
импортировать код нескольких слоёв. Это исключение не распространяется на приложение.

Редактор карточки находится в `features/card-authoring`, генерация — в
`features/card-generation`. Телефонные преобразования находятся в
`entities/phone/lib`, hook ввода — в `model`. Сохранённый демонстрационный процесс,
который связывает несколько сущностей, — `features/demo-training`.

## Кликабельность и обратная связь

Если вся строка открывает одну сущность, применяйте `shared/lib/rowAction`.
Он поддерживает мышь, Enter и пробел; вложенные кнопки/ссылки/поля работают
самостоятельно. Сохраняйте доступное явное действие внутри строки. Не используйте
кликабельный `div` вместо семантической кнопки или ссылки.

Кнопки, ссылки и строки-действия должны иметь подсветку hover, клавиатурный focus-visible
и состояние active. Общие стили находятся в `app/styles/interactions.scss`:
переход 150 мс, без задержки выполнения действия. При `prefers-reduced-motion`
переход отключён. Специализированный компонент может менять оформление, сохраняя
все три состояния. Заблокированный элемент не должен выглядеть активным.

Поля ввода используют собственную тонкую рамку или подчёркивание: не накладывать
на них общую заливку кнопок и дополнительный outline. Выделение и копирование
введённого текста сохраняются. Ошибки валидации остаются видимыми.

Серверное состояние ведётся через TanStack Query, общий сеанс — через Zustand,
формы — через React Hook Form. [Решение и границы ответственности](STATE_AND_API.md).

Нередактируемая оболочка АРМ не выделяется. Поля ввода и явно копируемые сведения
(`data-selectable`, `pre`) сохраняют выделение; глобально блокировать copy нельзя.

## Проверки

Node и браузер запускаются только в Docker; команды приведены в README.
`npm run lint` включает `check:architecture`: проверяет направление зависимостей,
публичные API слайсов, размещение типов/SCSS и отсутствие объектов стилей в JSX.
`npm run build` проверяет TypeScript и сборку; `npm test` — поведение функций и форм.
Перед сдачей изменений интерфейса обязательны браузерная проверка и личный просмотр
снимков с сопоставлением целевому АРМ. Тесты реального API запускаются на отдельной
тестовой БД, а не на рабочих данных.

Общий объект редактора, который нужен нескольким вложенным панелям, передаётся
через context с областью одного редактора. Для карточки и ДДС используются
`IncidentCardContext` и `DDSWorkspaceContext`. Типы context находятся в `types`,
сам context и hook чтения — в `model`; вне provider hook сообщает об ошибке.
Не передавать этот же объект одновременно через props и context. Индивидуальные
параметры отображения и события компонента оставлять props. Zustand использовать
для состояния, которому действительно нужна общая область за пределами дерева
редактора; не помещать туда Query-кэш или глобальную копию текущей карточки.
Состояния отправки (`pending/error/success/data`) брать из mutation, не отражать
их в параллельных useState и ручных try/catch/finally.
