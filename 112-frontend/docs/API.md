# Работа фронтенда с API

Все рабочие страницы используют FastAPI с префиксом `/api/v1`. Контракт запросов и ответов доступен в Swagger запущенного бэкенда: http://localhost:8000/docs. Демонстрационные ответы используются только в тестах.

## Как проходит запрос

1. Модель страницы или feature вызывает query/mutation своей сущности.
2. HTTP-функция сущности обращается к общему клиенту `shared/api/backendApi`.
3. Клиент добавляет токен и при необходимости выполняет один refresh.
4. TanStack Query сохраняет ответ; после записи обновляются затронутые списки и детали.

[Настройка адреса API](DEVELOPMENT.md) · [Правила состояния](STATE_AND_API.md) · [Авторизация](AUTH.md).

## Кто владеет контрактами

| Сущность            | Ответственность                                    |
| ------------------- | -------------------------------------------------- |
| `entities/user`     | Сессия, пользователи, профили, фотографии и группы |
| `entities/catalog`  | ЕКП, службы, профили служб и справочник бригад     |
| `entities/training` | Карточки, сценарии, занятия, сообщения и оценки    |

Списки используют компактные представления `/views/*`. Детальное решение загружается при открытии карточки, а не для каждой строки таблицы. Не добавляйте запрос на каждую строку, если сервер уже возвращает нужную проекцию.

## Ошибки и конкурирующие изменения

Сервер возвращает пользовательский `message` и `field_errors` с `path`, `message`, `code`. Показывайте ошибку рядом с полем и в сводке; раскрывайте нужный раздел и прокручивайте к первой ошибке. Не определяйте поле сравнением английских текстов исключений.

Редактируемые сущности передают ревизию. При конфликте сохраняйте ввод пользователя и предложите явно загрузить актуальные данные. Не повторяйте запись со свежей ревизией автоматически: это может затереть чужое изменение.

Сбой сети или 5xx не означает неверный пароль или неверный ответ ученика. Не очищайте сессию и ввод из-за временной недоступности API.

## Важные ограничения

- Аккаунт имеет одну неизменяемую роль. Администратор не получает права преподавателя.
- Библиотечную карточку можно редактировать, пока она не использована в сохранённой версии сценария. Назначенные работы используют снимки.
- Ученик получает только разрешённые ему данные. Скрытие кнопки не заменяет проверку доступа сервером.
- Подсказки, нормативы, сдача и оценивание определяются бэкендом. Фронтенд отображает состояние, но не назначает баллы самостоятельно.
- ИИ работает в фоне: отсутствие готового заключения не равно ошибке ученика.
