# Интеграция учебного процесса

Рабочие страницы используют FastAPI `/api/v1`, общий bearer-клиент и реальную
сессию. Fake API и его переключатель удалены. Старые демонстрационные модели
оставлены для изолированных примеров/тестов; учебные страницы их не используют.

## Доступные процессы

- Администратор: создание пользователей с одной выбранной ролью, обязательной
  сменой стартового пароля; редактирование ФИО/email/роли, отключение аккаунтов,
  даты создания, изменения, входа и смены пароля; создание служб, JSON-версии ЕКП и её публикация.
- Преподаватель: группы и добавление учеников, библиотека эталонных карточек,
  упорядоченные сценарии, сохранение новой редакции, запуск всей группы или одного
  ученика, наблюдение за прогрессом, просмотр работ и ручная оценка с комментарием.
- Ученик: собственные уроки, последовательное выполнение карточек оператора 112,
  сообщение заявителя, серверный черновик, поиск типа в назначенном ЕКП,
  рассчитанные получатели, учебное оповещение, ожидание проверки и её результат.
- Аналитика: последние оценки преподавателя по собственным урокам; средние значения
  приведены к процентам от максимального балла. Отсутствующая оценка не равна нулю.

Уточнение пользователя: в дальнейшем оценка будет и от ИИ, и от преподавателя.
В этой интеграции ИИ не оценивает. Выполнение ДДС и SIP явно обозначены как
недоступные. Автоматические подсказки и завершение по лимиту не подключены.

## Состояние и архитектура

Слои `app → pages → widgets → features → entities → shared` сохранены. Реальные DTO
и запросы находятся в `entities/training`. `widgets/lesson-list` использует
агрегированные страницы `/views/*`. Запуск урока и ручная проверка — отдельные
features. Адаптер карточки отделяет серверные поля от существующих ARM-контролов.
Визуальная библиотека не содержит API, состояние сессии или сценарии.

Списки имеют серверный поиск/пагинацию. Выпадающие каталоги ищут на сервере и явно
показывают первые 20 совпадений. Не загружается весь ЕКП или набор аккаунтов.
Открытие журнала — один запрос; полная попытка загружается при открытии карточки.
Последняя оценка и прогресс приходят вместе со строками уроков. Полные скрытые
данные сценария доступны только преподавателю.

Кнопка «Сохранить черновик» сохраняет поля и `revision`. При конфликте или сетевой
ошибке форма сохраняет ввод и показывает ошибку. При закрытии несохранённого ввода
появляется подтверждение. Перезагрузка восстанавливает последнюю серверную копию;
несохранённые поля не записываются в localStorage. Перед оповещением сохраняется
актуальный черновик и передаётся полученная ревизия. Следующая карточка становится
доступной только после подтверждения сервера. Статус «Оповещено» не означает
завершение работ служб. Все действия остаются учебными.

Редактирование сценария создаёт новую версию; назначенные уроки не меняются.
Учебный ориентир таймера и длительность сценария сохраняются миграцией backend
`0006_frontend_scenarios`. Лимит отдельной попытки задаётся при запуске урока.
Для условных маршрутов ЕКП сервер возвращает объяснимую ошибку: интерфейс не
подставляет произвольные службы. Дополнительные вопросы по типам пока не
поступают из API; доступно текстовое уточнение с сохранением и просмотром.

## Docker-проверки

Сборка, линтер, Vitest и Playwright запускаются только в Docker (команды в README).
Обычные браузерные тесты используют явные HTTP-фикстуры. Сквозной тест
`e2e/integration-real.spec.ts` использует настоящий backend с отдельной БД и требует
`AUTH_ISOLATED_API=true`, `API_PROXY_TARGET`. Он создаёт тестовые записи,
проходит все роли, проверяет восстановление черновика, конфликт ревизий, две
карточки, ручную оценку и аналитику. Не направлять его на рабочую БД.

Проверенные скриншоты реального процесса: `docs/screenshots/api-*.png`.
Журнал, ввод и просмотр карточки проверены рядом с исходными скриншотами.
Проверки размеров 1920, 1366 и 390 пикселей — `e2e/arm-layout.spec.ts`.

## Эталоны и предварительная оценка

Форма карточки поддерживает отдельную строку адреса и структурированные поля
(населённый пункт, улица, дом, корпус, строение, квартира, подъезд, этаж).
При заполнении компонентов строка адреса собирается автоматически. Количество
пострадавших необязательно: пустое поле означает отсутствие эталона, 0 — отсутствие
пострадавших по условию. Эталон должен опираться только на сведения из задания.

Результаты преподавателя содержат сводку и таблицы совпадений, пропусков и расхождений.
Предварительный процент равен доле совпавших структурированных полей с эталоном;
вес каждого поля — 1. Тексты и свободный адрес не входят в балл, смысл проверяет
преподаватель. Результат черновика помечен как неполный. Итоговую оценку преподаватель
выставляет отдельно; ученику и аналитике показывается именно она. ИИ не используется.
