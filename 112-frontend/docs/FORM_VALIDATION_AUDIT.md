# Аудит похожих ошибок сохранения — 27.09.2026

Проверены общая обработка ошибок API, редакторы карточек и сценариев, назначение занятий, редактор правил ЕКП и создание пользователей. Это целевая проверка обратной связи при сохранении, а не полный аудит всех бизнес-правил системы.

| Найденная проблема | Исправление |
| --- | --- |
| Карточка ДДС поступает на границе/после окончания сценария: модель возвращает ошибку всего объекта, поле не подсвечивается. | До отправки проверяется суммарное расписание. Выделяется интервал конкретной карточки; пояснение предлагает уменьшить интервал или увеличить длительность. Серверная проверка также распознаётся. |
| После смены роли/профиля в сценарии остаются ранее выбранные несовместимые карточки; причина серверного отказа теряется. | Сервер указывает список карточек и называет несовместимую карточку. Выбор не удаляется автоматически. |
| Дата окончания занятия равна началу либо уже прошла. | Проверка до окна подтверждения, подсветка даты окончания. Серверные отказы также привязаны к полю. |
| Отработка навыка невозможна для выбранной карточки; назначение закрывает подтверждение, оставляя общий 422. | Структурированная ошибка в блоке навыков с названием карточки, навыка и способом исправления. Технические коды навыков заменены названиями. |
| Редактор ЕКП ожидает ошибки `features...`, API возвращает `entry.features...`. Условия разных маршрутов также имели одинаковые имена. | Имена приведены к контракту API, условия маршрутов/показа получили уникальные пути. Выбор службы маршрута обязателен. Для дублей вариантов и ошибок условий выводится конкретное пояснение. |
| Занятый логин и дубли названий/кодов дают общий конфликт. | Известные отказы привязаны к логину, коду службы и названию версии ЕКП. |
| Простое нажатие по пояснению группы снимало ошибку без изменения данных. | Такие клики больше не снимают ошибку. Изменение значений и выбор вариантов продолжают её очищать. |
| После удаления условного поля ошибка оставалась до следующего сохранения. | При удалении поля снимается его регистрация и ошибка; перерисовка существующего поля не очищает ошибку. |

## Реализация

Общий справочник переводов API выделен в `src/shared/api/errorMessages.ts`. `constraintFields.ts` связывает известные доменные отказы с полями; неизвестные сообщения сервера по-прежнему не раскрываются. `getApiError` переиспользует тот же разбор вместо отдельного вывода технических путей.

Backend `app/core/validation.py` предоставляет структурированный отказ `form_constraint` для сценариев и совместимости навыков. Проверки допустимости не ослаблены. БД, миграции, seed и прежние оценки не меняются.

## Проверка

- Backend: 494 теста на отдельной PostgreSQL, в том числе реальное создание несовместимого сценария и проверка структуры отказа для навыка.
- Frontend: полный прогон 163 unit-теста; build, lint и FSD проходят.
- Playwright: 10 различных сценариев Chromium и 3 Firefox. Первоначальный новый тест занятия исправлен из-за неточного названия кнопки навыка; повтор прошёл. После уточнения фокуса расписания и навыков 6 новых проверок повторены. Покрыты сохранение после исправления, сохранность введённых данных, выделение полей, навигация и регрессии карточки ДДС/АРМ.
- Скриншоты лично просмотрены: `docs/screenshots/validation-audit`. Браузерные проверки используют API-фикстуры; backend проверен отдельно на PostgreSQL.

Не гарантируется, что любой неизвестный ответ внешнего сервиса удастся связать с конкретным полем. Для таких ответов остаётся общее сообщение; новые бизнес-проверки следует оформлять структурированными ошибками с безопасным пояснением и реальным путём к полю.
