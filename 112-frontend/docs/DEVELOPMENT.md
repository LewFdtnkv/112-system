# Разработка фронтенда

## Что установить

- Node.js 24 и npm. Версии пакетов зафиксированы в `package-lock.json`.
- Git.
- Для браузерных проверок — браузер Playwright, установка ниже.

Docker нужен только при запуске всей системы через Compose. Обычная разработка фронтенда выполняется на хосте.

## Первый запуск

Запустите API по [инструкции бэкенда](../../112-backend/README.md#разработка). Затем из каталога `112-frontend`:

```sh
npm ci
API_PROXY_TARGET=http://localhost:8000 npm run dev
```

Интерфейс откроется на http://localhost:5173. Изменения кода подхватываются автоматически.

`API_PROXY_TARGET` передаётся процессу Vite: одного добавления этой переменной в `.env` недостаточно. Указывайте её при каждом запуске или экспортируйте в терминале. Без неё текущая конфигурация использует адрес контейнерного окружения `host.docker.internal:8000`.

Для PowerShell:

```powershell
$env:API_PROXY_TARGET = "http://localhost:8000"
npm run dev
```

Браузер обращается к `/api/v1`, а Vite перенаправляет запросы на API. Обычно менять `VITE_API_URL` не нужно; если нужен другой публичный префикс, задайте его в `.env` по образцу `.env.example`.

## Проверки

```sh
npm run lint
npm test -- --maxWorkers=2
npm run build
```

| Команда         | Что проверяет                          |
| --------------- | -------------------------------------- |
| `npm run lint`  | ESLint и границы FSD                   |
| `npm test`      | Функции, состояние и формы в Vitest    |
| `npm run build` | TypeScript и итоговую сборку в `dist/` |

Браузерные проверки с подменой API:

```sh
npx playwright install chromium
npm run test:e2e -- --workers=2 --grep-invert 'real API:'
```

Playwright сам поднимает Vite на порту `4173`. Для проверки уже запущенного интерфейса задайте `PLAYWRIGHT_BASE_URL`. В Linux для установки системных библиотек браузера может понадобиться `npx playwright install --with-deps chromium`.

Сценарии с префиксом `real API:` изменяют данные. Запускайте их только с отдельным API и тестовой БД; необходимые переменные указаны в соответствующем файле `e2e/`. Например, тест первого входа требует `AUTH_ISOLATED_API=true` и меняет пароль начального администратора.

После изменения интерфейса откройте нужный экран, проверьте его в браузере и сравните снимок с исходным АРМ. Успешная сборка не подтверждает правильность вёрстки.

## Если не работает

- **Запросы `/api/` завершаются ошибкой:** проверьте доступность API на порту `8000` и значение `API_PROXY_TARGET`, затем перезапустите Vite.
- **Не установлен пакет:** выполните `npm ci`; не переносите `node_modules` между хостом и контейнером.
- **Вход требует сменить пароль:** это поведение нового аккаунта. Тестовые учётные записи создаются [seed-скриптом](../../112-backend/docs/DEMO.md).
