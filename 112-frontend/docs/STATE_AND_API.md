# Где хранится состояние

У каждого вида данных один владелец. Серверные ответы не нужно копировать в Zustand или `useState`, а открытие диалога не требует глобального хранилища.

| Данные                                               | Инструмент                    | Пример                                        |
| ---------------------------------------------------- | ----------------------------- | --------------------------------------------- |
| Списки и детали с сервера, загрузка, ошибки запросов | TanStack Query                | Карточки, занятия, результаты                 |
| HTTP и обновление токенов                            | ky и общий клиент             | `shared/api/backendApi`                       |
| Общая сессия                                         | Zustand                       | `entities/user/model/authStore`               |
| Несинхронизированный ответ 112                       | Zustand persist, localStorage | Несохранённые поля текущей попытки            |
| Поля и ошибки формы                                  | React Hook Form               | Вход, создание и редактирование               |
| Связанные изменения черновика                        | Reducer в модели слайса       | Смена типа происшествия и сброс его признаков |
| Открытый диалог, поиск, выбранная вкладка            | Локальный React state         | Состояние одного экрана                       |
| Доступ вложенных панелей к модели редактора          | React Context                 | `IncidentCardContext`, `DDSWorkspaceContext`  |

## Запросы и изменения

`QueryProvider` создаёт общий QueryClient. Ключи, query options и инвалидация принадлежат соответствующей сущности; HTTP-функции находятся в `api`, хуки — в `model`, контракты — в `types`.

Для чтения используйте `useQuery`, для обычных команд экрана — `useMutation`. Состояния `pending`, `error` и `data` берите из них. Передавайте `AbortSignal` в запрос. Повтор записи безопасен только при поддержке идемпотентности сервером.

После изменения обновляйте или инвалидируйте все затронутые представления. Например, `invalidateCard` обновляет не только библиотеку, но и выбор карточки в сценарии. Для пользователей и групп есть `invalidateUser` и `invalidateGroupMembers`.

У попытки один ключ `trainingKeys.attempt(id)`. Сохранение и сдача используют одинаковый `scope.id` mutations, чтобы выполняться последовательно. Перед записью отменяется незавершённое чтение, а ответ записи попадает в кэш. Для сохранённого локально черновика используется его базовая ревизия: свежий фоновый запрос не даёт права затереть чужие изменения.

## Формы и контексты

`ValidatedForm` использует регистрацию и ошибки React Hook Form; `ValidationField` подключает составные поля. Если форма уже имеет экземпляр RHF, передайте `form` и `onValid`, не создавайте второй `handleSubmit`.

Context действует в пределах одного редактора. Он передаёт модель вложенным панелям, но не создаёт ещё одну копию данных. Не передавайте ту же модель одновременно через props и context. Индивидуальные параметры компонента оставляйте в props.

Reducer нужен, когда одно действие меняет несколько связанных полей. Например, `cardEditorReducer` обрабатывает смену ЕКП, а `scenarioEditorReducer` — состав карточек и интервалы их поступления. Для независимого флажка `useState` проще и уместнее.

## Сессия, черновик и аудит

Только токены сессии сохраняются в sessionStorage; профиль и права восстанавливаются с сервера. При выходе или смене пользователя Query-кэш очищается. Параллельные запросы ждут одну операцию refresh; ответ прежнего сеанса не должен восстановить его после выхода.

Локальный черновик 112 — запасная копия несинхронизированных полей, а не автономная БД. Он привязан к пользователю и попытке; конфликт требует решения ученика. ДДС-команды и аудит туда не записываются.

Очереди действий ученика и прокторинга обеспечивают порядок и повтор доставки событий. Они решают другую задачу, чем кэш Query, поэтому не заменяются обычным `useQuery`.

## Восстановление черновика 112

Ключ localStorage разделён по пользователю и попытке. Запасная копия удаляется после подтверждения записи сервером; новый ввод во время запроса остаётся в очереди. При изменении серверной ревизии ученик выбирает свой черновик или актуальную версию. Завершённая попытка не восстанавливается как редактируемая.

Повреждение или переполнение хранилища и изменение данных другой вкладкой показывают предупреждение. Копия относится к одному браузеру и origin, не шифруется и не заменяет серверное сохранение. Для открытия занятия, сдачи, подсказок и команд ДДС нужен сервер. Офлайн-время не продлевает срок.
