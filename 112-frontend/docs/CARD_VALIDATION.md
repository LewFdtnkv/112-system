# Ошибки в редакторе учебной карточки

При сохранении форма показывает конкретные причины отказа, выделяет связанные поля и переводит фокус к первой ошибке. Кнопки в сводке позволяют вернуться к каждому полю. Значения формы сохраняются для исправления.

Профиль ДДС должен относиться к одной из служб-получателей в общих данных карточки. Например, получатель «ДДС района Южное Медведково» и профиль «ДДС Тверского района» несовместимы: нужно добавить службу выбранного профиля в получатели либо выбрать соответствующий получателям профиль. Форма проверяет это до отправки, API независимо проверяет при создании и редактировании.

Для ДДС обязательны хотя бы одна учебная цель и сообщение ученику. Серверные ошибки начального статуса, хронологии истории и уже выполненной/недостижимой цели привязаны к конкретному полю бригады. Необязательные признаки ЕКП остаются необязательными.

## Контракт и границы

- Backend возвращает `detail: [{loc: ["body", ...path], type: "card_constraint", msg: "..."}]` для известных проверок карточки. Адаптер `authoring/card_validation.py` переводит общие доменные отказы только на границе создания/редактирования карточки, сохраняя контракты команд ученика.
- Схема `DDSExercise` сообщает путь к конкретному статусу/времени/цели вместо общей ошибки всего объекта. Правила допустимости не ослаблены.
- Frontend доверяет тексту только явно разрешённых кодов проверок (`card_constraint`, `generation_constraint`). Произвольные сообщения Pydantic с отражением пользовательского ввода не выводятся.
- `ServerSelect.validate` дополняет обязательность проверками совместимости. `ValidationField` и `ValidatedTextField` связываются с сервером по именам полей. Если вложенного поля уже нет, навигация ищет ближайшую именованную группу.
- Миграции и перезапуск seed не требуются. Существующие карточки и оценки не переписываются.

## Проверки

`e2e/card-validation.spec.ts`: desktop/mobile, Chromium/Firefox, несовпадение служб, переход из сводки, отсутствие целей после смены профиля, серверная ошибка истории, исправление и успешное сохранение, пустой необязательный признак. Скриншоты: `docs/screenshots/card-validation`.

Backend: `tests/test_card_validation_fields.py` проверяет реальные API создания/изменения, неизменность карточки после отказа, точные пути ошибок ДДС и обязательность/необязательность признаков ЕКП.
