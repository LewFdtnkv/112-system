# Ошибка после входа из открытой до обновления вкладки

27.09.2026 проверен эпизод 10:47:11 UTC (13:47:11 МСК) на локальном стенде, Firefox/macOS.

- POST `/api/v1/auth/login` — HTTP 200.
- GET `/api/v1/users/me` — HTTP 200.
- Сразу затем браузер запросил прежние файлы `student-dashboard-B8ZpsDuU.js`, `lesson-list-Docmepdd.js` и другие. Все отсутствующие JS получили одинаковый ответ 200 / 1398 байт: SPA fallback `index.html` вместо JavaScript.
- После ручной перезагрузки в 10:47:17 загружены актуальные `student-dashboard-Dbz9UBtB.js` (924 байта), `lesson-list-D2VliInV.js` (6909 байт), запросы кабинета — HTTP 200.
- В доступных журналах этого эпизода нет HTTP 503. Общая страница ошибки React Router показывала «500. Произошла ошибка» при отказе динамического импорта. Это сбой загрузки версии интерфейса, а не ожидание ответа авторизации. Исторические журналы прежних пересозданных контейнеров недоступны; все возможные прошлые 503 этим не объясняются.

## Исправление

Nginx возвращает 404 для отсутствующих `/assets/*`, без подмены HTML; существующие файлы с хешами кешируются как immutable. HTML/SPA и map-config.js получают `Cache-Control: no-cache`.

Обработчик `vite:preloadError` устанавливается до создания роутера. На входных маршрутах `/` и `/login` однократно перезагружает документ при отказе импорта. Токены в sessionStorage сохраняются, повторная отправка логина/пароля не нужна. Защита от повторной автоматической перезагрузки действует 60 секунд на вкладку. Если sessionStorage недоступен, автоматического повтора нет.

На остальных маршрутах автоматической перезагрузки нет. Для ошибки импорта показано понятное сообщение и кнопка настоящей перезагрузки документа; обычные API/404/403 ошибки обрабатываются прежним способом. Дизайн рабочих карточек и стили не менялись.

Основание: [официальное описание Vite preloadError и Cache-Control](https://vite.dev/guide/build#load-error-handling).

## Проверка

Production build в отдельном Nginx, API-фикстуры. Четыре проверки в Chromium и четыре в Firefox: пропавший chunk после входа восстанавливается без повторного логина; постоянный отказ не вызывает цикл; последующая навигация не вызывает автоматического reload; HTML и отсутствующие assets имеют правильные HTTP ответы. Снимки страницы восстановления: `docs/screenshots/asset-recovery`.

Build/lint/FSD и 10 регрессионных unit-тестов маршрутизации/сеанса прошли. Рабочая БД, backend, пароли и API-контракты не менялись.

Повтор браузерных проверок: сначала собрать фронтенд, раздать `dist` через Nginx с `nginx.conf`; задать `ASSET_RECOVERY_CHECK=1`, `PLAYWRIGHT_BASE_URL` и запустить `e2e/asset-recovery.spec.ts` через `npm run test:e2e`. Для Firefox дополнительно `ASSET_BROWSER=firefox`, `ASSET_BROWSER_PATH`.
