# Разбор карточек и эталонное решение

[Открыть галерею всех вариантов](screenshots/card-review/index.html).
Снимки получены из работающего приложения с реальным API и отдельной тестовой БД.
Везде используется одна учебная работа: верная улица, неверный номер дома,
пропущенные телефон и корпус, переформулированное описание, неполный набор признаков.

## Выбранный интерфейс

По последнему пожеланию пользователя по умолчанию — **«Таблица»**: поле,
ответ ученика, эталонное решение и результат проверки видны на одной строке.
Решение видно сразу, без раскрывающей стрелки. Для подробного чтения сохранён
режим «Рядом», сгруппированный по заявителю, адресу, происшествию и службам.
Для быстрого разбора есть фильтр расхождений и полей, требующих проверки.

| Вариант | Назначение и результат сравнения |
| --- | --- |
| [Рядом](screenshots/card-review/01-paired.png) | Подробный разбор: легко сопоставить каждое поле, длинные тексты имеют достаточно места. |
| [Блоками](screenshots/card-review/02-blocks.png) | Каждое поле — отдельный блок с двумя значениями. Удобен для последовательного чтения, занимает больше места. |
| [Таблица](screenshots/card-review/03-table.png) | Выбран по умолчанию пользователем: самый компактный обзор множества полей. |
| [Ответ в АРМ](screenshots/card-review/04-arm-answer.png) | Дополнительный контекст: исходная форма ученика с подсветкой полей и эталонным значением при наведении. |
| [Эталонное решение в АРМ](screenshots/card-review/05-arm-reference.png) | Просмотр подготовленного решения в той же форме; режим переключается прямо в АРМ. |

Все варианты доступны преподавателю. В АРМ есть кнопки предыдущей/следующей
карточки, номер и название ситуации, переключатель ответа и эталонного решения.
При переходе сохраняется выбранная сторона. Для неначатой карточки в режиме
ответа показана пустая форма и явное сообщение; эталон вместо ответа не подставляется.
Службы используют тот же компонент плитки, что и рабочее место; нажатие раскрывает
полное название. На границах списка кнопки перехода отключены.

Все четыре подхода реализованы и просмотрены на одной работе. На узком экране пары перестраиваются
вертикально с явными подписями сторон; [снимок шириной 768 px](screenshots/card-review/06-paired-tablet.png).

## Цвета и смысл проверки

- Зелёный — совпадение по существующим серверным правилам проверки.
- Красный — расхождение или пропуск проверяемого структурированного поля.
- Жёлтый — требуется проверка смысла либо поле ещё не заполнено в черновике.
- Нейтральный — значение вне автоматической проверки.

Цвета сопровождаются текстом и значками. Расхождение свободного текста не
равно неправильному ответу. Жёлтый пока **не является решением ИИ**:
ИИ ещё не подключён. Формула балла и возможность ручного пересмотра сохранены.
Непроверяемые поля отмечены «Вне балла». Ноль и «Нет» не считаются пустыми значениями.

## Подготовка и просмотр карточки

В [форме создания](screenshots/card-review/08-template-editor.png) слева находятся
условие и инструкция для ученика, справа — всегда открытое «Эталонное решение»:
заявитель, сообщение, отдельные адресные поля, тип, признаки и службы.
При прокрутке условие остаётся рядом. [Просмотр библиотечной карточки](screenshots/card-review/07-template-view.png)
использует то же разделение и кнопку открытия решения в АРМ.

Ученик открывает [завершённую карточку](screenshots/card-review/09-student-card.png)
в знакомой форме без возможности изменить результат. Эталонные данные и
преподавательская подсветка ему не передаются. Учитель открывает ответ только
для чтения: команды сохранения и оповещения недоступны, ревизия не меняется.

## Архитектура и проверка

`features/lesson-review` строит сравнение из снимка задания, фактической карточки
и серверной автопроверки. Страница связывает его с `widgets/incident-card` через
слот действий. Общий адаптер данных перенесён в `features/incident-editing`;
он используется и рабочим местом, и просмотром. `shared/ui/arm` получает только
визуальные состояния полей, без зависимости от оценивания и API.

Ответ преподавательского `GET /cards/{id}` дополнен `classifier_entry` и
`recipients` с полным и коротким именами служб. Дополнительных запросов для
просмотра в АРМ не требуется. Доступ и владение карточкой проверяет сервер.
Миграций БД нет.

Проверки: 161 backend-тест, 70 Vitest, build/lint; реальные браузерные сценарии
разбора карточки, полного процесса оператора 112 и каталога/ДДС. Новый тест
`e2e/card-review-real.spec.ts` проверяет все виды, фильтр, подсветку, чтение без
изменений, доступ ученика и сохраняет снимки. Node и браузер запускаются в Docker.
