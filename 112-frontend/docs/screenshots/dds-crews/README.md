# ДДС: службы, бригады и история

Проверка через реальный API на отдельной БД. Исходный ориентир —
«СКРИНШОТ ДДСГСИ.docx», изображения 6–10 и 17–20: нижние плитки служб,
дополнительный ряд, синяя история и компактная форма статуса у нижней панели.
Ручной выбор бригад добавлен по QA2 и прямому поручению пользователя.

Администратор: «Службы и ЕКП → Профили служб → Бригады службы».
Для опубликованного профиля сохраняется новая версия, затем её нужно опубликовать.
Преподаватель выбирает профиль в новом сценарии ДДС и при необходимости задаёт
проверяемые цели бригад. Ученик принимает карточку своей службой, назначает бригады
кнопкой над нижней панелью, открывает нужную плитку и меняет статус карандашом.
Выбор службы раскрывает тёмный ряд бригад. Синяя история бригады появляется
только по нажатию на её плитку, повторное нажатие или крестик закрывает историю.
Назначение новой бригады само по себе историю не открывает.
История службы доступна отдельной кнопкой, её закрытие сохраняет видимый ряд бригад.
Выбранная служба выделена серым, открытая бригада — синим. Карандаш находится
на каждой плитке бригады, поэтому запись можно добавить и при закрытой истории.
При завершённом упражнении или отсутствии допустимого перехода карандаш виден,
но недоступен. Строки повторяют источник: `оп. 0 → дата и время статус → комментарий`;
стрелка комментария показывается только при наличии текста. Номер наряда
сохраняется в записи и доступен в подсказке, отдельной колонкой не выводится.
Плитки содержат время последнего статуса (МСК); полное название, дату и статус
можно прочитать во всплывающей подсказке. Изменение бригады не обновляет время службы.

Дополнительные получатели из ЕКП и назначенные бригады отображаются отдельными
рядами. По уточнению пользователя подбор бригад остаётся ручным; автоматический
подбор по району в этой итерации не вводился.

Служба и бригады имеют отдельные истории. Завершение бригады не закрывает службу.
Старые задания сохраняют прежний снимок профиля. Звонки и ИИ этой итерацией не подключаются.
