# Освоение интерфейса

Формат `introduction` назначается преподавателем существующему сценарию 112 или ДДС.
Снимки сделаны Playwright на API-фикстурах, соответствующих рабочему контракту.
Серверные переходы, проверка владельца, сохранение помощи и seed проверяются отдельно
интеграционными тестами на PostgreSQL.

- `teacher-settings.png` — выбор формата при назначении занятия.
- `operator-112.png` — весь блок конкретного адреса и значения отдельных полей из условия.
- `operator-mobile.png` — тот же шаг на узком экране.
- `dds-service.png` — открытие своей службы.
- `dds-editor.png` — подтверждение назначения в обычном редакторе бригады.

Подсветка не заменяет форму и не заполняет ответ за ученика. Сервер определяет
следующее действие по сохранённой карточке. Сопровождение можно отключить на поясняющей карточке (также Escape)
и включить снова из учебной полосы. «Проверить шаг» сохраняет ввод и повторно проверяет состояние;
это не принудительный переход. Чужие службы и вспомогательные окна не блокируются.

Состояние шага — server state в TanStack Query. Компоненты, hooks, типы, стили
и поиск DOM-целей разделены по FSD в `features/learning-assistance`.
Обычный АРМ получил только невидимые семантические атрибуты для точной подсветки.

Обновление по замечаниям: `task-introduction.png` — знакомство с условием,
`type-search.png` — подсветка поиска вместе с выпадающим списком,
`services-explanation.png` — пояснение автоматического подбора,
`journal-next-card.png` — новая карточка из журнала.
Точные поля ждут совпадения с условием; свободный адрес и описание требуют
«Продолжить» после ввода. Подтверждения хранит backend. Кнопка отключения
сопровождения размещена внутри поясняющей карточки.

Конкретный адрес без ориентиров — единый шаг: все заданные части адреса должны
совпасть с условием, описание вместо улицы и дома не завершает шаг.
`operator-mobile.png` показывает этот же блок на узком экране.
