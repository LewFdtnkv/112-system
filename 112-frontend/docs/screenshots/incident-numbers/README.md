# Целочисленные номера происшествий

Номер в списке происшествий и в открытой карточке поступает из API как
`display_number: number`. UUID остаётся внутренним идентификатором для связей,
выбора карточки и запросов. Поиск в журнале использует отображаемый номер.
Номер не зависит от фильтров, сортировки, страниц или повторного открытия.

Миграция backend `0029_incident_numbers` заменяет ранее неиспользуемое текстовое
поле числовым `GENERATED ALWAYS AS IDENTITY` с уникальным ограничением. Существующие
карточки получают номера; последовательность общая для 112 и ДДС. Пропуски в
последовательности допустимы. Номер не является количеством карточек в занятии.
Эталон ещё не начатой карточки не имеет номера происшествия и обозначен «Учебная
карточка»; для начатой работы разбор и эталон используют тот же номер.

Снимки сделаны в Chromium и Firefox на API-фикстурах: UUID различаются с числами
1042 и 1047. Проверены поиск, сортировка, перезагрузка, открытие по UUID и совпадение
номера в списке и форме. Телефония в этой фикстуре не настроена. Отдельно проверены
существующие сценарии АРМ 112 на трёх размерах и асинхронный журнал ДДС.
