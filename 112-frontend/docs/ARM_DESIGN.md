# Воспроизведение существующего АРМ

Обновлено 19.09.2026. Скриншоты задают внешний вид действующей системы, для которой создаётся тренажёр. Рабочие экраны воспроизводят её компоновку и элементы управления. Свободное оформление применяется к учебным кабинетам.

Основные источники: `СКРИНШОТ КАРТОЧКИ 112ГСИ.docx` (пустая карточка, опросник, выбор служб), `СКРИНШОТ ДДСГСИ.docx` (журнал и просмотр карточки), инструкция оператора и прежняя реализация в архиве. Рамка браузера, его боковая панель, панель Windows и водяные знаки не относятся к интерфейсу приложения и не воспроизводятся.

## Экраны

- Журнал: широкая строка поиска, часы справа, раскрываемые параметры, плотная таблица с отдельными строками описания, фильтры и пагинация. Дата и время сортируются вместе. Строку можно открыть мышью, Enter или пробелом.
- Создание сразу открывает пустую полноэкранную карточку. Телефоны находятся сверху; слева — заявитель, адрес по сетке исходного АРМ и описание; справа — признаки пострадавших, тип и опросник. Нижняя панель закреплена.
- В телефонах работает копирование АОН. Новые адресные поля, сведения заявителя и ответы опросника сохраняются в черновике. Одинаковые ответы разных вопросов хранятся раздельно.
- «+» открывает окно «Добавьте службы» с поиском и выбором. Выбранные службы показываются плитками внизу. Кнопка «сохранить» использует прежнюю учебную проверку заполнения.
- Учебный комментарий и журнал доступны через значок сообщения справа внизу. Здесь же открывается предварительный просмотр карточки. Просмотр использует серую нижнюю панель; «дополнение» возвращает к редактированию несданной карточки. После сдачи редактирование заблокировано.
- Навигация и интерфейсные списки имеют `list-style: none`; кнопки, навигация и панели — `user-select: none`. Поля и содержимое карточек остаются доступными для выделения и копирования. Есть hover, focus-visible и отдельный контрастный hover выбранных ответов.

## Архитектура

Сохранены слои `app → pages → widgets → features → entities → shared` и импорты через публичные `index.ts`.

| Слой                        | Ответственность                                                                              |
| --------------------------- | -------------------------------------------------------------------------------------------- |
| `shared/ui/arm`             | Универсальные поля, иконки, кнопки и базовые визуальные правила; без моделей тренажёра       |
| `entities/incident-card`    | Типы, демонстрационные справочники, чтение и запись совместимых черновиков                   |
| `features/incident-editing` | Изменение полей, выбор типа и признаков, валидация, сохранение и учебное действие            |
| `widgets/incident-card`     | Сборка карточки из отдельных телефонной, адресной, классификационной панелей и диалога служб |
| `widgets/incident-feed`     | Журнал с часами, фильтрами, сортировкой и пагинацией                                         |
| `pages/training-workspace`  | Занятие, навигация и композиция виджетов; карта передаётся в карточку через render-проп      |
| `app`                       | Общая тема MUI и оболочка учебных кабинетов                                                  |

Стили рабочего места находятся рядом с соответствующими виджетами. Общие контролы находятся в `shared/ui/arm`; монолитный `app/styles/arm.scss` удалён. Отдельный пакет `112-ui` не добавлялся поверх архитектуры MUI.

## Проверка и пределы прототипа

Проверки выполняются в Docker: TypeScript/Vite, ESLint, 75 модульных тестов и 7 браузерных сценариев. В браузере проверяются сохранение после перезагрузки, восстановление черновиков, фильтры, клавиатура, наведение, возможность выделять текст полей, ограничения ролей и завершение занятия. Снимки проверены вручную на 1920×964 (размер области приложения без рамки браузера в исходных изображениях), 1366×768 и 390×844.

Снимки: [журнал](screenshots/journal.png), [пустая карточка](screenshots/create.png), [опросник пожара](screenshots/card.png), [выбор служб](screenshots/services.png), [просмотр](screenshots/view.png), [1366×768](screenshots/card-compact.png), [мобильная карточка](screenshots/card-mobile.png).

Совпадение проверялось визуально по расположению, пропорциям, цветам и состояниям, без заявления о полном пиксельном совпадении. Содержимое демонстрационных карточек и часы отличаются от примеров.

Это фронтенд-прототип: список служб пока содержит 101–104, а быстрые типы и опросники не заменяют опубликованный ЕКП. Сохранение остаётся учебной отправкой на проверку, без реального оповещения. Предварительный просмотр не является отдельным реализованным workflow ДДС. Недоступные в задании операции исходной системы обозначены отключёнными кнопками; SIP, реальная маршрутизация и полноценное реагирование служб этим изменением не подключались. Существующая карта использует внешние сервисы и загружается только по запросу пользователя.

Для повторения из каталога `112-frontend`:

```sh
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app node:24-bullseye-slim npm ci
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app node:24-bullseye-slim npm run build
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app node:24-bullseye-slim npm run lint
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app node:24-bullseye-slim npm test -- --maxWorkers=2
```

Браузерная проверка в установленном Docker-образе Playwright с явным путём к его Chromium:

```sh
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app -e PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/ms-playwright/chromium-1234/chrome-linux/chrome mcr.microsoft.com/playwright:v1.62.1-noble npm run test:e2e -- --workers=2
```

По умолчанию тесты сами запускают Vite внутри контейнера. Для проверки уже запущенной сборки на Docker Desktop добавьте `-e PLAYWRIGHT_BASE_URL=http://host.docker.internal:8080`. При использовании другого браузерного образа укажите соответствующий путь Chromium либо установите браузер, соответствующий версии `@playwright/test`.

Артефакты повторного запуска находятся в игнорируемом каталоге `test-results/`. Vitest ограничен файлами `src/**/*.test.{ts,tsx}`, чтобы не пытаться исполнять сценарии Playwright.
