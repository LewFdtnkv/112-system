# Оформление АРМ

Обновлено 19.09.2026. Сохранены структура `app / pages / widgets / features / entities / shared`, MUI, маршруты и демонстрационные сценарии новой реализации.

Визуальные ориентиры: изображения из `СКРИНШОТ ДДСГСИ.docx` (журнал и карточка), `СКРИНШОТ КАРТОЧКИ 112ГСИ.docx` (ввод карточки), прежние компоненты и снимки из `Архив/112-frontend` и `Архив/112-ui`.

## Где менять оформление

- `src/app/theme/` — общая тема MUI: шрифты, цвета, поля, кнопки, таблицы и диалоги.
- `src/app/styles/arm.scss` — рабочее место: серый журнал, поиск, полноэкранная карточка, опросник, закреплённая панель служб и адаптация к небольшим экранам.
- `src/app/styles/global.scss` — оболочка кабинетов и вход. Силуэты зданий нарисованы CSS, внешние изображения и шрифты не нужны.
- `IncidentFeed` принимает `toolbar` для действий рабочего места. Расширенный поиск сворачивается; описания происшествий показаны отдельными строками. Карточка открывается мышью, Enter или пробелом.
- `IncidentCardDialog` сохраняет прежние обработчики полей, черновиков и отправки. Телефоны перенесены наверх, число пострадавших — в правую колонку, службы и действия — в закреплённый низ. Карта монтируется только после раскрытия блока.

Это оформление существующего прототипа, а не реализация всех функций настоящего АРМ. Состав полей, демонстрационные службы, алгоритмы проверки и роли сохранены. Кнопка «Отправить на проверку» остаётся учебным действием. Самостоятельный пакет `112-ui` из архива не подключён поверх MUI; общая тема новой структуры остаётся единой для кабинетов и рабочего места.

## Проверка

Все команды Node выполнялись в Docker. Проверены production-сборка TypeScript/Vite, ESLint, 73 модульных теста и 6 браузерных сценариев. Браузерные сценарии также выполнены на production-контейнере `http://localhost:8080`.

`e2e/arm-layout.spec.ts` проверяет поиск и сброс, открытие с клавиатуры, сохранение черновика, доступность нижних действий, отсутствие горизонтального переполнения страницы и кабинет преподавателя. Снимки создаются на 1920×1080, 1366×768 и 390×844. На узком экране таблица прокручивается внутри своего контейнера, колонки карточки располагаются последовательно. Скриншоты просмотрены вручную и сопоставлены с исходными материалами; это не автоматический тест пиксельного совпадения.

Зафиксированные примеры: [журнал](screenshots/journal.png), [карточка](screenshots/card.png), [создание](screenshots/create.png), [вход](screenshots/login.png), [мобильная карточка](screenshots/card-mobile.png), [кабинет преподавателя](screenshots/teacher.png).

Для повторения из каталога `112-frontend`:

```sh
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app node:24-bullseye-slim npm ci
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app node:24-bullseye-slim npm run build
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app node:24-bullseye-slim npm run lint
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app node:24-bullseye-slim npm test -- --maxWorkers=2
```

Браузерная проверка в установленном Docker-образе Playwright с явным путём к его Chromium:

```sh
docker run --rm -v "$PWD":/app -v system112-design-node-modules:/app/node_modules -w /app -e PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/ms-playwright/chromium-1234/chrome-linux/chrome mcr.microsoft.com/playwright:v1.62.1-noble npm run test:e2e -- --workers=2
```

По умолчанию тесты сами запускают Vite внутри контейнера. Для проверки уже запущенной сборки на Docker Desktop добавьте `-e PLAYWRIGHT_BASE_URL=http://host.docker.internal:8080`. При использовании другого браузерного образа укажите соответствующий путь Chromium либо установите браузер, соответствующий версии `@playwright/test`.

Артефакты повторного запуска находятся в игнорируемом каталоге `test-results/`. Vitest ограничен файлами `src/**/*.test.{ts,tsx}`, чтобы не пытаться исполнять сценарии Playwright.
