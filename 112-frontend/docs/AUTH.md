# Авторизация

Аккаунт имеет одну роль: ученик, преподаватель или администратор. Роль нельзя изменить; для другой роли создаётся отдельный пользователь. Администратор не получает права преподавателя.

## Вход и пароль

Вход выполняется по логину и паролю. Пароль передаётся без обрезки пробелов. После создания пользователя или сброса пароля администратором открывается обязательная смена пароля; до неё остальные страницы недоступны.

Новый пароль должен содержать 12–128 символов, отличаться от текущего и не состоять из одних пробелов. Повтор пароля проверяется в форме.

| Запрос относительно `/api/v1` | Назначение                            |
| ----------------------------- | ------------------------------------- |
| `POST /auth/login`            | Вход по `username` и `password`       |
| `GET /users/me`               | Профиль и права текущего пользователя |
| `POST /auth/refresh`          | Обновление пары токенов               |
| `POST /auth/change-password`  | Смена пароля                          |
| `POST /auth/logout`           | Отзыв текущего сеанса                 |

## Восстановление сессии

Zustand persist сохраняет токены в sessionStorage. Перезагрузка вкладки восстанавливает сессию, затем профиль запрашивается у сервера. Пароль и права в браузерном хранилище не сохраняются.

При HTTP 401 клиент один раз обновляет токены и повторяет запрос. Параллельные запросы ждут общий refresh. Если refresh возвращает 401, сессия очищается; при сетевой ошибке или 5xx показывается возможность повторить попытку. Выход и смена пользователя очищают Query-кэш.

Проверка поколения сеанса не позволяет запоздавшему ответу восстановить уже закрытый аккаунт. Сервер отзывает сеансы отключённого пользователя; повторное включение требует нового входа.

## Где искать код

- `shared/api/backendApi` — транспорт и повтор запроса.
- `entities/user` — DTO, токены и жизненный цикл сессии.
- `features/auth` — формы входа и смены пароля.
- `app/providers/AuthProvider` — восстановление и очистка кэша.
