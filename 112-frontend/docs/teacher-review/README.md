# Пересмотр результата и исправления для ИИ

В начале результата преподавателю доступны «Пересмотреть оценку», «Написать ученику» и «История оценок». После пересмотра показаны прежний и новый баллы, отдельная отметка преподавательской оценки и её причина. У ученика итог также подписан как пересмотренный преподавателем.

Два действия различаются по назначению:

- **Пересмотреть оценку** меняет итог конкретного занятия. Комментарий обязателен и не заполняется чужим объяснением автоматически. Он не становится примером для ИИ. Пока форма открыта, она сохраняет исходную редакцию: фоновая загрузка не стирает ввод и не позволяет обойти проверку конфликта.
- **Исправить вывод ИИ** находится у каждого проверенного смыслового критерия карточки. Преподаватель выбирает свой вердикт, кратко объясняет его и явно нажимает «Использовать в будущих проверках». Только тогда пример сохраняется в RAG. Текущая оценка не меняется. Пример можно заменить или исключить; сохранение и подготовка к поиску показаны отдельно.

Память принадлежит преподавателю. В следующие проверки попадают только подходящие активные разборы; модель не обязана копировать их вердикты. Исторические оценки и уже подготовленные задачи не пересчитываются после публикации. «Показать использованные разборы» показывает фактически переданные модели примеры, а не всю библиотеку. Для ДДС исправлен учёт: максимум два извлечённых примера вместе с обязательными примерами проверки этапов.

В шапке кабинета преподавателя есть «Написать»: выбор своего ученика или группы. В результате, профиле ученика и составе группы адресат уже задан. Отправка использует существующий API сообщений; выбор учеников ограничен теми же правами, что и отправка (`views/users?role=student&owned_only=true`). При смене адресата прежний текст не переносится другому получателю.

Архитектура: оценивание в `features/lesson-review`, сообщения в `features/teaching-messages`; страница передаёт действие сообщения через слот. Между фичами нет прямого импорта. Данные API и отправки управляются TanStack Query, состояние открытых окон и черновиков локальное.

Проверки: build, lint/FSD, 206 Vitest; Playwright проверяет пересмотр, историю, адресата, смену типа получателя, публикацию/исключение RAG и сохранение исходной редакции при фоновом обновлении. Браузерные проверки используют API-фикстуры; права адресатов и публикация RAG проверяются backend-тестами с PostgreSQL.
