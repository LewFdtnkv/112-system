# Направления учебного помощника

При публикации рекомендации сервер выдаёт персональное направление для каждого выбранного навыка, если есть подходящий сценарий. Модель выбирает методику из проверенного набора RAG; параметры назначения и получателя она не задаёт.

- Срок — **один календарный месяц от публикации рекомендации** (31 января → последний день февраля, время сохраняется в UTC).
- Ученик нажимает «Создать занятие» в рекомендации. Направление создаёт одно личное занятие с новыми заданиями и попытками. Повторные/одновременные запросы возвращают это же занятие.
- Создание не начинает таймер. Переход ведёт в ученическое рабочее пространство, где занятие начинается обычным способом. После создания срок направления не ограничивает прохождение: это самостоятельная тренировка без лимита и конечного срока.
- Берутся опубликованные, неархивные сценарии, уже завершённые и оценённые у этого ученика, назначенные действующими преподавателями его текущих нерасформированных групп. Проверяются до 100 последних редакций; состав карточек должен подходить выбранному навыку. Черновики, чужая библиотека и карточки будущих/незавершённых контрольных занятий не раскрываются. Если подходящего сценария нет, интерфейс предлагает обратиться к преподавателю.
- `focused` → отработка навыка; `checklist`/`compare` → повторение навыка (помощь до объяснения); `less_help` → полная ситуация с напоминанием цели; `independent` → проверка без подсказок. Для ДДС сохраняются профиль, история бригад и расписание карточек. Общие проверки назначения используются повторно.
- Пересмотр исходных оценок блокирует ещё не использованное направление. Проверка актуальности проводится также при нажатии, не только фоновым планировщиком. Расформирование группы, отключение преподавателя, архивирование сценария и недоступность справочников/служб препятствуют новому назначению. Уже созданные занятия сохраняются.

## API и хранение

`POST /api/v1/student/learning-referrals/{referral_id}/lesson` — только StudentDep и собственное направление, **без тела с параметрами назначения**. Ответ: `lesson_id`, `created`. Чужое направление — 404, другие роли — 403, истёкшее — 410, утратившее актуальность — 409. Teacher API не расширен.

Таблица `learning_referrals` (миграция `0036_learning_referrals`) хранит сообщение-основание, ученика, навык, сценарий, преподавателя, замороженную политику, срок и уникальную ссылку на созданное занятие. Уникальность `(message_id, skill)` предотвращает повторную выдачу; блокировка ученика/сообщения и одна транзакция создают занятие с assignments и погашают направление атомарно. В ученическом списке сообщений показываются только ID направления, срок, состояние и ссылка на занятие, без эталонов и скрытых параметров.

## Существующие рекомендации

Новые рекомендации (включая `seed_demo`) получают направления в общей функции публикации автоматически. Повторно запускать модель не нужно.

Для действующих старых рекомендаций после миграции:

```sh
docker compose run --rm --no-deps api python scripts/backfill_learning_referrals.py
```

Это пробный запуск с откатом. Для сохранения добавить `--apply`. Скрипт использует сохранённые решения помощника, не создаёт новых сообщений, не меняет оценки и не продлевает срок старых рекомендаций. Повторный запуск безопасен.
