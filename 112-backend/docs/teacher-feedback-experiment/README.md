# Влияние коротких исправлений преподавателя на RAG-оценивание

Эксперимент 27.09.2026 на фактически настроенной модели стенда: Qwen3 4B Instruct-2507 Q4_K_M, 2 CPU-потока; эмбеддинги Qwen3 Embedding 0.6B. Точные идентификаторы весов — `models.json`. Модель, системный промпт `semantic-v3-scoped` и правила начисления баллов не менялись ради получения нужного результата.

## Результат

**В двух спорных примерах короткое исправление изменило вердикт в обоих повторах. После отзыва исправления оба вердикта вернулись к исходным. Явное противоречие не было зачтено даже с ошибочным разбором преподавателя.**

| Пример | До исправления | С исправлением | Повтор | После отзыва |
|---|---|---|---|---|
| Дым из киоска → «Пожар в киоске» | Неверно | Верно | Верно | Неверно |
| Бригада у шлагбаума → «Прибыли» | Верно | Неверно | Неверно | Верно |
| Человек отвечает → «Без сознания» (контроль) | Неверно | Неверно | Неверно | Неверно |

Короткие реплики преподавателя (получены без изменения системного промпта):

- Дым из киоска → «Пожар в киоске»: «Здесь «пожар» — повод для выезда по дыму, а не утверждение, что заявитель видел пламя.» (86 символов).
- Бригада у шлагбаума → «Прибыли»: «Прибыли к шлагбауму, а не к месту аварии. Комментарий это скрывает.» (67 символов).
- Человек отвечает → «Без сознания» (контроль): «Зачесть: главное, что ученик понял необходимость скорой. Состояние сознания здесь неважно.» (90 символов).

Всего **12 оцениваний критерия / 24 вызова модели**. В 6 оцениваниях с исправлением его ID присутствовал в `used_examples`, а сама реплика — в реальном промпте; без исправления и после отзыва её там не было. Чужому преподавателю авторские разборы не выдавались (3/3 проверки). Все 12 итоговых вердиктов прошли существующие проверки цитат, уверенности и согласия двух проходов.

Время одного оценивания с двумя вызовами модели: 66,11–143,29 с, медиана 112,47 с. Это время `evaluate`, без предварительной индексации и поиска; стенд использовался и для остальных проверок, поэтому это не изолированный тест скорости.

## Методика

Использованы три синтетические работы: две допускающие разную трактовку и одна с явным противоречием. Названия экспериментов и желаемые ответы не передавались модели. Передана одна смысловая проверка карточки, без оценки всего занятия.

1. Исходная оценка с обычной библиотекой из 25 подготовленных разборов.
2. После получения исходного вывода выбран противоположный вердикт и короткая заранее подготовленная реплика преподавателя.
3. Реплика опубликована через настоящий API `assessment-memory`; PostgreSQL/pgvector, эмбеддинги, поиск и основной оценщик работают без моков.
4. Повторная оценка с найденным преподавательским примером, затем ещё один повтор с тем же снимком RAG.
5. Пример отозван через API, поиск выполнен заново, оценивание повторено.

Все этапы используют существующие проверки цитат, порог уверенности и два прохода модели. Проверяется не только попадание примера в поиск, но и его наличие в `used_examples` и фактических промптах. Отдельно проверено исключение авторского примера из поиска другого преподавателя.

Это повторная оценка того же **входа** в новой задаче, а не изменение завершённой задачи: в действующей системе RAG-снимок фиксируется, и повтор технически упавшей задачи не обновляет его. Исправления не пересчитывают уже выставленные оценки автоматически. API-фикстура подставляет синтетический вход в завершённую тестовую задачу, после чего исправление публикуется обычным API.

База отдельная, мигрированная, без рабочего воркера; изменения фикстур откатываются. Рабочая база, реальные оценки и общая память стенда не менялись. Первоначальный запуск прерван после первого исходного ответа для исправления кода критерия ДДС на `dds.comments`. Этот завершённый ответ сохранён и использован повторно (отмечено в JSON); прерванный вызов не включён в итоговые результаты. После двух полных сравнений истёк обычный 15-минутный токен API-фикстуры: исходный ответ контрольного примера уже был сохранён, публикация получила 401. Скрипт обновлён для повторного входа перед операциями API; завершённые сравнения и исходный ответ контроля сохранены. Это техническая остановка экспериментального скрипта, не ошибка модели и не сбой рабочей авторизации.

## Данные и воспроизведение

`results.json` содержит условия, ответы, короткие исправления, снимки поиска, оба ответа оценщика с промптами/цитатами и время каждого этапа. `models.json` содержит идентификаторы моделей. В `summary.json` — краткое сравнение этапов.

Опциональный скрипт `scripts/evaluate_teacher_feedback.py` запускается через pytest, чтобы использовать существующие API-фикстуры и откат транзакций. Он не входит в обычный набор `tests` и не вызывает модель без явно заданного пути отчёта. Нужны зависимости разработки и отдельная пустая тестовая PostgreSQL с применёнными миграциями; **не указывать рабочую БД**. Endpoint модели должен поддерживать `/api/chat`, `/api/tags`, `/api/embed`.

Пример для уже подготовленных тестовой БД и доступного локального endpoint модели (в одну строку):

```sh
TEST_DATABASE_URL=postgresql+asyncpg://check:check@127.0.0.1:15569/teacher_feedback LLM_BASE_URL=http://127.0.0.1:11435 LLM_THREADS=2 TEACHER_FEEDBACK_REPORT=$PWD/docs/teacher-feedback-experiment/new-results.json uv run pytest -s -q scripts/evaluate_teacher_feedback.py
```

Если отчёт уже существует, совместимые завершённые сравнения и исходный ответ незавершённого примера сохраняются; для полностью нового исходного прогона используйте другое имя файла. Примеры не являются утверждённой методикой и не загружаются в рабочий RAG.

## Что означают результаты

Это проверка **влияния** памяти на одинаковый вход, а не независимый тест повышения точности на новых карточках. В двух спорных примерах нет утверждённого заказчиком единственного верного толкования: исправление специально задаёт другую допустимую позицию преподавателя. Поэтому переворот вердикта не объявляется сам по себе улучшением качества.

Короткий комментарий может менять применяемый смысловой балл без дообучения модели: тот же критерий `correct` получает долю 1, `incorrect` — 0, если цитаты, уверенность и второй проход прошли проверки. В реальном занятии итог зависит ещё от формальных критериев, веса смысловой части и остальных карточек. Здесь общий балл занятия не пересчитывался.

Объяснения всё ещё требуют внимания. В повторе с киоском модель написала: «В условии не указано, что дым идёт из киоска», хотя условие начинается словами «Из закрытого киоска идёт дым». В ДДС встречаются путаные причинные формулировки и неестественное «пешая передвижная часть». Проверка цитат и совпадение двух вердиктов не гарантируют правильности каждой фразы объяснения; высокая самооценка уверенности тоже не является измеренной точностью.

Практический вывод: хранить короткий вердикт с причиной у конкретного критерия, явно публиковать его в RAG, показывать использованные примеры и оставлять возможность исключения. Не превращать произвольный комментарий к итоговому баллу в обязательное правило для всех будущих работ. Для уверенного вывода о качестве нужен больший независимый набор работ и проверка преподавателем: перенос на перефразированные и новые ситуации, конфликтующие исправления и устаревшие нормы здесь не проверялись.
