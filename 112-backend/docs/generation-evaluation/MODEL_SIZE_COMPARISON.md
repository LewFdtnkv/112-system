# Сравнение свободной генерации 4B и 8B — 23.09.2026

Практическая замена текущей 4B на выбранную 8B **не дала надёжного улучшения
согласованности** на старой схеме. Отдельные ответы улучшились, но существенные
ошибки остались, а в газовой ситуации появилось прямое противоречие признакам.
По этому небольшому набору нельзя утверждать, что более крупные модели вообще
бесполезны; оснований переключать рабочий генератор именно на эту 8B нет.

Полные 16 ответов, метрики Ollama, замечания к каждому ответу и незавершённая
дополнительная проверка сохранены в
[model-comparison-results.json](model-comparison-results.json).

## Результаты ручного разбора

| Согласованный вход | 4B Instruct-2507 | 8B |
|---|---|---|
| Пожар мусора во дворе, дом 12, без пострадавших/заблокированных | Речь оборвана на «д.»; мусор не назван; в описании появляется неподтверждённое «в помещении». | Адрес полный, но выдумано «не могу выйти из дома», вопреки признакам и прямому запрету промпта. |
| Два автомобиля, без пострадавших | Основные факты сохранены. Отрицательные признаки блокировки/возгорания не сообщены. | Аналогично: основная ситуация сохранена, часть признаков пропущена. |
| 104, плита в помещении, открытый огонь=false | Описана работающая плита без огня; не объяснена сама аварийная ситуация. | «Загорелась плита», «Пожар в кухне» — прямое противоречие открытому огню=false. |
| Взрослый без сознания, дыхание сохранено | Звонящий говорит «У меня потеря сознание», продолжая разговор. | Самоговорящий пострадавший исчез, но фраза «В квартире потеряло сознание» не называет человека; дыхание есть только в описании, а не сообщении ученику. |
| ДТП, два пострадавших, срыв звонка | Не переданы количество пострадавших и срыв; в речи «не вижу травм». | Количество и срыв также потеряны; в обоих текстах пострадавших «не видно», добавлен водитель в шоке. |
| Ошибочный набор, имя/возраст/адрес не заданы | Выдуманы другой город, человек и отдельное происшествие с пожарным ведром. | Смысл ошибочного набора сохранён, но придуманы Марина Петрова, 35 лет, Санкт-Петербург и адрес. |

«Не вижу травм/пострадавших» само по себе не доказывает, что их не существует.
Здесь это отмечено как непереданное условие: ученик не узнаёт о заданных двух
пострадавших. Фраза «в помещении нет пострадавших» в ответе 4B также не является
строгим отрицанием пожара во дворе; проблема — неподтверждённый контекст.

Два проблемных входа оцениваются отдельно:

- Парк + плита в помещении + отсутствие огня: обе модели придумывают огонь.
  Входную неоднозначность они не обозначают.
- Ошибочный набор + два пострадавших + срыв: обе теряют сведения о пострадавших.
  4B обрывает речь на адресе; 8B пересказывает разрыв звонка словами заявителя,
  хотя промпт требует наблюдение оператора, и заменяет 112 номером скорой.

Большая модель не исправляет противоречивый вход надёжным способом. При этом
старый контракт ответа вообще не предусматривал отдельного результата «условия
несовместимы» — такую проверку следует выполнять до генерации.

## Скорость, память и дополнительный контроль

| Метрика полного прогона, 8 случаев | 4B | 8B |
|---|---:|---:|
| Формально валидный JSON/GeneratedText | 8/8 | 8/8 |
| Медиана времени запроса, с | 16,06 | 22,24 |
| Минимум–максимум, с | 11,36–20,62 | 18,56–42,90 |
| Память загруженной модели по `/api/ps`, десятичные GB | 3,50 | 5,94 |

Память `/api/ps` — показатель модели, не полный пик потребления Docker или
компьютера. Снимки `docker stats` во время полного прогона 8B показывали
5,14–5,16 GiB для контейнера. Обе модели исполнялись на CPU, `size_vram=0`.
Формальная валидность всех ответов не обнаружила ни выдуманного огня, ни неверной
роли потерявшего сознание. Задержки измерены на локальном ARM64 Docker, не на
предполагаемом CPU-сервере с 32 ГБ; переносить эти времена на него нельзя.

Дополнительно начат повтор 8B с `--top-p 0.8`, как у 4B. Он **не завершён**:
параллельно появились чужие контейнеры браузерных проверок (~1,8 GiB), процесс
модели стал завершаться по нехватке общей памяти Docker. В `memory.events`
зафиксировано `oom_kill=2`, в Ollama — `signal: killed`; сохранены три HTTP 500.
Собственные экспериментальные контейнеры остановлены. Чужие проверки не трогались.
Эти ошибки не включены в оценку текстов или таблицу времени полного прогона.
Для чистого сравнения параметра семплирования этот дополнительный тест нужно
повторить при свободной памяти; результатов его качества сейчас нет.

## Решение для тренажёра

Рабочую модель и генератор v3 не переключать по результатам этого опыта. В v3
модель выбирает подготовленные формулировки; увеличение размера само по себе
не обогатит их. Найденные предметные недостатки планировщика, например смешение
недоступности места и заблокированных людей, исправляются в данных/правилах.

Если возвращать свободный текст, полезна последовательность: согласованные
факты → подготовленный сюжет → пересказ моделью → проверка текста → публикация
либо заготовка при неудаче. Проверка должна находить изменение адресов/количеств,
отрицаний, ролей участников и пропущенные оцениваемые сведения. Один JSON Schema
этого не обеспечивает; дополнительная LLM-проверка тоже не является гарантией.
Возможность редактирования преподавателем сохраняется.

Следующее исследование более сильной модели имеет смысл проводить на расширенном
наборе, с несколькими seed, одинаковыми параметрами семплирования, запасом RAM и
без параллельных тяжёлых проверок. Этот опыт сравнивает конкретные 4B и 8B; он не
доказывает, как поведёт себя другая 8B или модель 14B.

## Методика

Сравниваются `qwen3:4b-instruct-2507-q4_K_M` и `qwen3:8b-q4_K_M`.
Промпт `card-generation-v2` извлечён без изменений из родителя коммита `c6690da`.
Полные промпты, факты, seed и идентификатор исходного коммита сохранены в
[model-comparison-inputs.json](model-comparison-inputs.json).

Это сравнение двух конкретных доступных моделей, а не чистое исследование числа
параметров: 4B — более поздняя Instruct-2507, 8B — исходная Qwen3. Обе Q4_K_M,
рассуждения отключены. Модели запускаются последовательно в одном отдельном Ollama
0.34.2, CPU, лимит 6 ядер / 6,5 GiB, контекст 4096, максимум 1000 выходных токенов,
temperature 0.4, num_thread 6. Перед серией выполняется загрузка модели без текста.
Как и в прежнем API-запросе, остальные параметры берутся из модели: в частности,
top_p у 4B равен 0.8, у 8B — 0.95; top_k у обеих 20. Проверяется практическая
замена модели в старом запросе, а не влияние числа параметров при полной фиксации
всех внутренних настроек семплирования.
Общий Docker имеет около 7,75 GiB RAM и 10 CPU. Рабочие API/БД остаются включены.
При прогоне 4B параллельно скачиваются веса 8B; времена ориентировочные, это не
измерение пропускной способности сервера. Начальная загрузка весов исключена из
времени отдельной карточки; обработка промпта включена.

Шесть согласованных случаев: пожар мусора, ДТП без пострадавших, газ/плита,
потеря сознания, ДТП с двумя пострадавшими и срывом звонка, ошибочный набор.
Два отдельных стрессовых случая: парк вместе с плитой в помещении и ошибочный
набор вместе с пострадавшими. Последние не включаются в оценку ошибок на корректном
входе. Молчаливый вызов не проверяется: старая схема также обрабатывала его без LLM.

Каждый ответ проверяется вручную по следующим отдельным критериям:

- Изменение или противоречие заданным фактам и расхождения двух выходных текстов.
- Пропуск сведений, которые нужны ученику для заполнения оцениваемых полей.
- Выдуманные существенные сведения: этаж, причина, другое происшествие, работа служб.
- Завершённость, понятность и естественность речи.
- Валидность JSON/схемы, время и память (не считаются доказательством качества).

Допустимое склонение адреса не является изменением адреса. Отсутствие сведений
отмечается отдельно от явного противоречия. Название 104 само по себе не сообщает
характер аварии: если исходные признаки не содержат запаха газа, отсутствие запаха
в тексте — неполнота ситуации, а не нарушение явно заданного факта.

Один seed на случай, малый набор, один рецензент. Проценты улучшения и качество
всех будущих карточек по этому эксперименту не устанавливаются. В БД результаты
не публикуются, работающий генератор v3 и его модель не переключаются.

## Воспроизведение

В API-образе с исходниками проекта и доступом к отдельному Ollama:

```sh
PYTHONPATH=. python scripts/evaluate_model_size.py \
  --base-url http://112-generation-model-comparison:11434 \
  --model qwen3:8b-q4_K_M --warmup
```

Аналогично для `qwen3:4b-instruct-2507-q4_K_M`. Вывод — JSONL; скрипт не использует
сессию БД. `--cases fire road` позволяет ограничить набор. Загрузка нужной модели
в Ollama выполняется заранее. Для дополнительного контроля добавить `--top-p 0.8`.
Timeout 900 с используется для исследования качества,
а не как предложение настройки рабочего воркера.

Официальные сведения о весах:
[4B](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M),
[8B](https://ollama.com/library/qwen3:8b-q4_K_M).
