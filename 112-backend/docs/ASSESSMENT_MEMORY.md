# Память разборов для смыслового оценивания

Prompt `semantic-v3-scoped` использует опубликованные разобранные примеры,
подобранные PostgreSQL + pgvector. Арифметика оценки, защита точных ошибок,
приоритет ручной оценки, проверка цитат и два согласованных ответа сохранены.
RAG не гарантирует профессиональную корректность и не обучает веса модели.

## Модель и хранение

Qwen3 Embedding 0.6B (официальная Ollama `qwen3-embedding:0.6b`, Q8_0, 639 MB),
1024 измерения, Apache 2.0. Поддержка русского/многоязычного поиска и работа через
уже имеющийся Ollama позволили не добавлять PyTorch или отдельный сервис.
Это выбор под текущую CPU-инфраструктуру, не доказательство превосходства над E5
или EmbeddingGemma. Ограниченный прогон описан в [отчёте](assessment-evaluation/RAG_EVALUATION.md);
превосходство самого RAG над прежними примерами не установлено.
Источники: [модель](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B),
[Ollama](https://ollama.com/library/qwen3-embedding:0.6b),
[API embeddings](https://docs.ollama.com/api/embed),
[pgvector](https://github.com/pgvector/pgvector).

Вектор хранится вместе с текстом, автором, исходной AIJob, версией рубрики,
датой публикации/отзыва. Идентификатор embeddings включает название модели,
фактический digest весов и версию формата поискового запроса. Векторы разных
версий не смешиваются. Изменение модели требует переиндексации; размер сейчас
строго 1024. Запросы `truncate=false`: молчаливой обрезки нет. `keep_alive=0`
освобождает embedding-модель перед основным оцениванием при одном слоте Ollama.

Пока применяется точный поиск без HNSW: небольшая база и строгие SQL-фильтры.
Косинусный поиск (до 20 кандидатов, similarity >= 0.35) совмещён с русским
полнотекстовым ранжированием через reciprocal rank fusion. Порог стартовый,
не калиброванный на большой экспертной выборке. В промпт идут до трёх полных
разборов; если контекст превышает бюджет, последние примеры исключаются,
а условие/ответ не обрезаются. Сходство не является вероятностью правильности.

## Публикация преподавателем

В результате занятия у каждого смыслового критерия есть «Сохранить свой разбор»:
вердикт и объяснение 15–700 символов. Сервер сам берёт исходное условие и ответ
из зафиксированной проверки, не доверяет присланному клиентом содержимому работы.
Разбор доступен только в занятиях его автора. Сохранение нового разбора того же
критерия отзывает предыдущий. Запрос идемпотентен. Оценка ученика не меняется:
для неё используется отдельная существующая форма ручной оценки.

Во вкладке «Память ИИ» (`/teacher/assessment-memory`) доступны поиск, фильтры,
пагинация, просмотр, включение/отключение, удаление и восстановление. Видны общие
учебные примеры и свои исправления. Настройки общих примеров индивидуальны:
один преподаватель не меняет оценки и память другого. Удаление означает исключение
из личной памяти и скрытие из обычного списка; включить показ удалённых можно
отдельно. Копии в прошлых оценках сохраняются. Отозванную/заменённую публикацию
нельзя включить: новый вариант публикуется из результата работы.

API:
- `GET /assessment-memory` — q/kind/state/include_removed/limit/offset;
- `PATCH /assessment-memory/{id}` — `{ "enabled": false }`;
- `DELETE /assessment-memory/{id}` — убрать из личного списка и поиска;
- `GET/POST /lessons/{lesson}/students/{student}/attempts/{attempt}/assessment-memory`;
- `DELETE .../assessment-memory/{example}` — отозвать собственный разбор;
- `GET .../assessment-memory/retrieval` — фактически использованные копии разборов.
Все маршруты требуют роль преподавателя и проверяют принадлежность работы/примера.
Ученику чужие примеры и ответы не раскрываются.

## Воркер и воспроизводимость

HTTP-запрос сдачи не ждёт embeddings. Воркер под действующей lease подготавливает
до 16 ожидающих индексации примеров и ищет контекст. Отбор ограничен ролью,
кодом/видом критерия, рубрикой, автором, активностью и личными исключениями.
Собственный исходный разбор проверяемой AIJob исключён. Найденные тексты, ID,
источники, модель и similarity фиксируются в `AIJob.context.retrieval` до вызова LLM.
Ответ содержит использованные ID и hash снимка; публикация проверяет hash и lease.
Повтор воркера использует прежний снимок. Отзыв влияет на последующий поиск,
не меняет уже зафиксированный контекст выполняющейся/завершённой проверки.

Если embeddings недоступны, сохраняется статус `unavailable`, а проверка использует
прежние стандартные примеры. UI сообщает об этом. При недоступной основной модели
сохраняется формальная оценка по существующим правилам. Статус `ready` не означает,
что пример обязательно использован: возможен пустой поиск или превышение бюджета.

## Наполнение и запуск

Миграции 0024/0025. Compose собирает pgvector 0.8.2 поверх прежнего `postgres:17`:
сохраняются версия PostgreSQL и Debian/libc. Готовый образ pgvector на bookworm
здесь не используется для рабочей БД, чтобы не понижать PostgreSQL и не менять
версию системной сортировки существующего тома. Сброс БД не нужен.

Из каталога backend:

```sh
docker compose up -d --build --wait api worker frontend
docker compose exec llm ollama pull qwen3-embedding:0.6b
docker compose exec worker python -m scripts.seed_assessment_memory --index
```

Скрипт добавляет 25 авторских синтетических разборов из
`app/data/assessment_examples.json`: парафразы, пропуски, ложные утверждения,
неизвестные/противоречивые сведения, дополнительные службы, комментарии ДДС.
Это стартовые учебные примеры, НЕ подтверждённая заказчиком методическая база.
Преподаватель может исключить любой из них. Повторный seed не дублирует записи,
не восстанавливает отозванные и не сбрасывает личные настройки.
Пользователи, карточки, занятия и оценки этим скриптом не меняются.

`ASSESSMENT_RAG_ENABLED` фиксируется при создании задания проверки (default true).
Отключение флага для новых проверок возвращает стандартные примеры.
`EMBEDDING_MODEL` default `qwen3-embedding:0.6b`; при новой версии повторить `--index`.
Новые пользовательские примеры индексируются воркером при следующей проверке;
для большого накопившегося списка можно заранее выполнить `--index`.

Для локальных backend-тестов нужна отдельная мигрированная БД из того же образа
с установленным pgvector; обычный `postgres:17` без расширения больше недостаточен.

## Ограничения окончательного оценивания

Модель выбирает цитаты из дословных фрагментов текущего условия и ответа через
JSON Schema enum. Примеры из памяти не входят в эти варианты. Пустой вариант
разрешён и ведёт к отказу от автоматического применения. Это исключает склейку
цитат, но не доказывает логическую связь цитаты и вывода.

Узкая серверная защита замечает в условии или эталонном решении только явно
написанные фразы о противоречивых сведениях/показаниях или источниках, которые «противоречат друг другу». Такой
критерий сразу передаётся преподавателю без смыслового штрафа и без вызова LLM.
Это не универсальный алгоритм обнаружения противоречий. Остальные случаи
по-прежнему зависят от качества модели и двух согласованных проверок.

Завершённые оценки не пересчитываются. Задания, уже стоявшие в очереди со старым
prompt semantic-v1, не исполняются новым воркером как будто это прежняя версия:
действующая проверка версии оставляет такую смысловую проверку неполной.
