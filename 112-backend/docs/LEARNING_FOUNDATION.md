# Учебные режимы и контекстная помощь

Контракт `learning-v2`, 22.09.2026. Учебная роль (`operator_112` / `dds`) и сложность
принадлежат сценарию, формат и допустимая помощь — назначенному занятию.

## Доступные форматы

| Формат | Работа ученика | Подготовка |
| --- | --- | --- |
| `introduction` — освоение интерфейса | Реальные действия с пошаговой подсветкой | Помощь до эталонного решения включена автоматически |
| `practice` — полная ситуация | Вся карточка / обработка ДДС | Без выделения навыков |
| `skill_practice` — отработка | Только выбранные навыки | Остальное заполнено из снимка сценария |
| `review` — повторение | Выбранные навыки на новом назначении | Такая же подготовка, как в отработке |
| `assessment` — контроль | Полная ситуация без помощи | Отдельная контрольная успеваемость |

`worked_example` (демонстрационный разбор примера) пока недоступен. Автоматического
подбора повторения по прежним ошибкам нет. Для освоения интерфейса выбирается формат
`introduction`, без `target_skills`; отдельный навык `interface` не принимается.

### Пошаговое освоение интерфейса

Преподаватель назначает существующий сценарий 112 или ДДС в формате `introduction`.
Сервер закрепляет помощь `solution`, `on_request=true` в снимке занятия. Миграция не нужна.
Шаг определяется существующим движком подсказок по сохранённым полям/бригадам,
условным признакам и получателям. `POST /student/attempts/{id}/hints` с
`trigger=guided, level=solution` доступен только в этом формате. Ответ включает цель,
объяснение интерфейса и конкретный пример из снимка сценария. Выдача сохраняется
как `learning.hint_issued`, показ — отдельно `ui.hint_seen`; прокторинг не используется.
Отдельного клиентского счётчика «пройденных шагов» нет: перезагрузка и повторное
открытие восстанавливают следующий шаг по реальной работе. Завершение — обычное
сохранение карточки / завершение ДДС, а не кнопка перехода в подсказке.

Frontend затемняет экран вокруг нужного поля, оставляя обычные действия доступными.
Для ДДС цель уточняется состоянием интерфейса: своя служба → назначение / карандаш
бригады → открытый редактор. Панель следует за прокруткой, раскрытием окон и размером
экрана. Escape сворачивает сопровождение; его можно вернуть из учебной полосы.
«Проверить шаг» сначала сохраняет черновик и запрашивает актуальную инструкцию.
При сетевой ошибке шаг не считается выполненным; есть повтор.

Свободный текст на этапе навигации проверяется на наличие: допустимые перефразировки
не задерживают обучение. Итоговая оценка использует обычные правила и смысловую проверку,
с журналом предоставленной помощи. Это тренировка с образцом, не доказательство
самостоятельного освоения интерфейса; отдельный показатель владения им не выдумывается.
Сроки и поступление ДДС сохраняют настройки сценария/занятия. Для новичка преподавателю
следует выбирать простой сценарий без жёсткого срока. Seed `--with-training` добавляет
два занятия освоения интерфейса (112 и ДДС); теперь на чистой БД 13 занятий.

`POST /lessons/start` принимает, например:

```json
{
  "learning": {
    "version": "learning-v2",
    "kind": "skill_practice",
    "objective": "Указать место происшествия",
    "target_skills": ["address"],
    "assistance": {"max_level": "explanation", "on_request": true}
  }
}
```

В отработке/повторении нужен хотя бы один совместимый с ролью навык. Полная ситуация
и контроль не принимают `target_skills`. Сервер проверяет каждую карточку сценария:
нельзя тренировать адрес, если в эталонном решении его нет. При несоответствии — 422
с указанием карточки. Поле времени ожидания и выбор текстового/визуального режима удалены.

## Подготовка и защита полей

112: доступны адрес, заявитель, классификация с признаками, выбор служб, описание.
Выбранные данные первоначально пусты, остальные копируются из неизменяемого снимка.
`exercise_scope` у попытки сообщает UI, какие блоки доступны. Сервер также сохраняет
подготовленные значения при попытке подменить их прямым запросом.

Отработка служб начинается с явного пустого списка: автоматическая рекомендация ЕКП
не выполняет работу ученика. Если выбрана только классификация, службы подготовлены
независимо от ещё пустого типа. Подготовка фиксируется событием `learning.prepared`.

ДДС: `dds_crews` означает назначение бригад; `dds_response` — статусы бригад.
При выборе только статусов требуемые бригады заранее назначены системой. При выборе
только назначения дальнейшие статусы не требуются и не засчитываются. При обоих
навыках ученик выполняет весь процесс. Для статусов нужна хотя бы одна цель дальше
«Назначена». Сценарий без целей бригад запустить как новое занятие ДДС нельзя.

## Подсказки

`POST /student/attempts/{id}/hints`:

```json
{"request_id": "UUID", "trigger": "request", "level": "goal"}
```

Ответ содержит `status` (`ready`, `waiting`, `disabled`, `complete`), актуальную
`revision`, при наличии — `hint` с полями `id`, `task`, `level`, `text`, `target`,
`presentation`. Сервер проверяет владельца, открытость попытки и уровень разрешённой помощи.

- `goal`: цель оставшегося шага, без ответа, названия кнопки или подсветки.
- `explanation`: конкретное незавершённое действие/поле и подсветка блока.
- `solution`: эталонное значение или следующий допустимый статус бригады.
- `max_level=none`: подсказок нет; контроль всегда использует этот вариант.

Выбор шага учитывает сохранённые данные, видимые условные признаки, выбранные службы,
состав и историю бригад. Сначала тип, затем его признаки; выполненные элементы
пропускаются. Напоминание не означает доказанной ошибки или неспособности ученика.

Автоматически разрешено только `goal`. Пауза 45 секунд задана константой
`AUTO_HINT_DELAY_SECONDS` в `app/services/learning_hints/policy.py`. Браузер опрашивает API
раз в 15 секунд только на видимой странице без текущего ввода/записи; сервер
проверяет время последней содержательной команды/подсказки. Это временная эвристика,
не норматив. Подробная помощь — по запросу ученика, если `on_request=true`.

Сервер идемпотентен по `request_id`, не дублирует один шаг/уровень/ревизию. Старый
ответ после изменения карточки не выдаётся повторно. UI сбрасывает подсказку и
подсветку после изменения, перед запросом сохраняет локальный черновик.

`learning.hint_issued` — подтверждённое системное событие с уровнем, шагом,
ревизией, триггером и текстом ответа. Эти события отделены от прокторинга и
неподтверждённых наблюдений браузера. Контекст оценки и будущего ИИ содержит
количество подсказок по уровням, ссылки на события и область упражнения.

## Оценивание

Подготовленные поля и действия исключены из критериев. В 112 проверяются только
выбранные поля; в ДДС назначение и результат бригад считаются раздельно, лишние
действующие бригады снижают результат. Незавершённую работу можно сдать — пропуски
дадут нулевые критерии; пропущенные карточки учитываются при завершении занятия.
Преподаватель сохраняет возможность пересмотра.

Свободный текст не оценивается на смысл без ИИ/преподавателя. В отдельной отработке
описания или адреса, заданного только строкой, автоматический балл проверяет лишь
наличие текста: критерий явно подписан. Для проверки точного адреса преподавателю
нужно заполнить структурированные поля. Не трактовать такой балл как подтверждение
профессиональной правильности или готовности.

Число подсказок видно преподавателю, но автоматического штрафа за помощь нет.
Самостоятельность и владение интерфейсом пока `not_measured`, не выдуманный процент.
Время включает паузы и не штрафует. Тренировки и контроль сохраняют отдельные
диаграммы/агрегаты, последние пять оценённых работ и общую успеваемость.

## Новые занятия ДДС и история

Назначения, созданные сейчас, получают `learning_engine=workflow-v1`; ДДС фиксирует
`dds_policy.workflow=crews-v1`. Ученик назначает бригады, меняет статусы через карандаш
и завершает упражнение. Статус службы остаётся «Добавлена» (внутренний `received`),
действия бригады не меняют службу. Приём/завершение службы не нужны и запрещены API.
Эталонный список целей бригад не передаётся ученику; подсказки вычисляются на сервере.

Условия содержат весь пакет сообщений сценария сразу. Это текстовые сведения для
работы, а не симуляция поступления радиосообщений во времени. Комментарий бригады
необязателен. Новый редактор сценария сохраняет сообщения и цели бригад, без
обязательной последовательности статусов службы. Политика оценки — `dds-crew-workflow-v1`.

Миграция `0018_learning_workflows` переводит настройки в v2 и сохраняет исходные
снимки в `learning_legacy`. **Исторические назначения не получают новый движок**,
их оценки/события не переписываются. Для новых возможностей создайте новое занятие.
Совместимость HTTP-запросов со старой формой настроек не поддерживается; frontend
и backend обновляются вместе. Старая обработка ДДС сохранена только для истории.

## Проверки

`tests/test_learning_workflows.py` проверяет область навыков, защиту подготовки,
ограничения и идемпотентность помощи, автоматическую паузу, контроль, оценивание
бригад без изменения службы и миграцию истории. Старые тесты DDS проверяют
исторический процесс. `scripts/seed_demo.py --with-training` создаёт новые занятия
ДДС через бригады; существующие назначения повторный seed не переписывает.


### Уточнение сопровождения, 24.09.2026

Перед вводом показывается условие задачи с кнопкой «Продолжить». После заполнения
112 отдельно объясняется автоматический подбор служб и возможность изменить список
вручную; если получатели уже подходят к задаче, менять их не предлагается.
В журнале подсветка показывает «+» для новой карточки, возврат к начатой, старт
занятия или ожидание поступления ДДС. После сохранения — возвращение в журнал.
«Отключить сопровождение» находится на поясняющей карточке; отключение действует
в пределах открытого занятия, включая переключение карточек, включение — в учебной полосе.

`LearningHint.advance` различает `action` (проверка действия/точного ответа) и `confirm`
(ознакомление или свободный текст). `continue_allowed` сообщает, заполнено ли поле.
Для свободного адреса, описания и текстовых признаков наличие текста больше не переводит
гайд дальше автоматически. Клиент сохраняет текущий ввод и передаёт `confirm_hint_id`
в hints API. Пустой ответ отклоняется; подтверждается только реально выданный текущий шаг
данной попытки. Событие `learning.guide_confirmed` хранит ссылку на подсказку, шаг и хеш
текущего значения. После изменения подтверждённого текста требуется повторное подтверждение.
Повтор команды не подтверждает следующий шаг. Подтверждение не означает правильность
содержания: итоговая проверка остаётся отдельной. Точные поля ждут совпадения с условием.

Подсветка поиска включает выпадающий список. Технические формулировки про эталон/ЕКП
заменены коротким объяснением и фразами «По условию задачи правильный ответ…» либо
«Например…» для свободного текста. Подтверждения и подсказки не смешиваются с прокторингом.

Для конкретного адреса без `address_details.description` сопровождение объединяет
проверяемые части в шаг `guide.address`: подсвечивается весь блок, перечисляются
заданные в условии поля (улица, дом, квартира и другие). Переход — только после
совпадения всех заданных структурированных значений. Описательный ввод не заменяет
эти поля; неизвестные части не требуются. Адрес с ориентирами сохраняет отдельные
проверки известных частей и подтверждение свободного текста через «Продолжить».
