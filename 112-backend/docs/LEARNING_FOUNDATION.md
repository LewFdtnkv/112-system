# Основа учебных режимов

Реализовано 22.09.2026. Версия контракта: `learning-v1`.

Учебная роль (`operator_112` / `dds`) и сложность принадлежат версии сценария.
Цель и режим помощи принадлежат назначенному занятию. Один сценарий можно назначать
для тренировки и отдельно для контроля, не создавая копии карточек.

## Политика занятия

`POST /lessons/start` принимает `learning`:

```json
{
  "version": "learning-v1",
  "kind": "skill_practice",
  "objective": "Точно указать адрес происшествия",
  "target_skills": ["address"],
  "assistance": {
    "mode": "visual",
    "max_level": "explanation",
    "on_request": true,
    "idle_seconds": 45
  }
}
```

- Доступны `practice`, `skill_practice`, `review`, `assessment`.
- `introduction` и `worked_example` зарезервированы; запуск возвращает 422,
  пока нет соответствующего процесса. В форме они показаны как будущие режимы.
- Навыки: `interface`, `address`, `caller`, `classification`, `notification`,
  `description`, `dds_response`, `dds_crews`. Навыки ДДС несовместимы с ролью 112
  и наоборот; `interface` общий. Отработка навыка и повторение требуют хотя бы одного.
- `objective` — видимая ученику цель, без эталонного ответа.
- Помощь: `none`, `text`, `visual`; глубина: `goal`, `explanation`, `solution`.
  Включённая помощь требует запроса учеником или паузы 10–3600 с.
  Выключенная помощь не допускает триггеров или раскрытия решения.
- Контроль всегда без помощи. Сервер отвергает несовместимые настройки, а UI
  при переходе к контролю сбрасывает помощь.
- Значения времени — параметры преподавателя, не утверждённые нормативы.

**Выдачи подсказок, определения затруднений, обучения интерфейсу и адаптивного
назначения следующих занятий пока нет.** Настройки помощи сохраняют намерение
преподавателя, но не означают, что помощь реально выдавалась. UI прямо сообщает об
этом. `learning_result.assistance_available` сейчас всегда false.

Целевые навыки пока описывают фокус занятия, не отфильтровывают поля карточки и не
меняют рубрику. Все карточки выполняются текущим процессом, оценка — по сценарной
политике. Повторение назначается преподавателем; подбор новых ситуаций и пороги
освоения навыков остаются будущими алгоритмами.

## Сохранение и чтение

Миграция `0017_learning_foundation` добавляет `lessons.learning` JSONB и переносит
исторические режимы из assignments. Существующие оценки и контексты Evaluation
не переписываются. Старые hint_delay_seconds остаются в исторических данных;
наличие этого параметра не принимается за факт помощи.

При новом запуске нормализованная политика копируется в `assignments.settings.learning`.
При старте попытки она фиксируется в `attempts.settings_snapshot.learning`, затем
в контексте новой оценки. Поздние изменения назначения не меняют снимок попытки.
Параметры входят в отпечаток идемпотентного запуска.

Политика возвращается в LessonRead, StudentLessonRead, StudentAttemptRead,
LessonWorkReview и строках списков. `GET /views/lessons` и
`GET /views/student/lessons` принимают фильтр `kind`. Доступ ограничен существующими
проверками владельца, преподавателя и ученика; эталоны ученику не раскрываются.

Старые поля запроса `mode` и `hint_delay_seconds` заменены `learning`; лишние поля
запрещены. Внутренние mode у Assignment/Attempt пока сохраняются как грубая
категория: assessment для контроля, practice для остальных доступных режимов.

## Показатели результата

StudentLessonRead и LessonWorkReview возвращают одинаковый `learning_result`:

- `correctness`: последняя итоговая оценка в процентах; указано, формальные ли это
  критерии или пересмотр преподавателя. До оценки — pending/null.
- `independence`, `interface`: not_measured/null. Нулевое число подсказок не
  превращается в доказательство самостоятельности или владения интерфейсом.
- `duration`: сумма длительностей завершённых/прерванных попыток, включая паузы.
  Это не активное время взаимодействия и не временной штраф. Незавершённые
  попытки в сумму не входят.

Это проекции существующих данных, а не второй изменяемый источник оценок.
Будущие алгоритмы смогут сохранять доказанные показатели через версионированные
Evaluation/CriterionResult с источником, критериями и доказательствами.

Дашборд и краткий профиль показывают две независимые группы результатов:
training (practice/skill_practice/review) и assessment. Для каждой — общий средний
процент и последние 5 оценённых работ по времени завершения. Аналитика также
принимает `track=training|assessment`, по умолчанию training. Историческое
introduction не входит ни в тренировочную, ни в контрольную успеваемость.
Результаты formal_fields не объявляются подтверждением профессиональной готовности.

## Проверки

Тесты `test_learning.py` покрывают валидацию политик, границы доступа, совместимость
с ролью, повтор запуска, неизменность снимка, разделение результатов и отсутствие
выдуманных баллов. Playwright `e2e/learning.spec.ts` проверяет настройки преподавателя,
сброс помощи в контроле, фильтр занятий, раздельные диаграммы и показатели результата.
