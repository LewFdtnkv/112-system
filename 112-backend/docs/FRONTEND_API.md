# Представления для frontend

Все маршруты `/api/v1/views/*` защищены общей авторизацией. Системные роли ученика, преподавателя
и администратора взаимоисключающие. Ученику доступны только собственные назначения.

## Компактные страницы

Ответ списка: `{items, total, limit, offset}`. По умолчанию 20 записей, максимум
100. Поиск `q` ограничен 200 символами. Сортировка стабильная с ID как последним
ключом. Полные карточки и скрытые условия не включаются в списки.

| GET | Права | Поля / параметры |
| --- | --- | --- |
| `/views/users` | преподаватель/администратор | профиль без секретов, группы; `q`, `role`, `group_id` |
| `/views/groups` | преподаватель | свои группы с числом учеников; `q` |
| `/views/cards` | преподаватель | свои шаблоны без полного содержимого; `q`, `classifier_version_id` |
| `/views/scenarios` | преподаватель | последние версии своих сценариев с числом карточек; `q`, `status` |
| `/views/lessons` | преподаватель | строка на ученика в своём уроке; `q`, `status`, `lesson_id` |
| `/views/student/lessons` | ученик | собственные строки уроков; `q`, `status` |
| `/views/analytics` | преподаватель | агрегаты своих работ и пагинация по версиям сценариев |
| `/views/admin/dashboard` | администратор | только количества пользователей, служб и версий ЕКП |
| `/views/admin/services` | администратор | активные службы; `q` |
| `/views/admin/classifiers` | администратор | версии ЕКП без тяжёлого отчёта импорта |

`/views/*lessons` дополнительно возвращает числа назначенных, начатых, сданных
и оценённых работ для текущего фильтра. `score/max_score/evaluation_revision/evaluation_method`
берутся из последней редакции оценки, без отдельного запроса для каждой строки.
Усреднение в аналитике — проценты `score / max_score * 100`, только оценённые
работы, одна последняя оценка на работу. Отсутствующая оценка остаётся `null`.

В списке пользователей группы получаются одним пакетным запросом; преподаватель
видит только названия своих групп. Фильтр по группе проверяет её владельца.
Списки с подсчётом и агрегаты используют постоянное число SQL-запросов, без N+1.
Проверка преподавателем `/lessons/{id}/students/{id}/work` также загружает
карточки/получателей пакетно; `source_classifier_entry` показывает эталонный тип.
Это представления существующей БД, не отдельные копии учебного состояния.

## Версии сценария

Миграция `0006_frontend_scenarios` добавляет `category`, `duration_minutes`,
`norm_seconds`. Сложность: `basic`, `intermediate`, `advanced`.
`norm_seconds` — учебный ориентир интерфейса, не утверждённый профессиональный
норматив и не автоматическая формула оценки. Лимит попытки задаётся отдельно
при запуске урока.

`POST /scenarios` принимает `status: draft|published` (по умолчанию `published`
для совместимости). `POST /scenarios/{version_id}/versions` создаёт следующую
редакцию с новым упорядоченным снимком карточек. Родительский сценарий блокируется
при определении номера версии. Назначенные уроки сохраняют прежнюю редакцию.
Необходимость опубликованного ЕКП и профиля ДДС не обходится черновиком.

## Карточка ученика

`GET /student/lessons/{id}` теперь содержит компактный `assignments[].card`
только с собственными сохранёнными данными ученика: журнал открывается одним
HTTP-запросом без запроса на каждую строку. Детальная карточка загружается при
открытии. Эталонные сведения в ученическую проекцию не попадают.

Ответ попытки включает выбранный `classifier_entry`, `recipient_services`,
`recipient_error` и `norm_seconds`. Поиск по `q` поддержан в каталогах версий,
профилей и типов, включая `/student/attempts/{id}/classifier-entries`.
`GET /student/attempts/{id}/recipients?classifier_entry_id=...` рассчитывает
предпросмотр получателей без изменения черновика; проверяется назначенная версия.

Сохранение и оповещение остаются разными действиями. PUT черновика и POST submit
проверяют `revision`; повторная отправка уже завершённой попытки идемпотентна.
После оповещения статус карточки — `notified`, а не завершение работ служб.
Условные маршруты по-прежнему возвращают 409, выполнение ДДС/SIP и ИИ не добавлены.

## Проверка

`tests/test_frontend_views.py`: права, поиск/пагинация, отсутствие эталона у
ученика, предпросмотр без записи, последняя оценка, новые версии сценариев и
ограничение числа запросов проверки работ. Запуск — вместе с остальными pytest
на отдельной мигрированной БД через `TEST_DATABASE_URL`. Браузерные проверки
frontend используют другую отдельную БД: они сохраняют аккаунты и работы.

## Управление аккаунтами и автопроверка

Изменения ролей и отключение сеансов: [USER_ADMINISTRATION.md](USER_ADMINISTRATION.md).
Сравнение с эталонами и предварительный балл: [AUTOMATIC_CHECK.md](AUTOMATIC_CHECK.md).

Автооценка после сдачи всех карточек и ручной пересмотр возвращают общий Grade DTO:
`method: rules | teacher`, `reviewer_id: UUID | null`, `assessment_details` (группы,
баллы, число карточек и непроверенных полей; без скрытого эталона). Преподаватель
получает историю, ученик — последнюю редакцию. Аудит загружается лениво и постранично.
См. [оценивание](ASSESSMENT_ARCHITECTURE.md), [аудит](ATTEMPT_AUDIT.md),
[обзор незавершённых функций](CODE_ARCHITECTURE_AUDIT.md).
