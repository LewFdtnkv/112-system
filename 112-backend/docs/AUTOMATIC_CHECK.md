# Диагностическое сравнение полей

Преподаватель получает `automatic_check` вместе с
`GET /api/v1/lessons/{lesson_id}/students/{student_id}/work`. На уровне работы это
только агрегат; `assignments[].automatic_check` содержит строки сравнения. Дополнительных
HTTP/SQL-запросов для автопроверки нет. До начала карточки её проверка равна `null`,
а сводка до первого проверяемого поля имеет `score_percent: null`, не ноль.

Эталон — снимок `scenario_cards.snapshot`, сохранённый при выпуске версии сценария.
Изменение исходного шаблона не меняет результат назначенного урока. В ученические
ответы API эталон, строки сравнения и предварительный балл не попадают.

Метод `fields-v1` проверяет:

- выбранный код ЕКП и полный набор фактически оповещённых служб;
- ФИО и телефон заявителя, если заданы в эталоне;
- заполненные структурированные компоненты `data.address_details`;
- `data.features.victimsCount`, если задано, включая значение `0`.

Каждый такой критерий имеет вес 1. Предварительный балл в процентах —
`100 × earned_points / possible_points`, округление до двух знаков.
Пустые эталоны не добавляют критерий. Пропуск или расхождение получает 0;
сравнение списка служб — один критерий, порядок служб не учитывается.
Урок агрегируется по всем критериям начатых карточек, не по среднему их процентов.
Пока работа не сдана полностью, UI явно обозначает неполный результат.

Для строк игнорируются регистр, различие е/ё, края и повторяющиеся пробелы,
используется Unicode NFKC. В телефоне убираются знаки форматирования; начальная
8 в российском 11-значном номере эквивалентна +7. Номера домов `12/1` и `121`
не приравниваются. Сокращения улиц, перестановка ФИО и смысловые синонимы
не распознаются автоматически: преподаватель проверяет отмеченные расхождения.

Свободный адрес (если нет структурированного), уточнение адреса, сообщение и сведения
о пострадавших отображаются, но **никогда не входят в числовой балл**. Несовпадающий
текст имеет статус `needs_review`, а не профессиональную ошибку. Остальные статусы:
`matched`, `missing`, `different`. Для каждого поля показаны эталон, ответ и `scored`.
Неизвестные дополнительные JSON-поля, таймеры, действия ДДС и смысл текста автоматически
не оцениваются. Это тестовая прозрачная формула, не утверждённая методика аттестации.

Начиная с `0008_automatic_assessment`, итог рассчитывается и сохраняется автоматически
по взвешенным группам, а преподаватель может пересмотреть его. Старые агрегаты
`fields-v1` оставлены для совместимости API; интерфейс показывает таблицу диагностики,
а числовой итог берёт из сохранённой `LessonEvaluation`, не из равновесного процента.
Формула, веса, границы проверки и дальнейшее участие ИИ описаны в
[ASSESSMENT_ARCHITECTURE.md](ASSESSMENT_ARCHITECTURE.md).
