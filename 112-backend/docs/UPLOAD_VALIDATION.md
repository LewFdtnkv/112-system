# Проверка файлов и лимит загрузки

Для всех загрузок действует единый предел **1 МБ = 1 048 576 байт**:

- собственное фото и фото пользователя, загружаемое администратором;
- импорт справочника ЕКП из JSON;
- WAV преподавателя и WAV от фонового генератора речи.

Лимит проверяет API по фактическому потоку байтов, включая запросы без Content-Length.
Nginx ограничивает те же маршруты; лимит обычных API-запросов не изменён.
Frontend заранее проверяет размер фотографии, справочника и записи и показывает причину отказа.
Ограничение WAV означает примерно 65 секунд аудио в поддерживаемом PCM mono 8000 Hz / 16 bit.
Длинную запись нельзя загрузить целиком даже при корректном формате.

## Воспроизведённые дефекты

1. Pillow.load принимал PNG без IEND. Добавлены проверка целостности/контрольных сумм
   и проверка завершающего блока (Pillow.verify сам не проверяет CRC IEND).
   Допустимые PNG/JPEG по-прежнему полностью декодируются и преобразуются в JPEG 512×512;
   метаданные и исходный файл не сохраняются. Предел изображения — 16 мегапикселей.
2. Повреждённая длина WAV-чанка вызывала необработанный RuntimeError из wave.open.
   Теперь возвращается 422, также проверяются длина RIFF и целостность PCM-кадров.
3. Раньше пределы различались: фото 2 000 000 байт, JSON 8 МиБ, WAV 10 000 000 байт.
   Общий потоковый reader останавливается до добавления превышающего лимит блока в буфер.

Расширение и Content-Type не подтверждают формат. Проверяется содержимое:
текст, SVG или GIF под видом PNG не принимаются; JSON проходит схему справочника.
Ошибки возвращаются как 422 с понятным сообщением, превышение размера — 413.
Неудачная загрузка не заменяет существующее фото или запись и не создаёт версию справочника.

## Проверка 27.09.2026

- tests/test_upload_validation.py: обе ручки фото, обе ручки WAV, JSON;
  поддельный тип, пустой/обрезанный файл, неверные CRC/длины чанков, чрезмерное число
  пикселей, невалидный UTF-8/JSON, chunked-загрузка, граница размера и сохранность данных.
- Реальный временный HTTP API и отдельная PostgreSQL: корректный PNG — 204,
  поддельный/обрезанный/испорченный PNG — 422, фиктивный JSON — 422,
  превышающие лимит PNG/JSON — 413. Предыдущее фото не изменилось.
- Настоящий nginx: все пять upload-маршрутов возвращают 413 при превышении;
  небольшой запрос доходит до авторизации API; chunked JSON также ограничен.
- Frontend: build, lint/FSD и 201 Vitest; Chromium и Firefox проверяют ошибки выбора
  фиктивного PNG и слишком большого файла без отправки на сервер. Снимок просмотрен.

Рабочие пользовательские файлы и БД не менялись. Первая полная регрессия выполнялась
с дополнительным пользователем HTTP-проверки, из-за чего не совпали счётчики seed-тестов;
повтор выполнен на чистой БД. Отдельно исправлена нестабильная фикстура проверки
пагинации профилей: PostgreSQL now() одинаков для всех запросов внутри общей тестовой
транзакции, поэтому порядок двух профилей случайно зависел от UUID. Фикстура теперь
явно задаёт более раннее время первому профилю; сортировка API не изменена.

Итог полной регрессии до исправления фикстуры: 593 passed, 1 failed (только указанная
пагинация). После исправления отдельно прошли пагинация и все проверки загрузок —
7 тестов. До этого 27 целевых проверок загрузок, профиля и телефонии также прошли.
