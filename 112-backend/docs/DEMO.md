# Тестовые данные и сквозная проверка через API

`scripts/seed_demo.py` — отдельный Python-скрипт на стандартной библиотеке, без прямого
доступа к БД и без импорта моделей приложения. Все данные создаются HTTP-запросами.

## Запуск

Нужна БД с применёнными миграциями и работающий API. Скрипт рассчитан в том числе на
первый запуск, когда в БД есть только начальный `admin:admin`:

```bash
# Из 112-backend, при настроенном .env и запущенной PostgreSQL:
uv run --locked alembic upgrade head
uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
uv run --locked python scripts/seed_demo.py --base-url http://localhost:8000
```

Скрипт меняет обязательный стартовый пароль `admin`, создаёт `demo-teacher` и
`demo-student`, затем входит каждым новым аккаунтом и меняет его стартовый пароль.
Пароли генерируются случайно. **Сохраните `.demo-seed.json`: там находятся
`admin_new_password` и `accounts.teacher.password` / `accounts.student.password`.**
Права файла — `0600`, в Git он исключён. Токены в файл не записываются, пароли в консоль
не выводятся. `admin_new_password` применяется, только если администратору требовалась смена.

Если пароль администратора уже был изменён, передайте действующий пароль через
переменную окружения `DEMO_ADMIN_PASSWORD`. Скрипт не меняет его повторно без флага
обязательной смены. На повторном запуске также умеет использовать ранее сгенерированный
пароль администратора из своего файла состояния.

### Если вход вернул HTTP 502

Проверить `docker compose ps` и `curl --noproxy '*' http://localhost:8000/health/ready`.
Ошибка 502 означает проблему на пути HTTP-запроса или в шлюзе; неправильный пароль
обычно возвращает 401. Для `localhost` и loopback IP скрипт обращается напрямую,
игнорируя системный/VPN-прокси. Для удалённых адресов настройки прокси сохраняются.
После устранения причины повторить ту же команду с тем же файлом состояния;
из-за ошибки входа удалять БД или файл состояния не нужно.

Другой набор и расположение файла:

```bash
uv run --locked python scripts/seed_demo.py \
  --base-url http://localhost:8000 \
  --prefix check2 \
  --state-file .demo-seed-check2.json
```

Префикс — 1–20 строчных латинских букв, цифр, `_` и `-`, начинается с буквы/цифры.
Файл состояния привязан к адресу API и префиксу. Повтор **успешного** запуска с тем же
файлом переиспользует данные и не создаёт повторных уроков/оценок. Если БД была заменена,
нужен новый файл состояния. При ошибке скрипт завершается с ненулевым кодом, не удаляя
уже созданные данные. Потерю ответа на создание объекта до записи его ID в файл нужно
разобрать отдельно; общей распределённой транзакции между API и локальным файлом нет.

## Что останется в БД

- Администратор со сменённым стартовым паролем, преподаватель и ученик.
- Группа преподавателя с одним учеником.
- Одна явно тестовая служба и опубликованный искусственный справочник
  `demo-synthetic-ekp-v1` с кодами `DEMO.001` и `DEMO.002`.
- Две карточки преподавателя и сценарий оператора 112 из этих карточек.
- Завершённый урок: две попытки с заполнением карточек и учебным оповещением,
  журнал действий и ручная итоговая оценка `4/5` с комментарием.
- Второй назначенный урок, к которому ученик ещё не приступал, для ручной проверки.

Тестовый справочник проходит штатное создание черновика и публикацию через API.
Он **не является реальным ЕКП** и не заменяет импорт предоставленных XLSX.
Дополнительный справочник включает условные маршруты по явным признакам. ИИ, SIP и реальные службы не вызываются.

В консоли выводятся логины, идентификаторы группы, сценария, проверенного урока
(`completed_lesson_id`), урока для самостоятельной проверки (`ready_lesson_id`),
полученная оценка и путь к файлу с паролями.

## Ручная проверка

Войти через `/api/v1/auth/login` с данными из файла, вставить access-токен в Swagger
`Authorize` либо использовать его в HTTP-клиенте. У ученика открыть `/student/lessons`,
выбрать `ready_lesson_id` и пройти карточки последовательно. Преподаватель смотрит
`/lessons/{id}/students/{student_id}/work` и выставляет оценку через `/evaluations`.
Полные контракты: [STUDENT_WORKFLOW.md](STUDENT_WORKFLOW.md).

Frontend подключён: ученик открывает назначенные занятия, преподаватель — результаты, администратор — «Службы и классификаторы».

## Расширенный набор (v2)

В дополнение к прежним двум карточкам seed создаёт через штатный HTTP API:

- 36 искусственных типов в 6 разделах: пожары, полиция, медицина, газ, ЖКХ, спасательные работы.
- 7 учебных служб с опубликованными профилями, территориями, объектами и контактами.
- По 3 уточняющих признака на тип, условные маршруты, 12 эталонных карточек
  с разными ответами, структурированными адресами и описанными в условии фактами.
- Проверенный автоматически урок 112 из 12 карточек (100/100) и такой же новый урок.
- Сценарий ДДС из двух карточек: принятие, выезд, прибытие, проведение работ, завершение;
  сообщения наряда и проверка его номера, проверенный урок (100/100) и новый урок.

Итого 6 уроков, 32 назначения, 16 завершённых попыток. Новые ключи состояния имеют
префикс v2 и не заменяют прежние ID; повтор успешного запуска идемпотентен.
Вывод дополнен expanded_classifier_id, expanded_entry_count, expanded_case_count,
expanded_ready_lesson_id, dds_ready_lesson_id и service_profile_count.
Все соответствия явно учебные: набор расширяет охват интерфейса, но не заменяет
нормативный ЕКП. Формат файла и процесс ДДС — [CATALOG_AND_DDS.md](CATALOG_AND_DDS.md).
