# Наполнение справочника из документов

`seed_demo.py` загружает 211 служб и 51 тип происшествия (177 типовых полей).
Источник названий: `documents/СЛУЖБЫ 112.docx` и `documents/КАРТОЧКА 112.docx`.
По умолчанию загружается только справочник. Флаг `--with-training` добавляет
преподавателя, ученика, группу, шесть тестовых карточек, сценарий и активный урок
оператора 112 на этом же ЕКП. Старые искусственные типы/службы не возвращаются.
Новых миграций для наполнения или зависимых полей нет.

## Запуск в Docker

Из `112-backend` после обычного запуска Compose:

```bash
docker compose exec -T api python scripts/seed_demo.py --database
```

Команда использует настроенную БД и существующего активного администратора,
проверяет документ теми же моделями, что API, импортирует и публикует версию.
В режиме `--database` пароль администратора не меняется. Повторный запуск не дублирует записи.
Изменённый вручную справочник с тем же названием автоматически не заменяет.

Остался вариант через HTTP API (Python без дополнительных библиотек):

```bash
python scripts/seed_demo.py --base-url http://localhost:8000 --state-file .demo-seed.json
```

Для уже изменённого пароля задайте `DEMO_ADMIN_PASSWORD` либо используйте прежний
файл состояния. На пустой БД HTTP-вариант меняет обязательный стартовый пароль
`admin:admin`; новый пароль сохраняется в файле состояния с правами `0600`.
Не удаляйте и не публикуйте этот файл. `--prefix` сохраняет совместимость старых
команд и файлов состояния; содержимое справочника от префикса не зависит.

## Справочник вместе с пользователями и карточками

Через тот же HTTP seed:

```bash
python scripts/seed_demo.py --with-training --base-url http://localhost:8000 --state-file .demo-seed-source.json
```

Или полностью в Docker, с сохранением файла паролей в рабочей папке хоста:

```bash
docker compose run --rm --no-deps --user "$(id -u):$(id -g)" -v "$PWD:/workspace" -w /workspace api python scripts/seed_demo.py --database --with-training --state-file .demo-seed-source.json
```

Создаются `demo-teacher` и `demo-student` (префикс можно изменить). Карточки:
пожар мусора, пожар автомобиля, ДТП, запах газа, ошибочный вызов и консультация.
Службы рассчитаны по маршрутам нового справочника, зависимые ответы согласованы
с выбранной веткой. Файл состояния сохраняет ID и пароли с правами
`0600`; используйте его же при повторном запуске. Существующие записи не дублируются.
После удаления прежнего набора используйте новый файл состояния.

Seed в обоих режимах сам меняет стартовые пароли **ученика и преподавателя**.
Действующий пароль находится в `accounts.student.password` / `accounts.teacher.password`
и выводится в итоговом JSON (`training.accounts`). При входе менять его уже не требуется.
Для разработки используется формат `<логин>-123`: `demo-student-123` и `demo-teacher-123`.
`initial_password` — технический стартовый пароль, после успешного seed он не действует.
Повторный запуск с прежним файлом состояния также переводит старые тестовые аккаунты
на этот формат, используя сохранённый действующий или стартовый пароль. Если пароль
вручную изменили и он неизвестен seed, скрипт сообщает ошибку вместо записи неверного
`password`. Поле `pending_password` сохраняет целевой пароль до завершения операции,
чтобы повторный запуск мог продолжить её после прерывания.

Пароль администратора в HTTP-режиме остаётся в `admin_new_password`; в режиме
`--database` пароль администратора не меняется. Простые пароли и их вывод относятся
только к тестовым аккаунтам seed; обычное создание пользователей не меняется.

## Что подтверждено документами

- Названия всех 211 служб и 51 типа перенесены из Word и встроенных скриншотов.
- Короткие и полные названия служб хранятся отдельно. Когда полное название
  не показано, сохранено доступное имя; неизвестное официальное имя не придумано.
- Для «101» перенесены показанные поля и варианты веток «Улица» и «Транспорт».
- По поручению пользователя недостающие поля остальных типов и веток «101»,
  обязательность и рекомендации служб разработаны для тренажёра. Это учебные
  настройки, а не утверждённые правила ЕКП исходной системы.
- Технические коды `UI-*` и `s112-*` нужны для устойчивого импорта; это не коды
  официального классификатора. Ученику показываются короткие названия.

Данные: `scripts/data/system112_catalog.json` (также можно загрузить в кабинете
администратора). Происхождение, номера скриншотов и SHA-256 документов:
`scripts/data/system112_sources.json`. При экспорте сохраняются также службы,
которые пока не используются в маршрутах.

## Условные поля

Правила находятся в `entries[].features[].visible_when`, в БД сохраняются в
существующем JSONB `classifier_entries.conditions`; миграция не нужна.

```json
{
  "key": "street_object",
  "label": "Что горит",
  "type": "choice",
  "required": false,
  "options": ["Мусор", "Трава, пух"],
  "visible_when": [{"where": "Улица", "street_sign": "Открытое пламя / Дым"}]
}
```

Поля-родители должны идти раньше зависимых. Все условия внутри объекта — «И»,
объекты списка — «ИЛИ». Отсутствие условий означает постоянную видимость.
Скрытое поле не включает другие поля. Frontend переключает ветки без запроса,
удаляет скрывшиеся ответы; backend отклоняет такие ответы и проверяет
обязательность только видимых полей. Поддержаны boolean, choice, array и text.
Администратор меняет условия показа в редакторе черновика ЕКП или JSON-файле.
Опубликованная версия неизменяема: сначала создайте её новую черновую версию.

## Очистка прежнего демонстрационного набора

Сначала сохраните резервную копию вне Git:

```bash
mkdir -p .backups
chmod 700 .backups
umask 077
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > .backups/before-catalog.dump
```

План ничего не удаляет:

```bash
docker compose exec -T api python scripts/cleanup_demo.py --prefix demo
```

Применение проверенного плана:

```bash
docker compose exec -T api python scripts/cleanup_demo.py --prefix demo --apply
```

Удаляются старые службы `<prefix>-fire` и прочие известные коды старого seed,
справочники целиком из DEMO./TRAIN. с этими службами (включая копии), связанные
тестовые карточки/сценарии/занятия/попытки/оценки/аудит и задачи генерации.
Тестовые аккаунты и группы удаляются только при отсутствии посторонних данных.
Смешанные ссылки на другие справочники прерывают очистку. Удаление выполняется
одной транзакцией с блокировкой записи; на время команды остановите учебную работу.
Администратор, его пароль и посторонние данные сохраняются. Повторная очистка безопасна.
