# Карта, адресный поиск и перевод

Яндекс.Карты отображаются в браузере. Поиск и обратное геокодирование выполняются через DaData на backend, перевод — через Yandex Translate. Эти функции требуют интернета; ручной ввод остаётся доступным без них.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `VITE_YANDEX_MAPS_API_KEY` | Публичный ключ JavaScript API Карт 2.1, ограниченный доменами frontend |
| `DADATA_API_KEY` | Серверный ключ Suggestions API |
| `YANDEX_TRANSLATE_API_KEY` | Серверный API-ключ сервисного аккаунта Yandex Cloud для перевода |
| `YANDEX_CLOUD_FOLDER_ID` | Необязательный каталог Yandex Cloud |
| `EXTERNAL_SERVICES_TIMEOUT_SECONDS` | Ожидание ответа, по умолчанию 8 секунд |

Задайте значения в `.env` backend, затем:

```sh
docker compose up -d --build api frontend
```

Compose передаёт публичный ключ карт Nginx; при старте создаётся `map-config.js`. Секреты DaData и Translate получает только API. Ключ JavaScript API не подходит для переводчика.

При отдельной разработке frontend публичный `VITE_YANDEX_MAPS_API_KEY` задаётся в его `.env`. Секретные ключи остаются в backend. Не добавляйте рабочие значения в Git.

## API и применение

- `POST /addresses/suggest` — варианты адреса по строке поиска.
- `POST /addresses/reverse` — ближайший известный адрес точки.
- `POST /translations/translate` — перевод текста на русский.

Все пути имеют префикс `/api/v1` и требуют авторизации. Форматы тел доступны в Swagger. Адрес содержит строку, координаты и известные компоненты; отсутствующие сведения не выдумываются.

Обратное геокодирование не гарантирует точное совпадение дома. Пользователь проверяет результат и применяет его к черновику. Сам запрос поиска или перевода карточку не меняет.

Вызовы идут по фиксированным адресам без перенаправлений. Ошибка ключа, сети или лимита возвращается как понятная недоступность сервиса; исходный текст и секреты не попадают в обычный HTTP-журнал. Локальные тайлы и офлайн-геокодер требуют отдельного подключения.
