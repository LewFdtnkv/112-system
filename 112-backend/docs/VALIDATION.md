# Валидация запросов и загрузок

Проверка выполняется на сервере независимо от формы браузера. Сначала проверяется формат, затем права, ревизия и предметные ограничения. Допустимый, но неверный учебный ответ оценивается; недопустимый запрос отклоняется.

## Ошибки формы

API возвращает пользовательский `message` и `field_errors` с `path`, `message`, `code`. Frontend связывает путь с полем, раскрывает скрытый раздел и показывает сводку. Текст исключения не используется как ключ поля.

Для зависимых признаков ЕКП учитываются условия отображения и обязательность. Нельзя требовать скрытый вопрос без объяснения. Ограничения конфликтующих значений проверяются также после смены типа, профиля и режима задания.

## Числа и ревизии

| Значение | Ограничение |
| --- | --- |
| Общий `limit` пагинации | 1–100 |
| `offset` | Неотрицательное целое в диапазоне signed int64 |
| `after`, `through` аудита | 0–2147483647 |
| Входные ревизии | Целое до 2147483647; нижняя граница зависит от команды |
| Числа в новых произвольных JSON-полях | Конечные, модуль не больше 2^53−1 |

Ревизии не приводят строки, `bool` или дроби к целым. NaN, Infinity и числовое переполнение отклоняются с 422, включая вложенный JSON. Телефон, номер дома и большой идентификатор передаются строкой.

## Загружаемые файлы

Общий предел — **1 МиБ (1048576 байт) на файл** для фотографии, WAV и импорта ЕКП. Потоковое чтение ограничено; превышение возвращает 413. Неверное содержимое — 422. Неудачная загрузка не заменяет прежний файл и не создаёт версию справочника.

| Файл | Проверка |
| --- | --- |
| Фото | PNG/JPEG, целостность контейнера, полное декодирование, до 16 мегапикселей; результат JPEG 512×512 без исходных метаданных |
| WAV | RIFF и PCM-кадры, моно, 8000 Гц, 16 бит, длительность по назначению |
| ЕКП JSON | UTF-8, синтаксис и схема справочника |

Расширение и Content-Type не подтверждают формат. Текст под именем `.png`, обрезанный файл или повреждённые чанки не принимаются. Обратный прокси также ограничивает загрузку.

## Проверки разработчика

`tests/test_upload_validation.py` покрывает фиктивные файлы, границы размера, повреждения и сохранность предыдущих данных. Числовые проверки и ограничения моделей находятся в тестах валидации. Интеграционные проверки запускаются на отдельной БД по [инструкции](DEVELOPMENT.md).
