# Работа бригад в отдельной карточке ДДС

Карточка библиотеки содержит `dds_exercise`: профиль службы, исходную историю
бригад, новые сообщения по бригадам, учебные цели и необходимость звонка при новом
назначении. В редакторе карточки включите «Подготовить карточку для оператора ДДС».
Сценарий выбирает профиль, подходящие карточки и интервалы их поступления.
Общие для всех карточек сообщения больше не настраиваются в редакторе сценария.

## История и новая работа

- `initial_crews[].history` — выполненная предыдущей сменой работа. Записи начинаются
  с назначения, следуют допустимым переходам и идут от ранних к поздним.
  `seconds_before_start` задаёт время относительно **поступления карточки**, а не её
  открытия учеником. В форме преподавателя это минуты, в API — целые секунды (0–86400).
- `messages[]` — сведения, которые нужно обработать сейчас. Они привязаны к коду
  бригады и показываются в нижней панели отдельно от истории. У ещё не назначенных
  бригад сообщения доступны на панели своей службы. Все сообщения доступны сразу;
  отложенная доставка сообщений бригад в эту итерацию не входит.
- `required_crews[]` — результаты работы, ожидаемые от ученика. Цель не может быть
  уже выполнена в исходной истории или недостижима из её последнего статуса.
  Для каждой цели обязательно сообщение; бригады должны быть активны в профиле,
  а служба профиля — получателем карточки.

Пример: в исходной истории расчёт назначен пять минут назад и выехал три минуты
назад. Новое сообщение — «Расчёт прибыл по адресу». Ученик видит две старые записи
и сам вводит «Прибытие». Новое сообщение само по себе статус не изменяет.

На старте АРМ выбирается своя служба. Синяя история раскрывается только при выборе
бригады; плитки, карандаш бригады и статус службы «Добавлена» сохранены.
В учебной инструкции даётся краткое пояснение о принятой карточке и работе с нижней
панелью. Подробные сообщения и исходная история туда не дублируются.

## Оценка, аудит и телефон

Подготовленные записи имеют `actor=simulation`, `prepared=true`, время источника
в `source_at`. Реальное время записи аудита не подменяется. Они не считаются первой
реакцией, действиями ученика или выполнением подсказки, не приносят баллы и не
передаются ИИ как комментарии ученика. ИИ получает их отдельно как исходную ситуацию.
Норматив реакции по-прежнему отсчитывается с поступления карточки.

Исходно назначенная бригада считается уже оповещённой предыдущей сменой; повторный
звонок не требуется. `crew_calls_required` относится к новым назначениям ученика.
После отмены и повторного назначения начинается новый цикл, для него звонок нужен.
Исходная отмена не засчитывается как выполненное новое назначение.

Назначение занятия на отдельный навык проверяется по каждой карточке. Если все
нужные бригады уже назначены, упражнение только на назначение отклоняется. Если в
исходной истории назначение отменено, нельзя выбрать только статусы: нужен также
навык назначения. Исходные посторонние бригады не штрафуют ученика; их самостоятельное
повторное назначение проверяется как новая работа.

## Хранение и применение

Миграция `0031_dds_card_exercises` добавляет nullable JSONB к библиотечной карточке.
Сценарий сохраняет отдельный снимок `dds_exercise` для каждой карточки, попытка —
свой снимок. Использованные карточки по-прежнему нельзя редактировать. Старые
назначения, результаты и снимки не переписываются; их прежний `dds_policy` продолжает
читаться. Для нового сценария через UI выберите карточки с новой настройкой ДДС.

`seed_demo --with-training` создаёт две отдельные карточки ДДС: продолжение работы
смены и начало работы. Ключи этих карточек/сценария/занятий имеют суффикс v2: повтор
seed со старым state-file добавляет новый пример, не сбрасывая старые занятия.
Подготовка учебных форматов использует карточки с локальной настройкой. Существующие
записи из state-file автоматически не редактируются.

Проверки: `tests/test_dds_card_exercise.py`, прежние DDS/seed/оценивание/телефония;
frontend `e2e/dds-card-history.spec.ts`. Браузер проверяется на API-фикстурах,
реальные команды и оценка — интеграционными тестами на отдельной PostgreSQL.
