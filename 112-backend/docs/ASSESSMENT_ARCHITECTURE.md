# Автоматическое оценивание и участие ИИ

Последнее решение пользователя: итог обычно появляется автоматически; преподаватель
может пересмотреть его. Для новых попыток подключена фоновая смысловая проверка semantic-v1.
История формальных и ручных оценок сохранена.

## Реализовано: weighted-fields-v1

После submit сервер атомарно сохраняет карточку, оповещение, событие и Evaluation
методом `rules`. CriterionResult хранит результат каждой группы, CriterionEvidence —
ссылки на сохранение и оповещение. Для каждой оценки сохраняется context_snapshot:
версия правил, эталон, фактическая карточка, адресаты, граница аудита и SHA-256 контекста.
Это воспроизводимый снимок, а не новая оценка при каждом просмотре.

Веса по умолчанию — учебная настройка, не утверждённый профессиональный норматив:

| Группа | Вес |
| --- | ---: |
| Тип происшествия | 25 |
| Оповещённые службы | 25 |
| Компоненты адреса | 30 |
| Имя и телефон заявителя | 10 |
| Количество пострадавших | 10 |

Преподаватель меняет веса в редакторе сценария (1–100). Политика сохраняется в
AnswerKey.rubric версии сценария и копируется в settings_snapshot попытки.
Новая версия не изменяет прежние попытки. Для старых версий без политики используется
явно обозначенная weighted-fields-v1 с весами по умолчанию, зафиксированными при старте.

Внутри группы доля — число совпавших заданных структурированных полей / число таких
полей. Баллы группы = вес × доля. Отсутствующий в эталоне критерий исключается;
нули и false не считаются отсутствием. Оповещение оценивает фактический набор служб,
а не только выбранный список. Набор служб — один критерий, порядок не важен.
Нормализация строк/телефона описана в [AUTOMATIC_CHECK.md](AUTOMATIC_CHECK.md).

Итог ученика за урок = 100 × сумма набранных баллов групп всех карточек /
сумма доступных весов. Округление до двух знаков. Таким образом, учитываются именно
доступные критерии; карточка с более полным эталоном может внести больший вес.
Число мелких компонентов адреса не увеличивает вес всей адресной группы.

На этапе формальной проверки свободный текст, свободный адрес без компонентов
и описание пострадавших не проверяются по смыслу и не входят в балл. Они явно перечислены как непроверенные.
100 по формальным полям не означает подтверждения профессиональной правильности
всего ответа. Квалификация «допущен к практике» и нормативный проходной балл не вводятся.

Когда сданы все карточки конкретного ученика, автоматически создаётся первая
LessonEvaluation с `method=rules`, шкалой 100, источниками и разрезом по критериям.
Остальных учеников ждать не нужно. Повтор submit не дублирует оценки.
Незавершённый урок не получает нулевую оценку. Если урок начат до обновления,
при последней сдаче недостающие формальные оценки предыдущих карточек достраиваются.

Пересмотр преподавателем — отдельная редакция `method=teacher` с причиной-комментарием
и expected_revision. Автоматический процесс не переписывает её. Для ранее полностью
сданных работ без результата есть идемпотентный teacher POST
`/lessons/{lesson_id}/students/{student_id}/automatic-evaluation`.
Существующий результат, включая ручной, эта команда не изменяет.

## Реализовано: semantic-v1

Новая попытка фиксирует включение смысловой проверки в settings_snapshot. При сдаче
в той же транзакции создаётся AIJob (purpose=evaluation). Исторические попытки без
этой отметки автоматически не переоцениваются. HTTP не ждёт модель. Общий worker
последовательно выполняет генерацию и оценивание, используя PostgreSQL SKIP LOCKED,
lease/heartbeat, три ограниченных повтора и защиту от запоздалого ответа.

Модель по умолчанию — существующая Qwen3 4B Instruct-2507, другой сервис не требуется.
Настройки: SEMANTIC_ASSESSMENT_ENABLED=true, ASSESSMENT_MODEL (по умолчанию модель
генерации в Python; Compose задаёт 4B), LLM_TIMEOUT_SECONDS. Контекст 4096 токенов,
выход до 650, thinking выключен. На CPU проверка выполняется в фоне и может занимать
несколько минут на карточку. Увеличение модели и памяти не входит в это обновление.

### Критерии и доказательства

- Описание, свободный адрес и уточнение адреса проверяются отдельно по условию,
  инструкциям, эталону и остальным заполненным полям. Сведения о пострадавших
  оцениваются внутри описания: отдельного текстового ввода в ученическом АРМ нет.
  Написанные необязательные комментарий оператора и уточнение типа проверяются
  только на противоречия; повторять всё условие в них не требуется. ИИ различает
  парафраз, пропуск, противоречие и недостаточность сведений.
- Обоснованность дополнительных оповещённых служб проверяется только при наличии
  всех основных получателей. Компетенция берётся из последнего опубликованного
  профиля службы и замораживается. Без профиля — спорный случай, не догадка по имени.
- В ДДС проверяются написанные комментарии бригад в контексте сообщений сценария.
  Пустой необязательный комментарий не создаёт критерия и не даёт штрафа. Статусы,
  назначение бригад и номера нарядов продолжает проверять код.
- Навыковые упражнения проверяют только выбранную область; подготовленные системой
  поля не превращаются в работу ученика. Прокторинг никогда не входит в контекст ИИ.

Каждый критерий получает отдельный небольшой промпт с разобранными примерами.
Ответ содержит цитаты, объяснение, correct/partial/incorrect/uncertain, уверенность
в вердикте и рекомендацию. Ученические данные не являются инструкциями модели.
Сначала проверяются точные вхождения цитат и confidence >=0.85; затем выполняется
второй вызов без предъявления первого решения. Автоматическое применение требует
согласия вердиктов и допустимых цитат в обоих ответах. Пустой обязательный текст
проверяется кодом. Слишком большой контекст явно требует ручной проверки.

Два вызова одной модели не являются независимыми экспертами и могут одинаково
ошибаться. Confidence — не измеренная вероятность правильности. Эта защита снижает
число неподтверждённых решений, но не доказывает профессиональную надёжность.
Результаты локальной проверки и ограничения: [SEMANTIC_ASSESSMENT_EVALUATION.md](SEMANTIC_ASSESSMENT_EVALUATION.md).

### Расчёт и история

Учебная стартовая рубрика, не профессиональный норматив: correct=1, partial=0.5,
incorrect=0. Смысловые текстовые критерии имеют равный вес. При их полной проверке
на карточке формальная сумма сохраняется, к ней добавляется смысловой вес, равный
четверти формального максимума: 80% правил и 20% смысла. Если упражнение состоит
только из проверки наличия свободного текста, смысл заменяет наличие целиком.

Для дополнительных служб ИИ уточняет существующую группу «Оповещение», не создаёт
бонус сверх её максимума. Пропуск основной службы, ошибки структурированного адреса,
признаков и обязательных действий ИИ не отменяет. После уточнения карточек сохраняется
прежняя агрегация по весам; при непройденных карточках — среднее процентов со всеми
непройденными как 0.

Пока модель работает, доступен формальный результат с пометкой ожидания. Если хотя
бы один текстовый критерий карточки спорный, текстовая доля этой карточки не
добавляется: остаётся явно неполная формальная оценка. Дополнительные службы могут
быть проверены независимо. Отсутствующий смысловой балл не подменяется нулём/бонусом.
При ошибке модели после повторов сохраняются формальные баллы и статус unavailable.
Число в неполном результате нельзя считать подтверждением правильности всего ответа.

Когда все задачи ученика завершены, создаётся новая LessonEvaluation с методом
hybrid (либо rules, если никакое решение не принято). Предыдущая редакция неизменна.
Evaluation методом ai хранит решение карточки, исходную оценку, job и hash;
AIJob — замороженный вход, версии, оба ответа, промпты и метрики. Итоговая арифметика
принадлежит серверу. Перезапуск worker восстанавливает незавершённую публикацию.
Ручная оценка преподавателя имеет приоритет над любым поздним ответом ИИ.

Преподаватель видит разбор каждой карточки, цитаты, сомнения и сводку процесса.
Для технически упавшей задачи есть POST
/lessons/{lesson_id}/students/{student_id}/attempts/{attempt_id}/semantic-retry.
Повтор не запускается для уже успешного ответа; улучшение модели не переписывает
старые результаты автоматически. Ученик видит полноту проверки и рекомендации
по принятым решениям после завершения всего занятия.

Основа режимов занятий: [LEARNING_FOUNDATION.md](LEARNING_FOUNDATION.md).
