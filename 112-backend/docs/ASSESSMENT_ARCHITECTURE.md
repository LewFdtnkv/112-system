# Как выставляется оценка

Оценка обычно формируется автоматически. Сначала сервер проверяет правила, затем ИИ разбирает смысл ответов в фоне. Преподаватель может пересмотреть итог; его решение имеет приоритет над поздним ответом модели.

## Последовательность

1. При сдаче сохраняются ответ, действия и формальная оценка карточки.
2. В той же транзакции создаётся задача смысловой проверки с неизменяемым контекстом.
3. Воркер проверяет критерии, подтверждает допустимые выводы и публикует новую редакцию результата.
4. Ученик видит баллы и комментарии к каждой карточке после завершения своей работы. Остальных учеников ждать не нужно.

Просмотр результата не запускает оценивание заново. Старые ответы, версии правил и заключения сохраняются.

## Что проверяет код, а что — ИИ

| Область | Проверка |
| --- | --- |
| Тип, признаки, отметки, заявитель, компоненты адреса | Сопоставление полей с эталоном; ограниченный смысловой пересмотр ИИ для новых попыток |
| Свободное описание и адрес | Согласованность с условием, пропуски и противоречия |
| Дополнительные службы | Обоснованность в рамках компетенций; без отмены пропуска обязательного получателя |
| ДДС | Код проверяет действия, этапы, звонки и нормативы; ИИ — смысл комментариев |
| Подготовленная часть навыкового упражнения | Исключается из оценки работы ученика |

Ноль и `false` являются значениями, а не отсутствием ответа. Только непустой текст ещё не доказывает правильность решения. Прокторинг не передаётся в смысловую проверку. [Точные сравнения полей](AUTOMATIC_CHECK.md) · [Процесс ДДС](QA4_WORKFLOW.md).

## Баллы

Формальная рубрика задаёт относительные веса групп. Внутри группы учитывается доля выполненных критериев; число отдельных адресных полей не увеличивает вес всей группы. Настройки сохраняются в версии сценария и снимке попытки.

Для полностью проверенного текста в новых попытках смысловая часть обычно составляет 25%, формальная — 75%. Старые снимки без этой настройки сохраняют прежние 20%. Если упражнение проверяет только свободный текст, смысловая оценка заменяет простую проверку его наличия.

Для текста используются доли: верно — 1, частично — 0,5, неверно — 0. Дополнительные службы уточняют существующую группу оповещения, а не создают бонус сверх её максимума.

Полностью выполненные карточки агрегируются по доступным весам. При завершении занятия с непройденными карточками итог учитывает их как ноль. Округление выполняет сервер; фронтенд не пересчитывает оценку самостоятельно.

## Ограниченный пересмотр полей ИИ

В новых попытках действует `semantic-v4-rule-review` с политикой `rule-review-v1`. Модель видит условие и ответ одного поля без эталона и исходного балла. Она может предложить оставить результат, повысить или понизить его.

Размер изменения задаёт сервер: **25% веса конкретного поля**, в пределах от нуля до полного балла за поле. Это не 25 пунктов итоговой оценки. Пустой ответ не получает баллы за сведения, которых ученик не вводил.

Для изменения нужны два согласованных вердикта, уверенность не ниже 0,85 и проверяемые цитаты. Если изменение не предложено, второй вызов для этого поля не нужен. Действия, сроки, звонки и статусы ДДС таким пересмотром не меняются.

## Защита от ошибочного вывода

Каждый смысловой критерий проверяется отдельно по сохранённым фактам и примерам. Ученический текст считается данными, а не инструкциями модели. Сервер проверяет формат ответа, цитаты, уверенность и согласие подтверждающей проверки перед применением изменения.

При спорном текстовом критерии смысловая доля не добавляется как достоверная: сохраняется формальный результат с отметкой о неполной проверке. При техническом отказе после ограниченных повторов остаются формальные баллы. Сбой модели не является ошибкой ученика.

Два вызова одной модели могут одинаково ошибаться. Уверенность модели не является измеренной вероятностью правильности. [Локальные эксперименты](assessment-evaluation/rule-review/README.md) показывают результат на конкретной выборке, а не гарантируют качество всех оценок.

## Преподаватель и память ИИ

Пересмотр итогового балла создаёт отдельную редакцию с комментарием. Автоматическая публикация её не перезаписывает.

Для будущих проверок преподаватель отдельно сохраняет исправление конкретного критерия или создаёт разбор в памяти ИИ. RAG подбирает подходящие примеры в новые запросы; модель не переобучается и прежние оценки не меняются. [Как работать с памятью](AI_GUIDE.md) · [Контракт и отбор примеров](ASSESSMENT_MEMORY.md).

## Технические точки входа

- `services/automatic_assessment/` — формальная проверка и итог занятия.
- `services/semantic_assessment/` — промпты, подтверждение, поправки и публикация.
- `services/assessment_memory/` — примеры RAG.
- `AIJob` хранит вход, версии, ответы и диагностику; `Evaluation` — результат карточки, `LessonEvaluation` — редакции итога занятия.
- `SEMANTIC_ASSESSMENT_ENABLED`, `ASSESSMENT_MODEL`, `LLM_TIMEOUT_SECONDS` управляют включением и вызовом модели; остальные настройки — в `.env.example` и `app/core/config.py`.

HTTP не ждёт модель. На CPU проверка многих полей может занять несколько минут. Повтор технически неуспешной задачи не должен переоценивать уже успешную работу или менять её сохранённую методику.
