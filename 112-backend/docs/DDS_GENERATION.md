# Отдельная генерация упражнения ДДС

В библиотеке открыть сохранённую карточку → «Оператор ДДС — работа бригад» →
«Сгенерировать упражнение ДДС». Можно использовать ручную карточку или результат
обычной генерации. Запуск ДДС отдельный, автоматической цепочки после генерации 112 нет:
преподаватель сначала проверяет входящую карточку.

## Параметры

- Опубликованный профиль службы, входящей в получателей карточки.
- Одна случайная действующая бригада или одна/две выбранные вручную.
- Начальное состояние: случайное, ещё не назначена, назначена, выехала, прибыла,
  выполняет работы. История до состояния строится алгоритмом.
- Учебная цель: случайная либо конкретный следующий достижимый статус, включая отмену.
  Уже выполненная цель не допускается. Для каждой бригады случайный выбор независим.
- Требовать звонок при новом назначении: нужен контакт руководителя своей службы.
- При наличии упражнения — явное подтверждение его замены после успешной проверки.

Все структурные факты фиксируются **до очереди**. ИИ пишет только комментарии исходной
истории и сообщения по оставшимся переходам. Промпт не предлагает сочинять новых
пострадавших, причины отмены, времена, адреса или результаты спасения. Все сообщения
доступны в нижней панели при открытии: это не планировщик будущих радиообменов.
Начальное краткое условие ДДС собирает сервер по наличию исходной истории.

## Две задачи и сохранение

`AIJob.purpose=dds_generation` использует существующий worker, heartbeat и lease.
`target_card_id` ссылается на готовую карточку; `parent_job_id` — на задачу её генерации,
если она была. Уникальный `card_template_id` обычной генерации не переиспользуется.
Администратор видит новый тип в общей таблице, преподаватель — состояние в библиотеке
и в просмотре карточки. API: POST/GET `/cards/{card_id}/dds-generations`.

Критик сверяет каждый ключ, статус, полноту и отсутствие новых фактов. До двух вариантов
за запуск; если оба не прошли — задача неуспешна, **без шаблонной подмены ДДС**.
Исходная карточка и существующее упражнение остаются прежними. Для нового запуска
открыть карточку; повтор по устаревшему снимку не предусмотрен. Диагностика обеих
попыток сохраняется в деталях задачи администратора.

Сохранение атомарно: активный владелец-преподаватель, актуальная редакция, карточка
ещё не используется в сценариях, действующий профиль, неотозванные RAG-образцы.
История уже назначенных занятий никогда не меняется. Миграция `0032_dds_generation`.

## RAG

Отдельный подбор образцов ДДС: базовые авторские короткие примеры по виду записи и
статусу; подтверждённые владельцем карточки из PostgreSQL с тем же типом происшествия,
профилем и признаками. История сопоставляется по статусу, новые сообщения — только
при совпадении плана переходов. Приоритет у преподавательских образцов, до 10 фрагментов.
Выбор и редакции записываются в результат. Флаг «Использовать как пример генерации»
теперь разрешён также для карточки только с ДДС; редактирование снимает подтверждение.

Здесь RAG использует точные фильтры и совпадение слов, **не векторное ранжирование**:
для небольшого набора фиксированных переходов точные ограничения важнее близости
формулировок. Уже имеющийся pgvector оценивания не меняется. Базовые примеры —
учебные авторские заготовки, не подтверждённая заказчиком методическая база.

## Что нужно для максимального балла

Ученик работает только со своей службой. Нужно назначить указанные новые бригады,
по сообщениям внести статусы по допустимому порядку до учебной цели, не назначать
лишние бригады; если включено требование — самому позвонить руководителю каждой
новой бригады и получить подтверждение. Исходная история предыдущей смены не даёт
баллов и не требует повторного звонка. «Новое сообщение» — информация для действия,
а не автоматически выполненный статус.

При учебном звонке сейчас проверяется голосовая активность и завершение диалога
с подтверждением «Принято», а не содержание речи. Комментарий необязателен;
отсутствие не штрафуется. Если ученик его написал, ИИ проверяет согласованность;
принятая смысловая проверка составляет 25% комбинированной оценки в новых проверках (старые сохраняют 20%). Точные статусы,
назначения и звонки проверяются правилами. В занятии на отдельные навыки берутся
только соответствующие критерии. Норматив реакции 30 секунд показывается как
диагностика, без отдельного штрафа. Непройденные карточки при завершении занятия — 0.

## Ограничения

Генерация не оценивает достаточность реальных сил и средств и не заменяет методическую
проверку преподавателя. Маленький критик может ошибочно отвергать корректные сообщения.
Приоритет — не публиковать сомнительный текст, сохраняя базовую карточку. Встроенные
примеры намеренно краткие: это подготовка согласованных сообщений, а не обещание
разнообразного радиообмена. В этой версии нет автоматической генерации целого сценария.

## Проверка реализации

Полный обязательный pre-commit backend прошёл на отдельной PostgreSQL (481 тест).
Frontend: production build, lint/FSD, 149 Vitest и 6 уникальных Playwright-сценариев;
после последней правки таблицы оба новых браузерных сценария повторно прошли.
Широкий и мобильный варианты лично просмотрены, снимки в frontend
`docs/screenshots/dds-generation`. Браузерные проверки используют API-фикстуры;
очередь, права, RAG и атомарная публикация проверены интеграционно на PostgreSQL,
реальная модель — отдельно: [отчёт](dds-generation/REVIEW.md).

Первоначальные полные проверки выявили неподготовленный mock нового вида задач,
неперехваченные запросы аудита в тесте страницы и нестабильные проверки сроков
авторизации/lease. Mock обновлён, API аудита явно имитируется тестом;
production-правила авторизации и аудита не ослаблялись. Финальный набор прошёл.

Локальные API/worker/telephony-worker/frontend обновлены, readiness и frontend HTTP200;
OpenAPI содержит новый маршрут и purpose. Рабочая БД не очищалась, seed не запускался.
