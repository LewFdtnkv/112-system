# Аккаунты и взаимоисключающие роли

Аккаунт имеет одну системную роль: `student`, `teacher` или `admin`.
Учебные роли оператора 112 / ДДС назначаются сценарием и не являются правами аккаунта.
Администратор не получает права преподавателя.

`POST /api/v1/users` принимает `role` (по умолчанию ученик), логин, стартовый пароль,
ФИО и необязательный email. Старые `is_admin` / `is_teacher` принимаются для
совместимости, но два `true` или противоречие с `role` возвращают `422`.
В БД флаги сохранены ради совместимости; миграция `0007_exclusive_user_role`
добавляет `CHECK NOT (is_teacher AND is_admin)`. Существующие смешанные аккаунты
нужно разобрать явно до миграции: она не выбирает роль вместо администратора.

`GET /users/{id}` и `/users/me` возвращают роль и профиль без пароля/хеша:
ФИО, email, активность, необходимость смены пароля, даты создания, изменения,
последнего успешного входа и смены пароля. `/views/users` содержит `last_login_at`
для отображения списка без запроса к каждой записи.

Только администратор может вызвать `PATCH /users/{id}`. Поддерживаются `first_name`,
`last_name`, `middle_name`, `email`, `is_active`. Пропущенное поле сохраняется;
`null` очищает только отчество и email. Логин, системные даты и хеш не редактируются.

Роль задаётся только при создании и не изменяется. Для другой роли нужно создать
отдельного пользователя. Передача `role`, `is_teacher` или `is_admin` в PATCH
отклоняется с `422`, даже если значение совпадает с текущим.

Изменение активности отзывает все сеансы в той же транзакции. Отключённый
аккаунт не входит и не обновляет токены; повторное включение не восстанавливает
прежние токены. Самоотключение и отключение последнего
активного администратора запрещены (`409`). Административные изменения сериализуются
между API-процессами, а блокировка пользователя согласована с login/refresh.

Отключение сохраняет карточки, уроки, оценки и принадлежность к группам.
При запуске урока API по-прежнему требует активных ученических аккаунтов.
