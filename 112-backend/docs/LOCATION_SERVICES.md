# Адресный поиск и перевод

Три защищённых POST-маршрута поддерживают новую карту и перевод сообщения
заявителя во frontend. Доступны авторизованным активным пользователям после
обязательной смены стартового пароля. Миграция БД не требуется.

| Маршрут `/api/v1` | Запрос | Ответ |
| --- | --- | --- |
| `/addresses/suggest` | `query` (1–300 символов), `count` (1–20, по умолчанию 5) | `items`: адреса с координатами и отдельными полями |
| `/addresses/reverse` | `latitude` (−90…90), `longitude` (−180…180), `count` (по умолчанию 1) | Такой же `items` |
| `/translations/translate` | `text` (1–5000 символов), `target_language_code: "ru"` | `text`, `detected_language_code` |

Пустые строки, дополнительные поля, недопустимые координаты и размеры запросов
дают 422. Нет ключа, ошибка провайдера, таймаут или повреждённый ответ — 503
с постоянным сообщением; содержимое ответа провайдера и реквизиты не раскрываются.
Пустой результат поиска возвращается как `items: []`. Подсказки без пригодных
координат пропускаются: frontend требует точку, координаты не выдумываются.

Пример элемента `items`:

```json
{
  "point": { "latitude": 55.75, "longitude": 37.61 },
  "addressLine": "г Москва, ул Тверская, д 1",
  "country": "Россия",
  "administrativeAreas": ["г Москва"],
  "localities": ["Москва"],
  "district": "Центральный",
  "area": "Тверской",
  "street": "ул Тверская",
  "house": "1",
  "building": "",
  "structure": "",
  "apartment": ""
}
```

`city_area` DaData соответствует округу, `city_district` — району;
для адресов за пределами города используется `area_with_type`. `block` с типом
`стр`/`соор` попадает в `structure`, остальные варианты — в `building`.
Результат обратного геокодирования — ближайший известный адрес, а не доказательство
точного совпадения. Оператор проверяет его перед применением.

## Настройка

В локальном `112-backend/.env` или окружении Compose:

```dotenv
DADATA_API_KEY=
YANDEX_TRANSLATE_API_KEY=
EXTERNAL_SERVICES_TIMEOUT_SECONDS=8
VITE_YANDEX_MAPS_API_KEY=
```

- `DADATA_API_KEY` — ключ подсказок DaData. И поиск, и обратное геокодирование
  используют официальный Suggestions API; секретный ключ стандартизации не нужен.
- `YANDEX_TRANSLATE_API_KEY` — API-ключ сервисного аккаунта Yandex Cloud с правом
  перевода (область `yc.ai.translate.execute` и соответствующая роль сервисного аккаунта).
  Реализована авторизация `Api-Key`; IAM-токен и старый API Переводчика сюда не подходят.
- `VITE_YANDEX_MAPS_API_KEY` — отдельный публичный ключ JavaScript API Карт 2.1,
  ограниченный доменами frontend. Compose передаёт его Nginx, entrypoint пишет
  runtime `map-config.js`. Ключи DaData/Translate передаются только сервису API.

Применить настройки из каталога backend: `docker compose up -d --build api frontend`.
API и frontend должны обновляться вместе. Рабочие ключи не коммитить.
Переменная из `112-frontend/.env` сама по себе в Compose не передаётся; для Vite dev
её нужно передать в процесс Vite внутри Docker.

Вызовы идут по фиксированным HTTPS-адресам, без перенаправлений и автоматических
повторов. Предельное ожидание — 8 секунд по умолчанию (настраивается от 1 до 30).
Сами запросы адреса/перевода не изменяют карточки и не сохраняют исходные тексты;
результат попадает в обычный черновик только после подтверждения пользователя.
Обычный журнал HTTP не записывает тела запросов или ключи.

## Проверки и ограничения

Контракт и авторизация проверяются в `tests/test_location_services.py` через
ASGI и отдельную PostgreSQL; внешний HTTP имитируется `httpx.MockTransport`.
Проверены формат полей, координаты, перевод, ошибки ключей/лимитов/сети,
отсутствие исходящих запросов для невалидного ввода и запрещённых сеансов.
Это не проверка реальных ключей или качества перевода. Живые обращения к платным
провайдерам при интеграции не выполнялись.

Первичные контракты:
[подсказки DaData](https://dadata.ru/api/suggest/address/),
[обратное геокодирование DaData](https://dadata.ru/api/geolocate/),
[Yandex Translate v2](https://aistudio.yandex.ru/ru/docs/translate/api-ref/Translation/translate),
[авторизация API-ключом](https://yandex.cloud/ru/docs/iam/concepts/authorization/api-key).
