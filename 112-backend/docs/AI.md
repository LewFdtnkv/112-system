# ИИ, память и рекомендации

ИИ генерирует условия, проверяет смысл ответов и готовит рекомендации. Запрос пользователя ставит задачу в PostgreSQL, а воркер выполняет её в фоне. HTTP не ждёт модель.

## Модели и ресурсы

По умолчанию используется `qwen3:4b-instruct-2507-q4_K_M`, для эмбеддингов — `qwen3-embedding:0.6b`. Модели загружаются один раз:

```sh
docker compose exec llm ollama pull qwen3:4b-instruct-2507-q4_K_M
docker compose exec llm ollama pull qwen3-embedding:0.6b
```

Имена и параметры задаются в `.env.example`. `LLM_THREADS` должен соответствовать выделенному CPU; лишние потоки могут замедлить ответ. На CPU сложная проверка занимает минуты. Увеличение модели требует отдельно проверить память, задержки и качество.

## Память ИИ (RAG)

RAG добавляет в запрос подходящие примеры. Это не обучение весов модели. PostgreSQL хранит текст, автора, версию и вектор pgvector; модель эмбеддингов формирует 1024-мерные представления.

Примеры отбираются по роли, критерию, версии и смысловой близости. Общие примеры доступны всем, личные — своему преподавателю. Отключённые исключаются. Сходство не является вероятностью правильности. Снимок выбранных примеров сохраняется с задачей для воспроизводимости.

В «Память ИИ» доступны два раздела:

| Раздел | Что хранится |
| --- | --- |
| Оценивание | Критерий, факты, ответ, вердикт и короткое объяснение |
| Генерация | Собственные карточки, разрешённые как примеры хорошего условия |

Преподаватель может создать разбор вручную, сохранить исправление вывода ИИ, отключить или удалить пример. Пересмотр общего балла сам по себе не создаёт исправления каждого критерия. Новые примеры используются в будущих задачах и не пересчитывают старые результаты. Карточка с разрешением генерации не обязательно попадёт в каждый запрос: действуют фильтры совместимости.

Изменение модели эмбеддингов требует переиндексации. Векторы разных моделей и версий не смешиваются. Необходимые команды наполнения и индексации доступны в `scripts/seed_assessment_memory.py --help`.

## Рекомендации и направления

Индивидуальные рекомендации используют подтверждённые ошибки, навыки и историю результатов. Это советы по дальнейшему обучению после занятия. Подсказки во время решения управляются отдельным учебным процессом.

При подходящей практике сообщение содержит направление на один календарный месяц. По нему ученик создаёт одно личное занятие; повторный запрос возвращает тот же результат. Срок ограничивает создание, а не дальнейшее прохождение. Занятие создаётся без личного лимита; его таймер не запускается нажатием кнопки создания.

Подбираются доступные опубликованные сценарии из ранее оценённых занятий ученика с проверкой преподавателя, группы и актуальности материалов. Будущие контрольные ответы не раскрываются. Если подходящего варианта нет, предлагается обратиться к преподавателю.

Для старых сообщений есть `scripts/backfill_learning_referrals.py`: по умолчанию пробный запуск с откатом, `--apply` сохраняет направления без новой генерации и продления срока.

Групповой разбор доступен преподавателю по его группе. Модель получает агрегаты навыков и выбирает методические рекомендации. Пересмотренные общим баллом работы выделяются отдельно: из одного числа нельзя достоверно восстановить покарточные ошибки. Устаревший разбор помечается после изменения исходных результатов.

## Очередь и диагностика

Общий воркер обслуживает пять назначений задач: генерацию карточки, дополнение ДДС, оценивание, индивидуальные и групповые рекомендации. PostgreSQL `SKIP LOCKED`, ограниченный срок захвата и проверка его токена защищают от двойной публикации. Сетевые обращения выполняются без удержания транзакции.

Администратор видит очередь, активные и завершённые задачи, фильтры и подробности с копированием JSON. История отказов содержит этап, тип ошибки и длительность. Промежуточные подтверждённые критерии оценивания могут использоваться при повторе только при совпадении входа, модели, промпта и памяти.

Неизвестное назначение задачи не перенаправляется в генератор. Тайм-аут, спорный ответ и ошибка ученика — разные состояния. [Оценивание](ASSESSMENT_ARCHITECTURE.md) и [генерация](GENERATION.md) определяют свои резервные варианты.
