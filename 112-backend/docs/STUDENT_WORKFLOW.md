# Выполнение урока оператором 112

Префикс всех путей — `/api/v1`. Администратор создаёт преподавателя и ученика;
оба меняют стартовые пароли. Преподаватель создаёт группу, добавляет ученика,
готовит карточки и сценарий `operator_112`, запускает `/lessons/start` с `student_id`.
Контракт подготовки: [TEACHER_API.md](TEACHER_API.md).

Ученик использует только свои назначения. Учебная роль фиксируется сценарием,
системные права преподавателя/администратора не предоставляют доступ к ученическим ручкам.

| Ручка | Результат |
| --- | --- |
| `GET /student/lessons` | Свои уроки, состояние выполнения и порядок назначений |
| `GET /student/lessons/{id}` | Один урок: `work_status`, назначения с `available` и `attempt_id` |
| `POST /student/assignments/{id}/start` | Создаёт попытку и пустую рабочую карточку; повтор возвращает прежнюю попытку |
| `GET /student/attempts/{id}` | Текст заявителя, инструкции, своя карточка, времена и оповещённые службы |
| `GET /student/attempts/{id}/classifier-entries` | Коды закреплённой версии ЕКП; `limit`, `offset` |
| `PUT /student/attempts/{id}/card` | Сохраняет черновик целиком с проверкой `revision` |
| `GET /student/attempts/{id}/recipients` | Рассчитанные получатели по выбранному учеником коду |
| `POST /student/attempts/{id}/submit` | «Оповестить и сохранить»: завершает карточку и попытку |

Начать можно только первое незавершённое назначение. Следующая карточка открывается после
предыдущей. На этом этапе поддерживается одна попытка на назначение, без пересдач.
Старт возвращает `201`, повтор — `200`; попытки стартовать следующую карточку раньше — `409`.
`incident_cards` принадлежит попытке ученика; шаблон и снимок сценария не меняются.
Скрытый образец, ожидаемый код и ожидаемые получатели из снимка ученику не передаются.

Черновик сохраняется так:

```json
{
  "revision": 1,
  "classifier_entry_id": "<UUID кода выбранной версии ЕКП>",
  "data": {
    "caller_name": "Учебный заявитель",
    "address_text": "Учебная улица, 1",
    "description": "Сообщение, записанное учеником",
    "features": {"has_victims": false}
  }
}
```

`PUT` заменяет поля черновика: отсутствующие необязательные поля очищаются. Для неполного
черновика адрес, описание и код могут отсутствовать. Ответ содержит актуальную `card.revision`;
при устаревшей ревизии сервер возвращает `409` без перезаписи чужого сохранения.

Для завершения передать `{"revision": <актуальная ревизия>}` в `/submit`.
Обязательны адрес, описание и код этой версии ЕКП. Правильность выбранного кода и содержания
оценивает преподаватель. Службы берутся из маршрутов **выбранного учеником кода**;
клиент не может подменить список получателей. Поддерживаются безусловные маршруты.
Условные правила пока возвращают `409`, а не интерпретируются приблизительно.

Завершение одной транзакцией устанавливает `incident_cards.status=notified`,
`saved_at`, `notification_completed_at`, создаёт `service_responses` с временем направления,
завершает попытку и записывает событие. Это учебное оповещение; реальных сетевых отправок
и звонков нет. Статус `notified` не означает завершение работ служб.
Повтор `/submit` не создаёт повторных реагирований или событий.

В `attempt_events` сохраняются старт, сохранения черновика и оповещение, включая серверное
время. Начало попытки и открытия карточки совпадает с ученическим `/start`; сохранение
черновика не останавливает таймер официального заполнения карточки.
Лимит времени хранится и возвращается для отображения, но пока не завершает попытку
автоматически и не выставляет штрафов. Автоматические подсказки также пока не реализованы.

После всех карточек ученика `work_status=submitted`. Когда все назначения всего урока
выполнены, `lessons.status=finished` и фиксируется `ended_at`.
Завершённые работы недоступны для дальнейшего редактирования учеником.

## Проверка и оценка преподавателем

`GET /lessons/{lesson_id}/students/{student_id}/work` доступен владельцу урока.
Ответ содержит исходные снимки карточек, все работы ученика с введёнными данными,
выбранными кодами, оповещёнными службами и временами, а также историю итоговых оценок.
Правильность содержания и выбора кода проверяется человеком; ИИ не вызывается.

Когда ученик завершил все карточки, преподаватель вызывает
`POST /lessons/{lesson_id}/students/{student_id}/evaluations`:

```json
{
  "request_id": "<UUID запроса оценки>",
  "expected_revision": 0,
  "score": 4,
  "max_score": 5,
  "comment": "Сведения переданы; в первой карточке следует уточнить адрес"
}
```

Это **итоговая оценка урока конкретного ученика**, сохраняемая в `lesson_evaluations`.
Шкала задаётся явно; формула среднего по карточкам не вводится. `0 <= score <= max_score`,
максимум положительный, до двух знаков после запятой. Комментарий обязателен.
Отдельная таблица `evaluations` остаётся моделью будущих оценок отдельных попыток.

Первое оценивание использует `expected_revision=0`. Для исправления передаются
актуальная ревизия, новый `request_id` и обоснование в комментарии. Новая строка ссылается
на прежнюю через `supersedes_id`; история не перезаписывается. Устаревшая ревизия — `409`.
Повтор того же запроса возвращает прежнюю запись (`200` вместо `201`), изменённые значения
с тем же ключом — `409`. Оценить незавершённую работу нельзя. В групповом уроке можно
оценить уже закончившего ученика, пока остальные ещё работают.

`GET /student/lessons/{lesson_id}/evaluation` возвращает ученику его актуальную оценку
или `null`, если преподаватель ещё не выставил её. Чужая работа или чужая оценка — `404`.
