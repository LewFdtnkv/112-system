# API прохождения занятия

Все пути ниже имеют префикс `/api/v1` и требуют ученическую сессию. Доступ проверяется по назначению, а не только по роли. Полные тела запросов — в Swagger на `/docs`.

## Начало и время

| Запрос | Назначение |
| --- | --- |
| `GET /student/lessons` | Список своих занятий |
| `GET /student/lessons/{id}` | Занятие и доступность его карточек |
| `POST /student/lessons/{id}/start` | Начать или продолжить личное выполнение |
| `POST /student/lessons/{id}/presence` | Подтвердить присутствие |
| `POST /student/lessons/{id}/leave` | Выйти из занятия |
| `POST /student/assignments/{id}/start` | Открыть попытку карточки; повтор возвращает существующую |
| `GET /student/attempts/{id}` | Получить рабочую карточку и состояние выполнения |

В 112 карточки выполняются последовательно. В ДДС они поступают по расписанию независимо от завершения предыдущих. Сроки и блокировки проверяет сервер. [Время, паузы и автоматическое завершение](LESSON_TIMING.md).

## Оператор 112

`PUT /student/attempts/{id}/card` сохраняет черновик с проверкой ревизии. `PUT` заменяет поля: отсутствие необязательного поля очищает его. При устаревшей ревизии сервер возвращает конфликт и не перезаписывает более свежую работу.

ЕКП закреплён за назначением. Типы доступны через `/classifier-entries`, рекомендации служб — через `/recipients`; `/recipients-preview` рассчитывает их по текущему вводу без сохранения.

Службы можно выбрать вручную: `recipient_service_ids=null` следует рекомендациям, пустой список означает отсутствие оповещения, список ID задаёт выбранных получателей. Сервер оценивает фактическое решение, а не исправляет его автоматически.

`POST /student/attempts/{id}/submit` сохраняет завершение с актуальной ревизией. Ошибки формы возвращаются с путями полей. Неверный учебный ответ и недопустимый формат ввода — разные случаи: допустимую, но неполную работу можно оценить с учётом пропусков.

## Оператор ДДС

`POST /student/attempts/{id}/dds/crews` выполняет команды бригад; `/dds/submit` завершает упражнение. Ученик управляет только бригадами своей службы. Плитка службы остаётся «Добавлена».

В новых упражнениях проверяются оставшиеся этапы реагирования, тексты записей, нужные звонки и нормативы. Старые назначения сохраняют свою методику. Точные переходы и причины отказа — в [процессе QA4](QA4_WORKFLOW.md).

## Помощь, результат и аудит

`POST /student/attempts/{id}/hints` выдаёт помощь в рамках настроек занятия. Шаг определяется выполненными действиями; скрытое эталонное решение не включается в обычное чтение карточки.

После личной сдачи `GET /student/lessons/{id}/feedback` возвращает покарточные разборы. Готовность ИИ отмечается отдельно. Пересмотр преподавателя имеет приоритет. [Оценивание](ASSESSMENT_ARCHITECTURE.md).

Действия и прокторинг записываются раздельно. События видимости вкладки не подменяют доказательства сохранения, оповещения или звонка. [Контракт аудита](ATTEMPT_AUDIT.md).
