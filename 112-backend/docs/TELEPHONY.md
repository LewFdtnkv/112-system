# Учебная телефония

| Режим станции | Подключение |
| --- | --- |
| `browser` | Гарнитура браузера, SIP.js/WebRTC и Asterisk |
| `phone` | Отдельный SIP-аппарат или программный IP-телефон и Asterisk |
| `external` | Внешняя АТС через адаптер событий |

Телефонное место закрепляется за учеником администратором. У одного ученика одно место; во время активного звонка его нельзя переключить или отключить.

## Запуск Asterisk

В `.env` задайте `TELEPHONY_ENABLED=true` и случайный `ARI_PASSWORD` не короче 24 символов (`openssl rand -hex 32`). Остальные параметры и их назначение перечислены в [шаблоне окружения](../.env.example):

```sh
docker compose --profile telephony up -d --build --wait
```

Профиль добавляет `asterisk` и `telephony-worker`. ARI доступен внутри Docker-сети; наружу проксируется только SIP WebSocket `/sip-ws`. Dialplan разрешает учебный номер `9000` после авторизации станции. Транков и выхода в город нет.

API, воркеры и АТС используют том `telephony_media`; Asterisk читает подготовленное аудио. Озвучка во время разговора не запускается. [Записи и TTS](AUDIO.md).

## Браузер с гарнитурой

1. Создайте станцию типа «Asterisk · браузер» и закрепите за учеником.
2. Откройте занятие, подключите телефон и разрешите микрофон.
3. Для звонка руководителю назначьте бригаду и нажмите «Позвонить» у её контакта.

На одном компьютере подходит `http://localhost:8080`. Для удалённого доступа нужен HTTPS с доверенным сертификатом и поддержкой WebSocket Upgrade у `/sip-ws`. `TELEPHONY_WS_URL=/sip-ws` использует схему страницы: `ws` или `wss`. [Готовый пример HTTPS-прокси Nginx](HTTPS.md).

## SIP-телефон

Создайте станцию «Asterisk · телефон». Администратор открывает «Настройки SIP» и копирует логин, пароль и домен в клиент. Виртуальный телефон на компьютере настраивается так же, как аппарат.

Для доступа из локальной сети:

- `SIP_PUBLIC_ADDRESS` — доступный клиенту IPv4-адрес сервера Docker;
- `SIP_BIND_ADDRESS=0.0.0.0` — публикация SIP;
- UDP `5060` и RTP UDP `10000–10100` должны быть доступны;
- `SIP_LOCAL_NET=auto` подходит для обычной схемы с опубликованными портами.

Не объявляйте всю Docker-подсеть локальной без понимания NAT: АТС может вернуть телефону недоступный адрес контейнера. После изменения транспорта пересоздайте Asterisk.

Ученик выбирает контакт в карточке, затем набирает `9000` на телефоне. Регистрация SIP сама по себе не привязывает звонок к нужной бригаде.

## Разговор с руководителем ДДС

У бригады должен быть контакт руководителя в опубликованном профиле. В карточке включается требование звонка при новом назначении. Ученик:

1. Слушает приветствие.
2. После приветствия сообщает сведения и делает паузу.
3. Слышит подтверждение; АТС завершает разговор.

Asterisk TALK_DETECT фиксирует не менее 600 мс входящего звука и паузу 1500 мс. Ожидание речи ограничено 90 секундами. Речь во время приветствия, короткий щелчок, сброс до завершения подтверждения или ошибка воспроизведения не дают зачёт.

Это проверка звуковой активности, а не содержания речи: шум тоже может сработать. Аудио ученика и расшифровка не сохраняются. Успех подтверждает только доверенный воркер. После отмены и нового назначения нужен новый звонок. Предустановленная история бригады не требует повторного оповещения.

## Внешняя АТС

Нужен адаптер конкретной АТС. Backend не может достоверно определить события физического телефона без её интерфейса.

Станция имеет `provider` и стабильный `endpoint`. Адаптер авторизуется заголовком `X-Adapter-Token` со значением `TELEPHONY_ADAPTER_TOKEN` и использует:

| Путь относительно `/api/v1` | Назначение |
| --- | --- |
| `GET /pbx/{provider}/stations/{endpoint}` | Привязка станции, попытка и разрешённые контакты |
| `POST /pbx/{provider}/events` | События набора, соединения и завершения |
| `GET /pbx/{provider}/calls/{call_id}/wav` | Подготовленная реплика |

`event_id` стабилен при повторе, `provider_call_id` объединяет каналы одного разговора. Сохраняйте привязку `attempt_id` в момент начала, чтобы поздний ответ не попал в другое занятие. Полученный `call_id` используется для дальнейших событий. Скачивание WAV не считается его воспроизведением.

Для обязательного голосового подтверждения ДДС внешнего контракта соединения недостаточно. Нужна поддержка детекции речи и подтверждённого воспроизведения в адаптере; пока этот режим для такого упражнения отклоняется.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Первоначальный SIP 401 | Это нормальный Digest challenge; важен ответ на повтор с авторизацией |
| После регистрации вызов отклонён | Выбран ли контакт и открыта ли нужная попытка, работает ли ARI-воркер |
| Соединение есть, звука нет | RTP-порты, NAT, адрес в SDP, готовность записи |
| Нет «Принято» | Уровень микрофона, речь после приветствия, пауза после сообщения |
| Браузер не даёт микрофон | HTTPS/localhost, разрешение браузера и выбранное устройство |

```sh
docker compose logs --tail=100 asterisk telephony-worker
```

Один активный воркер выбирается блокировкой PostgreSQL. После переподключения он сверяет каналы с БД; неопределённый сетевой результат не вызывает повторный звонок автоматически. Техническая ошибка не превращается в успешное упражнение.
