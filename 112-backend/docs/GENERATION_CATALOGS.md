# Заявители и московские адреса для генерации

## Заявители

`app/data/generation_names.json` содержит отдельные списки:

| Часть | Мужские | Женские |
| --- | ---: | ---: |
| Имена | 321 | 80 |
| Фамилии | 250 | 250 |
| Отчества | 132 | 79 |

Источник — [словарь Faker ru_RU](https://github.com/joke2k/faker/blob/975dd2a11d7f083cb028e2f07478ab401b5fde17/faker/providers/person/ru_RU/__init__.py),
лицензия MIT сохранена в `app/data/generation_names.LICENSE.txt`.
В JSON указаны точная версия источника и SHA256 исходного файла.
Из шести буквальных кортежей first/last/middle_names_male/female удалены только
повторы; словари включают и редкие имена. Faker не нужен как зависимость.
Это словари частей имени, не реестр заявителей.

Backend сначала определяет пол (заданный или случайный), затем **независимо**
выбирает имя и фамилию из соответствующих списков. С вероятностью **80%**
добавляет случайное отчество того же пола; иначе получается ФИ.
Вероятность задаёт `PATRONYMIC_PROBABILITY` в `app/services/generation/catalogs.py`.
Пол при случайном выборе равновероятный. Миллионы сочетаний не хранятся заранее.

Анонимное сообщение не получает имени, пола или возраста; режим «только имя»
использует только имя. Явно введённое преподавателем ФИ/ФИО сохраняется без
дополнения отчеством или обрезания. Для своего имени пол указывается отдельно;
если он не задан, backend его не выдумывает и не пытается угадывать по строке.

Возраст и учебный номер телефона по-прежнему определяются существующими
настройками; они не являются частью справочника заявителей. Никакой связи
между вымышленным человеком и реальным адресом в справочниках нет.

## Адреса

`app/data/generation_moscow_addresses.json` — отдельная открытая выборка
**108 уникальных пар на 30 улицах центра Москвы**, не полный адресный реестр.
Источник: © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright).
Этот адресный набор распространяется по
[Open Database License 1.0](https://opendatacommons.org/licenses/odbl/1-0/).
Атрибуция и лицензия отображаются в форме генерации.

Набор получен 24.09.2026 через основной OSM API:
`https://api.openstreetmap.org/api/0.6/map?bbox=37.595,55.751,37.610,55.760`.
Отобраны контуры зданий с `building`, `addr:street` и `addr:housenumber`;
повторные пары удалены. В эту небольшую выборку включены номера без корпусов
и строений, в том числе дробные. Москва указана по области загрузки в центре
города: не у всех объектов есть отдельный тег населённого пункта. Записи содержат
ID исходного OSM way. Пример ссылки на источник конкретного объекта:
`https://www.openstreetmap.org/way/<число из id>`.
Официальной проверки по ГАР/ФИАС не выполнялось.

Улица и дом выбираются совместно, а не комбинируются независимо. При выборе
конкретной улицы случайный дом берётся только из её записей. В форме фильтруются
дома по улице, улицы по населённому пункту; смена родительского поля очищает
зависимые значения. Если частично заданный адрес отсутствует в справочнике,
API предлагает заполнить его вручную полностью или выбрать описательный формат,
а не придумывает дом. Полностью введённый адрес сохраняется как преподавательский,
без утверждения о проверке по OSM.

Описательный адрес берёт известную улицу, но не добавляет скрытый номер дома.
Ориентиры остаются учебными; наличие парка, магазина или происшествия по реальному
адресу не утверждается. Для служебных ситуаций без места адрес не создаётся.

## Хранение и изменение

Оба JSON входят в образ backend и доступны без сети, ключей, миграции и повторного
seed. Загрузка кэшируется на процесс; после изменения файла пересоберите и
перезапустите API/worker. Адресные варианты и вероятность отчества API `/card-generations/options`
берёт из backend; все словари имён в браузер не передаются.

Конкретное собранное имя, факты и ID выбранного адреса сохраняются в задаче **до** обработки
воркером; повтор задачи не меняет их. ФИО/адрес попадают в эталон и сообщение
программно, слабая LLM их не сочиняет и не переписывает. Существующие карточки
и уже поставленные задачи не изменяются. Промпт выбора формулировок не менялся.

Проверки: распределение имён/пола, ФИ без отчества, анонимность, заданные значения,
невозможность случайного смешения улиц/домов, собственные и описательные адреса,
цикл API → очередь → публикация карточки. Браузер дополнительно проверяет
сохранение своих имени/пола и зависимые варианты домов.
