# Проверка генерации и оценивания — 26.09.2026

Все вызовы выполнены локальной Qwen3 4B Instruct-2507 Q4_K_M через Ollama 0.34.2.
Рабочая БД читалась только для получения замороженных входов. Скрипт не захватывает
задачи, не публикует карточки и не меняет оценки. Старые тексты остаются в библиотеке.

## Подход

1. Повтор всех шести генераций с исходными фактами и seed, но текущим генератором.
2. Ручное чтение сообщений, а не только подсчёт `assisted`.
3. Повтор всех шести отказавших оцениваний со старым замороженным RAG-контекстом.
4. Контрольные примеры: допустимые короткие/ранние комментарии ДДС, неизвестное число,
   известный номер наряда, оправданная дополнительная служба; разные каналы и адреса генератора.

Исторические шесть оцениваний сохранили только общую ошибку. Ни таймаут, ни найденный
ниже OOM нельзя задним числом объявить доказанной причиной каждого из них.

## Что обнаружилось при испытаниях

- Первый вариант нового генератора подготовил все шесть сообщений без fallback.
  Консультация перестала добавлять адрес, возраст заявителя остался у заявителя,
  исчезли «У меня зовут» и «Я паникую». Критик один раз ошибочно пропустил в списке
  сохранённых фактов представление заявителя; повтор прошёл.
- При ручном чтении медицинского сообщения обнаружилась замена «не приходит в себя»
  на «не встаёт». Это разные признаки; критик пропустил подмену. Добавлена узкая
  проверка и явные сведения о сознании/дыхании в контексте писателя и критика.
- Даже при двух потоках длинная серия оцениваний исчерпала 4 GiB контейнера.
  Docker events подтвердил OOM. Перед падением движок сохранял очередной снимок
  промпта объёмом около 303 MiB; память росла до 3,96 GiB. Последующие мгновенные
  отказы — потеря соединения с перезапускающейся Ollama, не плохое решение ученика.
- У установленного llama-server кэш старых промптов по умолчанию имеет лимит 8192 MiB.
  `LLAMA_ARG_CACHE_RAM=0` отключает только этот дополнительный кэш. Логи подтвердили
  `prompt cache is disabled`, два потока и сохранение KV-контекста 4096 токенов.
  Лимит контейнера 4 GiB и память Docker Desktop не увеличивались.
- В рекомендации по описанию модель потребовала «точного воспроизведения» сообщения,
  хотя парафразы разрешены. Защита заменяет такой совет подготовленным текстом о
  сохранении смысла своими словами, сохраняя оригинал модели в диагностике.

## Ограничения

Известные ошибочные примеры использованы для настройки, поэтому это регрессии,
а не независимое измерение точности. В частности, пример «432» явно включён в промпт;
для дополнительного контроля используется другое число и допустимые ответы.
Нет утверждённой экспертной разметки заказчика. Небольшой прогон не доказывает
пригодность автономного оценивания для аттестации. Проверка преподавателем и
консервативное `uncertain` остаются необходимыми.

Свободный текст всё ещё может быть сухим или перечислительным. Узкие проверки
известных ошибок не заменяют общего понимания смысла и русского языка.

## Воспроизведение

`python -m scripts.replay_ai_jobs --purpose generation --output ./generation.json`
и аналогично `--purpose evaluation`. Необязательный повторяемый `--id` ограничивает
список задач. Отчёт содержит входные учебные данные, поэтому требует той же защиты,
что подробности ИИ-задач. Запускать внутри Docker с настроенным подключением к стенду.

## Дополнительные находки на контрольных сообщениях

- Анонимная СМС-консультация совпала с исходной фразой, но критик дважды объявил
  её неподтверждённой. Для неизменённого служебного сообщения теперь используется
  точное сравнение с подготовленным источником, `review_source=exact-source`.
  Это не решение модели-критика. Любое добавление или изменение смысла требует
  обычной проверки; при публикации совпадение проверяется повторно.
- Имя «Екатерина» без явно заданного пола получило «ошибся номером». Источник
  уже был мужского рода, так что критик не увидел расхождения. Теперь если пол
  неизвестен используются нейтральные фразы («это ошибка набора», «после падения мне больно»),
  а пол не угадывается и не заполняется автоматически по имени.
- В звонке о падении модель дважды пропустила сведения о доступности места и
  отсутствии отказа от скорой. Проверка правильно выбрала безопасную заготовку.
  Теперь эти отрицательные отметки для звонка находятся в отдельном блоке уточнений,
  как возраст и остальные дополнительные признаки. СМС сохраняют их в самом сообщении.
  Обратная связь при повторе перечисляет пропущенные факты, а не только их индексы.

Эти изменения не меняют промпты шести основных повторов: равенство промптов проверено
программно, все шесть сохранённых сообщений повторно прошли финальную проверку публикации.

## Проверка качества объяснений и допустимых альтернатив

Пять дополнительных случаев (`assessment-controls-initial.json`): «Принято» при
назначении, «Выезжаем» при выезде, известный наряд УЧ-101, неизвестное число 98765,
дополнительная скорая при ожоге. Все пять вердиктов совпали с ожидаемыми,
74,84–85,30 с на критерий, по две проверки. Это близкие к обучающим примеры, не
независимый экзамен модели. Дополнительная скорая при ожоге также есть в few-shot.

**Оставшийся дефект:** для 98765 модель правильно отклонила комментарий, но написала,
что в условии нет номера наряда вообще. На самом деле УЧ-101 в условии есть;
необъяснено именно 98765. В другом случае модель правильно засчитала УЧ-101.
Этот дефект объяснения сохранён в отчёте, а не исправлен вручную ради статистики.
Также в объяснениях ещё встречаются технические слова вроде `service_scope`.

Отдельный реальный повтор `advice-guard-final.json` занял 96,83 с: бессодержательное
описание отклонено; совет дословного переписывания заменён рекомендацией сохранять
смысл своими словами. Первоначальный совет модели доступен в диагностике.

## Финальная генерация

Шесть исторических входов повторены после исправления медицинского состояния:
6/6 сообщений приняты с первой попытки без резервной генерации, 46,17–53,78 с.
Результаты прочитаны вручную. Подмена возраста и потеря сознания не повторились;
консультация без адреса не получила выдуманный адрес. Однако СМС о конфликте и
пожаре остаются достаточно формальными, не все сообщения звучат как живая речь.
Согласованность стала лучше на проверенных случаях; считать естественность решённой
задачей нельзя.

Исходные и окончательные JSON сохранены рядом. `generation-controls-initial.json`
содержит первые четыре дополнительных проверки, в том числе две безопасные
резервные генерации и ошибку грамматического рода. Пятый вход добавлен только в
финальную серию и проверяет падение заявителя по имени Саша без указанного пола.

Финальная дополнительная серия (`generation-controls-final.json`): 5/5 с первой
попытки, без fallback, 29,58–62,86 с. Проверены консультация без имени/адреса,
ошибочный набор с именем Екатерина и неизвестным полом, падение Марии 72 лет,
СМС с описательным адресом и падение Саши с неизвестным полом. Все тексты прочитаны:
переноса возраста на другого человека, выдуманного дома, неверного согласования
рода и потери выбранных отметок в этой серии не обнаружено. У консультации
`review_source=exact-source`: её проверило точное сравнение кода с источником;
остальные четыре сообщения прошли модель-критик. Это различие важно при чтении 5/5.

Итого в финальных сериях: 11 генераций без резервного текста, 6 исторических
оцениваний без технического отказа, 5 дополнительных оценочных случаев и один
повтор защиты рекомендации. Модель не увеличивалась. Это улучшение устойчивости
и известных ошибок, а не доказательство отсутствия новых противоречий.

## Проверка реализации

Полный backend-набор: 459 тестов на отдельной PostgreSQL, включая повтор по lease,
контрольные точки частичного оценивания, границы фактов и повторную проверку текста
при публикации. Проверены lint, форматирование и Compose build API/worker. Схема БД
не менялась, миграции и seed не нужны. На стенде перед обновлением по-прежнему шесть
успешных генераций и шесть исторически отказавших оцениваний, активных задач нет.
Их статусы экспериментами не менялись; для пересчёта нужен обычный явный повтор задачи.

После серии модель занимала 3,44 GiB из 4 GiB, счётчик перезапусков контейнера — 0.
Это измерение данной нагрузки, не гарантия расхода памяти для любой модели/контекста.
