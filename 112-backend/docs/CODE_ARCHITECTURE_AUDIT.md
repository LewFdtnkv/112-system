# Аудит кода и архитектуры — обновлён 21.09.2026

Проверены маршруты FastAPI, сервисы, модели, миграции, активные страницы React,
состояние АРМ и тесты. Наличие модели или демонстрационного компонента не считается
готовой функцией. ИИ-исполнение и телефония исключены из перечня недоработок ниже.
Это инженерный обзор, не изменение согласованных предметных требований.

## Что работает

- Пакетная генерация библиотечных карточек локальной ЛЛМ в отдельном воркере;
  параметры и случайные значения фиксируются до вызова, очередь PostgreSQL
  восстанавливается по lease. Готовые тексты проверяет преподаватель.
  Подробнее: [CARD_GENERATION.md](CARD_GENERATION.md). ИИ-оценивание ещё не подключено.

- Одна системная роль аккаунта, авторизация/refresh/смена пароля, отключение доступа.
- Учительские группы, библиотека карточек, снимки версий сценария, запуск группы/ученика.
- Оператор 112: последовательные карточки, серверный черновик с revision,
  выбор кода подготовленного ЕКП, расчёт безусловных и типизированных boolean-маршрутов, учебное оповещение.
- Пагинированные списки, сводные результаты и аналитика, пересмотр оценок с историей.
- В этой итерации: сохраняемая автоматическая оценка, настройки весов в версии сценария,
  доказательства по критериям, серверный аудит и отдельные наблюдения браузера.

- JSON-файлы ЕКП, точечный редактор черновиков, публикация и неизменяемые версии.
- Профили служб с территориями/объектами/контактами; действия ДДС по сообщениям
  сценария, отдельные статусы служб, автооценка и аудит.
  Подробности: [CATALOG_AND_DDS.md](CATALOG_AND_DDS.md).

Подробнее о новых кабинетах, расписании и независимом прокторинге: [BPMN_IMPLEMENTATION.md](BPMN_IMPLEMENTATION.md).

## Незавершённые функции вне ИИ и звонков

P1 — следующий функциональный приоритет; P2 — необходимое развитие кабинетов и эксплуатации.
Порядок внутри P1 зависит от того, какой учебный процесс принимается первым.

| Приоритет | Элемент | Факт в коде | Что ещё требуется |
| --- | --- | --- | --- |
| P1 | Полная семантика исходных условий ЕКП | Работают подготовленные boolean-признаки и AND-условия JSON v1, неизвестные форматы отклоняются | Согласованный разбор всех формулировок XLSX, дополнительные типы/выражения, импорт и предметная проверка |
| P1 | Импорт исходного XLSX | `api/v1/catalog_admin.py` принимает подготовленный JSON | Импорт по заголовкам/версии, полный диапазон, отчёт ошибок, исключённые службы, проверка и публикация. Не выбирать v046_11/v046_24 автоматически |
| P1 | Вводное освоение | `Assignment.hint_delay_seconds`, `ScenarioVersion.hints` хранят настройки; UI сообщает, что подсказок нет | Ожидаемое действие, обнаружение бездействия, показ и аудит подсказки. Влияние подсказок на оценку задавать явно |
| P1 | Жизненный цикл задания | Есть окно доступности, серверное завершение и оценка пропусков | API/кнопки отмены и досрочного окончания по решению преподавателя |
| P1 | Повтор и продление | Лимит новых карточек исполняется сервером; workflow использует `Attempt.number == 1` | Продление и повтор внутри задания; сейчас можно назначить новое задание |
| P2 | Состав группы | Есть добавление, исключение и перевод с сохранением истории | Переименование и передача группы другому преподавателю |
| P2 | Редактирование учебного контента | Версии и архив сценариев реализованы; карточки создаются/читаются | Редактирование/дубликат/архив карточки, явное различие между библиотекой и опубликованным снимком |
| P2 | Карта и адресные справочники | `widgets/location-map-placeholder` — заглушка; адрес вводится вручную | Локальные картографические данные и поиск адреса. Произвольные внешние карты не решают требование автономной сети |
| P2 | Отчёты | Сводные числа, средний балл, профиль ученика, экспорт TXT/XLSX | Разрезы по критериям, ролям и периодам, индивидуальная динамика, экспорт CSV/PDF; сертификаты — после утверждения правил допуска |
| P2 | Сброс пароля администратором | Есть смена текущего пароля самим пользователем | Безопасная выдача нового стартового пароля с отзывом сеансов и аудитом. Исходный пароль/хеш не показывать |
| P2 | Работа при разрыве сети | Черновик восстанавливается с сервера; несохранённый ввод остаётся в памяти | IndexedDB/outbox и согласование конфликтов пока только в ARCHITECTURE.md. Новые UI-наблюдения также могут потеряться при аварийном закрытии вкладки |
| P2 | Событийный мониторинг | Страницы обновляются HTTP-запросами; WebSocket/SSE нет | Решить измерением, достаточно ли polling, затем push/cursor восстановления при необходимости |
| P2 | Эксплуатация | Compose и health-check есть | Проверяемое резервирование/восстановление, локальный пакет образов/зависимостей, метрики, централизованный сбор журналов и нагрузочные испытания |

Кнопки связанных происшествий, напоминаний, части классификационных признаков и
постобработки в `IncidentCardDialog`/`CardClassification` отключены. Это видимые
пробелы относительно полного АРМ, но их необходимость в каждом учебном задании
нужно определять по его цели. Сходство со скриншотом само по себе не задаёт workflow.

## Архитектурные выводы

**Сохранить модульный монолит.** Транзакция «команда → карточка → событие → формальная
оценка» полезнее преждевременного разделения на сервисы. ИИ и тяжёлые задания должны
выполняться отдельными workers через существующую модель AIJob; на HTTP submit
ожидать модель нельзя. Хранилища Evaluation/CriterionResult/CriterionEvidence
использованы повторно, отдельная параллельная БД оценки не создана.

**Frontend:** направление FSD `app → pages → widgets → features → entities → shared`
сохранено. Сетевые DTO — `entities/training`, состояние редактирования — feature,
АРМ — widgets. Компоненты `demo*`, старые SessionTable/диаграммы и локальные stores
остаются как отдельный технический долг: текущие учебные маршруты используют API,
но не следует развивать параллельно две предметные модели. Выделение и удаление
неиспользуемого кода стоит делать отдельной проверяемой задачей.

**Синхронизация:** start/save/submit сериализуются блокировкой урока; это сохраняет
целостность, но может стать узким местом для большой группы. В этой итерации
выделение последовательного номера события защищено блокировкой попытки, а
браузерные наблюдения не захватывают блокировку всей группы. Перед дальнейшим
ослаблением блокировок нужны измерения и конкурентные тесты завершения/отмены.

**Чтение:** активные списки `/views/*` ограничены и загружаются пакетно. Старые
`GET /student/lessons` и некоторые детальные teacher API ещё собирают элементы
в цикле; текущий frontend использует компактные представления. Не переводить
его обратно на эти списки. Аудит читается отдельными страницами по sequence только
при раскрытии; полный журнал не включается в каждое открытие карточки.

**JSON-схемы:** подготовленные маршруты, часть деталей карточек, scheduled_events
и hints пока свободные JSON-поля. Для исполняемого workflow нужны версионированные
схемы и валидация, а не вывод предметных правил из произвольного JSON.

**Права:** системная роль, учебная роль и профиль службы различаются. Смена роли
не удаляет старые учебные объекты; передача владения материалами/группами пока
отдельно не реализована. Не давать администратору неявные права преподавателя.

## Что изменено по результатам этого обзора

1. Автооценка стала сохраняемым результатом после последней карточки ученика,
   независимо от того, завершили ли урок остальные участники.
2. Веса версионируются с заданием и фиксируются в попытке; результаты не меняются
   от открытия страницы или изменения будущей версии сценария.
3. Пересмотр преподавателем создаёт следующую редакцию, сохраняя автоматический
   исходный результат и комментарий. Аналитика использует последний результат.
4. Аудит хранит изменения сохранённых полей, отклонённые команды, оповещение,
   автоматический расчёт и пересмотр; ввод между сохранениями выделен как
   непроверенные наблюдения браузера. Никакого сбора паролей или глобального ввода.
5. Для будущего ИИ подготовлены замороженный контекст, схема решения, проверка
   ссылок на доказательства и запрет подмены контекста. Вызов модели не добавлен.
