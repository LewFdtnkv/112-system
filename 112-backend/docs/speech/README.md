# Озвучка учебных звонков

Преподаватель открывает редактор карточки:

- **Оператор 112 → Озвучить текст заявителя**: сообщение из карточки подставляется в форму; его можно поправить перед синтезом.
- **Оператор ДДС → Голоса руководителей бригад → Создать голос бригады из текста**: один голос и две реплики — приветствие и подтверждение. Раздел доступен при требовании звонка руководителю.

Выбрать Дениса, Дмитрия, Ирину или Руслана, ввести текст, нажать «Озвучить», дождаться готовности,
прослушать и нажать «Добавить в карточку». Затем сохранить карточку. Можно добавить
несколько вариантов; существующий механизм фиксирует выбранную пару на попытку/контакт.
Уже назначенные сценарии сохраняют прежние снимки записей.

Подготовка продолжается после закрытия окна. Записи появляются в общей библиотеке
«Записи звонков» и в выборе готовых записей редактора; при ошибке доступен повтор.
Кнопка «Изменить текст или голос» создаёт новые записи, не заменяя использованные.
Для пары, оставленной в фоне, приветствие и подтверждение можно выбрать в редакторе
отдельно и нажать «Добавить голос».

## Развёртывание

`docker compose up -d --build api speech-worker frontend`

Сервис `speech-worker` включён в основной Compose, работает на CPU: 1 ядро, до 1 ГБ ОЗУ.
Он не зависит от LLM или Asterisk. Модели скачиваются **при сборке образа**, закреплены
коммитом и SHA256. Во время эксплуатации внешняя сеть не нужна. При обычном первом
`docker compose up -d --build` отдельная настройка TTS не требуется. Для самих звонков
по-прежнему нужны настроенная телефония и профиль Compose `telephony`.

Образ API не содержит Piper/scipy. Модели и тяжёлые зависимости находятся только
в отдельном target `speech-worker`; слои моделей не пересобираются при изменении приложения.

Python-зависимости синтеза выделены в группу `tts` в `pyproject.toml`, включая
транзитивные зависимости в общем `uv.lock`. Для их установки:
`uv sync --locked --no-dev --group tts`. Docker использует эту же группу с
`--frozen`; обычная сборка API её не устанавливает. Файлы голосовых моделей
по-прежнему скачиваются отдельным скриптом с проверкой SHA256.

## Очередь и хранение

Используются существующие `speech_assets` и `recordings`, миграций нет. API создаёт
неизменяемые записи; воркер забирает работу через PostgreSQL `FOR UPDATE SKIP LOCKED`,
с десятиминутной арендой и проверкой токена перед публикацией. Транзакция не удерживается
во время синтеза. Выполнение ограничено 180 секундами в отдельном процессе, до трёх
автоматических попыток. После падения воркера работа возвращается по истечении аренды.
Ошибки длины не повторяются автоматически. Одновременно преподавателю разрешены
20 незавершённых реплик. `request_id` обеспечивает идемпотентность отправки формы.

Кэш определяется текстом, голосом и версией синтезатора/назначением реплики.
Одинаковое содержимое может использовать один аудиофайл, но доступ к записи проверяется
по её владельцу. Другие преподаватели и ученики не получают текст или файлы чужих записей.
Повторная генерация готовой записи не допускает её изменения.

Сохраняются PCM WAV 8000 Гц и PCM `.sln16` 16000 Гц с общим ключом. Asterisk выбирает
кодировку под согласованный кодек, в том числе G.722. Нет TTS/LLM в процессе разговора:
приветствие → речь ученика → подтверждение. Смысл речи по-прежнему не распознаётся;
критерий успешного оповещения не изменён.

Лимиты: текст заявителя до 1000 символов/65 секунд, каждая реплика бригады до
200 символов/20 секунд, WAV не более 1 МиБ. Слишком длинный результат отклоняется
с просьбой сократить текст, не обрезается. Ограничение загрузки файлов 1 МиБ сохранено.

## API (только преподаватель)

- `GET /api/v1/telephony/recordings/voices` — список доступных голосов.
- `POST /api/v1/telephony/recordings/synthesize` — 202, одна запись или пара.
  Общие поля: `request_id`, `title`, `voice`, `kind`; для `caller` — `text`,
  для `crew` — `greeting` и `acknowledgment`.
- `POST /api/v1/telephony/recordings/{id}/retry` — повтор своей неудачной озвучки.
- Существующие список/детали/WAV доступны как прежде; детали содержат статус, текст,
  голос и понятную ошибку. До готовности WAV и использование в карточке недоступны.

Внутренний воркер обрабатывает только свою версию Piper. Старый доверенный контракт
внешнего генератора сохранён. Старые задачи с произвольной моделью/голосом автоматически
на новую модель не переводятся. Для них следует создать озвучку через новую форму.

## Модель и проверка

[Piper Python API](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/API_PYTHON.md),
Piper 1.8.0 (GPL-3.0), scipy 1.17.1. Все четыре русских голоса качества medium
из [piper-voices](https://huggingface.co/rhasspy/piper-voices/tree/c10ece1aade47bb51c153c893d14e5bf8e5b7117/ru/ru_RU):

| Голос | Модель | Лицензия датасета по MODEL_CARD |
| --- | --- | --- |
| Денис | `ru_RU-denis-medium` | CC0 |
| Дмитрий | `ru_RU-dmitri-medium` | CC0 |
| Ирина | `ru_RU-irina-medium` | Unknown (не указана) |
| Руслан | `ru_RU-ruslan-medium` | CC BY-NC-SA 4.0 |

Оригинальные MODEL_CARD всех голосов включены в образ рядом с моделями в `/opt/voices`.
Модели не являются клонами голосов пользователей. На диске хранятся все четыре,
но воркер загружает только выбранную модель для текущего синтеза; лимит памяти не увеличен.

После подключения всех четырёх голосов проверены по две реплики каждым:
восемь успешных синтезов без сети при 1 CPU/1 ГБ, 0,70–2,37 с на запись.
Результаты в `four-voices-check.json`; это техническая проверка непустого WAV,
не экспертное прослушивание. API также проверен на создание записей заявителя
и пары реплик руководителя каждым голосом.

Реальная проверка на CPU с лимитами 1 ядро/1 ГБ: шесть фраз двумя голосами,
результаты в `synthesis-check.json`. На этом стенде синтез отдельной записи занял
0,62–2,14 с, длительность аудио 2,13–11,39 с. Не обнаружено пустых WAV и клиппинга.
Это техническая проверка, не экспертная оценка естественности речи.

Отдельно полный путь PostgreSQL → воркер → реальный синтез → две готовые записи →
валидация выбора/фиксация пары ДДС прошёл за 5,61 с. Сам SIP-разговор этой проверкой
не воспроизводился; проигрывание использует существующий механизм подготовленных пар.
