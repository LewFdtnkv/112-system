# Службы, ЕКП и профили ДДС

Справочники настраивает администратор. Преподаватель использует опубликованные версии при подготовке карточек и сценариев.

## Чем отличаются сущности

| Сущность | Содержимое |
| --- | --- |
| Служба | Короткое и официальное название, доступность |
| ЕКП | Типы происшествий, вопросы, условия показа полей и рекомендации служб |
| Профиль службы ДДС | Настройки работы конкретной службы, бригады, компетенции и памятка |
| Карточка ДДС | Исходная история конкретных бригад, новые сообщения и цели занятия |

Профиль не является учётной записью оператора. Один ученик может проходить разные занятия, но внутри занятия ДДС работает за выбранную службу.

## Подготовка

1. В разделе служб и классификаторов создайте службы или импортируйте JSON ЕКП.
2. Проверьте типы, признаки и маршруты; опубликуйте версию.
3. Создайте и опубликуйте профиль нужной службы с бригадами.
4. Создайте карточки для этого профиля, затем сценарий ДДС.

Если подходящих карточек в выборе нет, проверьте выбранный профиль и наличие карточек именно для него. Для тестового стенда [seed](SEED.md) создаёт профили всех активных служб.

## Типы и поля

У типа есть понятное название; внутренний код не нужен ученику. Популярные типы показываются быстрым выбором. Вопросы допускают флажок, выбор одного или нескольких значений, а также текстовые и числовые поля. Обязательность задаётся отдельно.

Зависимые поля показываются по условиям верхних вопросов. Схема и правила приходят на фронтенд, а сервер повторно проверяет значения при сохранении. Скрытое поле не должно становиться необъяснимой ошибкой формы.

## Рекомендации служб

Маршрут учитывает тип, признаки и при настройке — части адреса. Территориальное правило сравнивает указанные компоненты; оно не выполняет геокодирование или поиск по полигонам. Неизвестный адрес не определяет территориального получателя.

Оператор может изменить предложенный набор служб. Автоматическое назначение бригад по району не реализовано: бригады назначаются вручную. Точные правила адресных условий и пример JSON — в [схеме маршрутов ниже](#территориальные-маршруты).

## Версии и данные

Импорт и экспорт позволяют переносить JSON между стендами; точечные правки выполняются в редакторе. Сохранённые версии и снимки занятий нужны для воспроизводимости результатов.

Демонстрационные признаки и маршруты предназначены для обучения. Перед использованием собственного справочника проверьте его полноту и соответствие вашей методике.

## Территориальные маршруты

У маршрута `addresses` содержит варианты сочетаний частей адреса: внутри варианта условия соединяются И, между вариантами — ИЛИ. Признаки `when` также должны выполняться. Пустой список означает отсутствие ограничения по территории; пустой вариант запрещён.

```json
{
  "service_code": "district-service",
  "when": {},
  "addresses": [{"locality": "Москва", "area": "Тверской"}]
}
```

Сравнение не учитывает регистр, ё и лишние пробелы. Общие безусловные службы сохраняются, территориальные добавляются. Редактор, генерация и ученический предпросмотр используют общий расчёт.

Импорт JSON ограничен 1 МиБ. Полный формат скачивается через интерфейс экспорта; актуальная схема доступна в Swagger. [Валидация](VALIDATION.md) · [Оглавление](README.md).
