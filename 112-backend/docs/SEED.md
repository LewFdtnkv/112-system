# Тестовое наполнение БД

Один скрипт `scripts/seed_demo.py` заполняет ЕКП, профили служб и, по выбранному режиму, учебные данные. Выполняйте команды из `112-backend` после запуска Compose и миграций.

## Полный демонстрационный стенд

```sh
docker compose run --rm --build --no-deps api python scripts/seed_demo.py --database --full-demo --prefix demo --state-file /home/appuser/telephony/.demo-seed.json
```

Скрипт создаст справочник, пользователей, группы, карточки, сценарии и решения учеников. Оценки по правилам появятся сразу. Смысловые оценки, новые карточки и рекомендации создаёт настоящий ИИ-воркер; seed не записывает за него ответы, успешные задания или ошибки.

До наполнения загрузите модели по командам из [README](../README.md), включите `SEMANTIC_ASSESSMENT_ENABLED=true` и `LEARNING_RECOMMENDATIONS_ENABLED=true`. Для обработки нужны `worker`, `llm` и `speech-worker`. Можно запустить их после наполнения: очередь хранится в БД. Если они уже работают, обработка начнётся по мере создания задач. Рекомендации появятся после оценивания достаточного числа работ. На CPU это может занять продолжительное время; состояние видно в административной таблице ИИ-задач.

## Учётные записи

После `--full-demo --prefix demo` доступны:

| Логин | Пароль | Для чего использовать |
| --- | --- | --- |
| `admin` | Из файла состояния: `admin_new_password` | Пользователи, справочники, телефоны и ИИ-задачи |
| `demo-teacher` | `demo-teacher-123` | Сценарии, занятия, результаты, сообщения и аналитика |
| `demo-student` | `demo-student-123` | Основной тестовый ученик: все форматы занятий, ошибки для рекомендаций и звонок ДДС |
| `demo-student-good` | `demo-student-good-123` | Успешные работы для сравнения результатов |
| `demo-student-help` | `demo-student-help-123` | Работы с ошибками, подсказками и пересмотром преподавателя |
| `demo-student-new` | `demo-student-new-123` | Ученик с нетронутыми заданиями для самостоятельной проверки |

При другом `--prefix` замените `demo` в логинах и паролях. В обычном `--with-training` создаются только преподаватель и основной ученик; три дополнительных ученика появляются в `--full-demo`.

Пароль `admin` заменяется на случайный и сохраняется в `admin_new_password` файла `--state-file`. [Команда чтения пароля](../README.md#тестовые-данные). Скрипт сохраняет пароль до изменения БД, поэтому он не теряется при прерывании запуска. Пароли преподавателя и учеников находятся в разделе `accounts` этого файла. Если тестировщик потом сменит свой пароль через интерфейс, файл seed сам не обновится.

## Что проверить в полном демо

| Раздел | Подготовленные данные |
| --- | --- |
| Ученик | Доступные занятия 112 и ДДС всех пяти форматов; начатая работа и пауза; запланированное занятие, лимит времени и истёкший срок |
| Результаты и аналитика | Успешные ответы, ошибки адреса, подсказки, журнал действий и события прокторинга; один явно обозначенный пересмотр преподавателем |
| Преподаватель | Основная, резервная и архивная группы; карточка для редактирования, сценарии, сообщения, результаты группы и выгрузка отчётов |
| Память ИИ | Методические примеры и одобренная карточка для генерации; групповой разбор можно запросить после завершения оценивания |
| ИИ-задачи | Две генерации (звонок и СМС), отдельная ситуация ДДС, смысловая проверка завершённых работ; рекомендации планируются воркером по их итогам |
| Аудио | Девять записей в очереди Piper: заявитель и пары приветствие/подтверждение четырьмя голосами. После подготовки их можно выбрать в карточках |
| Звонки | Упражнение ДДС «Звонок руководителю бригады», готовая запись приветствия и браузерное рабочее место основного ученика |
| Администратор | ЕКП, профили всех служб, пользователи, телефонное рабочее место и очередь ИИ |

Для реального звонка отдельно включите [SIP-сервер](TELEPHONY.md). Seed не запускает АТС и не подделывает историю соединений. Рабочее место настраивает `telephony-worker`; в браузере разрешите микрофон (localhost или HTTPS).

Старый полный демонабор с готовыми ИИ-разборами автоматически не переписывается: используйте отдельную чистую БД и новый файл состояния. Это защищает уже выполненные пользователями работы.

## Другие режимы

| Параметр | Что добавляет |
| --- | --- |
| Без учебных флагов | ЕКП и опубликованные профили активных служб |
| `--profiles-only` | Профили для уже существующих активных служб |
| `--with-training` | Основной набор ученических занятий и данных для рекомендаций |
| `--recommendation-cards N` | Число решённых карточек для рекомендаций: 3–30, либо 0 для отключения в обычном учебном режиме |
| `--with-crew-calls` | Вместе с `--with-training`: отдельное упражнение ДДС со звонком бригаде |
| `--full-demo` | Расширенный набор; включает учебные данные, очередь ИИ/TTS и упражнение со звонком |

`--full-demo` требует `--database`, не сочетается с `--profiles-only` и не отключает историю рекомендаций при значении 0.

Только справочник:

```sh
docker compose run --rm --build --no-deps api python scripts/seed_demo.py --database --state-file /home/appuser/telephony/.catalog-seed.json
```

Для меньшего набора решений с настоящими ИИ-рекомендациями используйте обычный учебный режим:

```sh
docker compose run --rm --build --no-deps api python scripts/seed_demo.py --database --with-training --recommendation-cards 6 --prefix demo --state-file /home/appuser/telephony/.training-seed.json
```

Выберите один режим и постоянный файл состояния для своего набора. Команды выше — альтернативы, а не обязательные последовательные шаги.

## Восстановление пароля администратора

Администратор `admin` уже создаётся миграцией. Seed меняет пароль этой записи, не создавая второго администратора. Для отдельной смены пароля используйте:

```sh
docker compose run --rm --build --no-deps api python scripts/seed_demo.py --database --admin-only --prefix demo --state-file /home/appuser/telephony/.demo-seed.json
```

Команда работает и со старым файлом состояния, где есть только `admin_new_password`, без `accounts.admin`. Она не заполняет ЕКП, не создаёт занятия и не заменяет оценки. Старый пароль знать не требуется. БД должна быть запущена и мигрирована. Используйте префикс и путь своего набора; если файл относится к другой БД, укажите новый файл состояния.

Прочитать установленный пароль:

```sh
docker compose exec -T api python -c 'import json; from pathlib import Path; print(json.loads(Path("/home/appuser/telephony/.demo-seed.json").read_text())["admin_new_password"])'
```

В старой версии `--database` только записывал сгенерированный пароль в файл, но не устанавливал его администратору. Само наличие `admin_new_password` в старом файле ещё не означает, что этот пароль действует. Режим `--admin-only` устанавливает его и снимает требование смены стартового пароля.

## Повторный запуск

Используйте тот же `--prefix` и `--state-file`. Скрипт сохраняет связь с созданными записями и не удаляет прогресс. Обычный учебный режим восстанавливает пароли учеников и преподавателя в значение «логин + `-123`». Завершённый `--full-demo` сохраняет дальнейшие изменения тестировщика. Пароль администратора устанавливается из файла состояния; повторный запуск с тем же паролем не завершает его текущие сеансы.

Файл состояния содержит служебные данные и может содержать пароли. Не публикуйте его и не добавляйте в Git. Для демостенда храните его в постоянном томе, как в командах выше.

## Запуск с хоста

После `uv sync --locked`, с настроенными `.env` и доступной БД:

```sh
uv run python scripts/seed_demo.py --database --with-training --prefix demo --state-file .demo-seed.json
```

Для генерации и хранения готовых аудиозаписей нужен доступный для записи `TELEPHONY_MEDIA_DIRECTORY`. Также поддерживается HTTP-режим: `python scripts/seed_demo.py --base-url http://localhost:8000 --state-file .demo-seed.json`. Он тоже сохраняет итоговый пароль администратора; для входа в существующий аккаунт задайте `DEMO_ADMIN_PASSWORD`. В режиме `--database` старый пароль знать не требуется. Полный список параметров:

```sh
uv run python scripts/seed_demo.py --help
```
