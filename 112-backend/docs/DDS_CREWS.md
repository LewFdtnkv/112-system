# Бригады и панель реагирования ДДС

## Настройка

Администратор открывает «Службы и ЕКП → Профили служб», добавляет бригады и
публикует профиль. У каждой бригады есть код, название, описание назначения,
доступность и необязательный контакт старшего из контактов этого профиля.
У опубликованного профиля редактирование создаёт новую версию.

Преподаватель выбирает опубликованный профиль в сценарии ДДС. Он может задать
цель для каждой бригады: назначить или довести до выбранного этапа. Эти цели
показаны ученику в учебном задании. Сообщения этапов должны содержать сведения,
на основании которых ученик принимает решения. Имитируемые телефонные сообщения
пока передаются текстом; SIP этой задачей не подключается.

Старые профили и назначенные уроки не получают новые бригады задним числом.
Для них сохраняется прежнее поле «Номер наряда» и прежняя оценка.

## Работа ученика

Нижние плитки представляют службы. Выбор раскрывает историю службы; дополнительные
службы доступны через «Все службы». В собственной службе над нижней панелью видны
назначенные бригады. Нажатие на бригаду открывает её историю, карандаш — компактную
форму статуса, номера наряда и комментария у нижней панели.

После принятия карточки ученик вручную назначает доступную бригаду. Назначения
нескольких бригад независимы. Допустимые переходы единого учебного алгоритма:

```text
Назначена → Начало реагирования → Прибытие → Проведение работ → Работы завершены
                                     └────────────────────→ Работы завершены
Любое незавершённое назначение → Назначение отменено → Назначена
```

Комментарий обязателен, в том числе при отмене. Отмена сохраняет всю историю.
Завершение бригады не завершает службу или другие службы автоматически.
Для завершения/отказа службы все её активные назначения надо завершить или отменить.
Для учебных целей, заканчивающихся промежуточным этапом, сдача упражнения остаётся
доступна после выполнения этапов службы; непройденные цели бригад учитываются в оценке.
«Не принята → Принята» разрешено до сдачи упражнения, как в памятке, стр. 25 и 32.

Ученик не может менять чужую службу, чужую попытку или завершённое упражнение.

## Хранение и API

- Справочник `crews` хранится в JSONB `service_profiles.rules` вместе с процедурой.
  Он проверяется `ProfileInput`, версионируется и фиксируется в снимке попытки.
  Код уникален внутри версии профиля; контакт должен принадлежать тому же профилю.
- Миграция `0016_dds_crews` добавляет `crew_assignments`: связь с ответом службы
  и попыткой, код бригады, снимок названия/назначения/контакта, текущие статус,
  номер наряда, комментарий, дата назначения, revision. Уникальность — ответ
  службы + код бригады. Старые таблицы и данные не переписываются.
- `GET /service-profiles/{id}` — опубликованный профиль для преподавателя.
  Административный API профилей читает и сохраняет новое поле `crews`.
- `POST /student/attempts/{id}/dds/crews` — назначение/смена статуса. Тело:
  `request_id`, общая `revision` ответа службы, `information_event_id`, `crew_code`,
  `status`, необязательный `crew_number`, обязательный `comment`.
- Все команды блокируют попытку в том же порядке, что остальные действия ДДС.
  Изменение бригады повышает общую ревизию службы; устаревшая вкладка получает 409.
  Повтор того же request_id/содержимого идемпотентен, переиспользование с другими
  параметрами запрещено.
- Источник — уже доступное сообщение этой попытки. Действия бригад не потребляют
  сообщение службы и не открывают следующий этап. В `dds.crews` возвращаются
  назначения с историей; отдельные запросы на каждую бригаду не нужны.
- Учебный аудит `dds.crew_changed` хранит актёра, серверное время, службу,
  назначение, бригаду, прежний и новый статус, сообщение-основание, номер и
  комментарий. События прокторинга остаются отдельными. Ссылки на события
  включены в доказательства автоматической оценки для будущего ИИ.

## Оценивание и просмотр преподавателем

`dds_policy.required_crews` — список `{crew_code, status}`; допускаются только
доступные бригады выбранного профиля. Проверка каждой бригады независима от порядка
действий других бригад. Требуемый этап должен быть достигнут; последующая отмена
обнуляет достижение, если целью не была сама отмена. Отсутствующая бригада — пропуск.

Прежняя политика без целей бригад остаётся `dds-steps-v1`. При наличии целей
сохраняется `dds-crews-v2`: относительные веса статусов службы 80, номера наряда 20,
бригад 20. Группы без эталона исключаются, итог нормируется на сумму оставшихся
весов. Это учебная формула, не профессиональный норматив. Последовательность этапов
службы пока проверяется прежним способом; действия бригад в неё не включаются.

Свободные комментарии службы и бригад помечаются для смысловой проверки, не дают
формального балла. Преподаватель видит сводку, назначения, статусы, номера, историю
и учебный аудит, может пересмотреть итог. ИИ-оценивание ещё не подключено.

процесс `112-frontend/e2e/catalog-dds-real.spec.ts`. Скриншоты — frontend
`docs/screenshots/dds-crews/`.
# Время на плитках АРМ

Ответ ДДС включает `responses[].added_at`, `received_at` и `status_updated_at`.
Последнее поле — время последнего события статуса соответствующей службы;
при отсутствии события используется время получения/направления/добавления.
Назначение и изменение бригады не меняет время статуса службы.
Для бригад возвращаются `assigned_at` и `status_updated_at` из своей истории.
Все времена передаются в ISO 8601; АРМ показывает время Москвы.
