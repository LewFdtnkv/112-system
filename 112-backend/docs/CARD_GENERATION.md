# Локальная генерация карточек

Преподаватель открывает **Карточки → Сгенерировать нейросетью**, задаёт количество
от 1 до 10 и общие параметры пакета. Каждое поле можно оставить случайным.
Версия ЕКП выбирается один раз на пакет, остальные случайные значения — отдельно
для каждой карточки. Поэтому карточки пакета совместимы с одним сценарием.

Типы, признаки и службы берутся из опубликованного ЕКП и активных служб БД.
Города, улицы, дома, объекты, имена и варианты подачи сообщения — небольшие
учебные наборы в `app/services/card_generation.py`; текстовые значения можно
ввести вручную. Телефоны вымышленные, с кодом `000`.
Для свободного обязательного признака без вариантов в ЕКП нужно задать значение
явно: генератор не придумывает профессиональный справочник допустимых значений.

По умолчанию службы рассчитываются по ЕКП с учётом выбранных признаков.
**Явный список преподавателя имеет приоритет**, включая пустой список без
оповещения. При случайном типе предпочтительны типы с соответствующим набором
маршрутов. Модель получает уже конкретные значения, включая службы; определять
маршруты и UUID самостоятельно ей не поручается.

В таблице библиотеки сразу видны строки «В очереди» / «Генерируется» / «Ошибка
генерации». Обновление — раз в 5 секунд, закрытие браузера не останавливает работу.
Готовая карточка появляется в обычной библиотеке с пометкой происхождения.
Преподаватель проверяет условие и эталон, при необходимости изменяет их и включает
карточку в сценарий обычным способом. Автоматической публикации сценария нет.

## Запуск

Из `112-backend`:

```sh
docker compose up --build -d --wait
docker compose exec llm ollama pull qwen3:1.7b
```

Загрузка модели нужна один раз на машине (около 1,4 ГБ). Веса сохраняются в
`llm_models`; после загрузки генерация не требует интернета. Сервис llm доступен
только во внутренней сети Compose. Проверка готовности контейнера проверяет
Ollama, а наличие модели — фактический вызов; если веса не загружены, задача
показывает понятную ошибку и допускает повтор после загрузки.

```sh
docker compose logs --tail 100 worker llm
docker compose exec llm ollama list
docker compose stats --no-stream llm worker
```

Два новых постоянных сервиса: `llm` (Ollama 0.34.2, Qwen3 1.7B Q4) и `worker`
(тот же Python-образ, отдельный процесс). Очередь — существующая PostgreSQL,
таблица `ai_jobs`; Redis не требуется. Миграция `0015_card_generation` добавляет
владельца генерации и уникальную ссылку на созданную карточку; прежние задания
оценивания сохраняются без изменений. Воркер обрабатывает только генерацию v1.

Лимиты по умолчанию: llm — 3 ГБ и 2 CPU, worker — 512 МБ и 1 CPU; один запрос
модели одновременно, контекст 4096, максимум 1000 выходных токенов, thinking
выключен. Через 60 секунд простоя модель выгружается. Настройки окружения:
`LLM_MODEL`, `LLM_MEMORY_LIMIT`, `LLM_CPUS`, `LLM_TIMEOUT_SECONDS` (по умолчанию 300).
При смене модели её надо загрузить отдельно; уже зарегистрированная задача
сохраняет исходное имя модели. GPU не требуется; Docker на macOS здесь работает
на CPU. Лимит контейнера не равен гарантии свободной памяти всего ноутбука.

На локальной проверке две карточки заняли 49–52 секунды каждая; наблюдаемая
память llm — 1,94 ГБ, worker — 63 МБ. Это измерение одного запуска, не SLA.
Официальные сведения: [модель](https://ollama.com/library/qwen3:1.7b),
[API и JSON-схемы](https://docs.ollama.com/api/chat),
[память и параллелизм](https://docs.ollama.com/faq).

## API и гарантии очереди

- `GET /api/v1/card-generations/options` — учебные варианты полей.
- `POST /api/v1/card-generations` — 202, список зарегистрированных задач.
  Тело: `request_id`, `count`, `parameters`. Не заданное значение / null означает
  случайный выбор; отсутствие ключа признака в `feature_answers` тоже случайное.
- `GET /api/v1/card-generations?limit=20&offset=0&pending_only=true` — собственные
  незавершённые и ошибочные задачи; без `pending_only` — история, включая готовые.
- `POST /api/v1/card-generations/{id}/retry` — повтор ошибочной задачи с прежними
  конкретными параметрами. Чужая задача возвращает 404. Ученик и администратор
  не имеют доступа к этим преподавательским маршрутам.

Регистрация пакета атомарна; `request_id` идемпотентен в пределах преподавателя.
Изменённое тело с тем же request_id — 409. На преподавателя допускается максимум
30 одновременно ожидающих/выполняемых карточек. Случайные параметры, seed, версия
промпта и модель сохраняются до вызова ЛЛМ; сетевой повтор их не меняет.
При автоматическом повторе неудачного вызова seed сдвигается на номер попытки,
чтобы не воспроизводить один и тот же ошибочный текст; сами факты неизменны.

Захват через `FOR UPDATE SKIP LOCKED`, lease 90 секунд, продление каждые 20 секунд.
После остановки воркера задачу подбирает новый процесс. Результат может сохранить
только владелец действующей аренды; карточка, получатели и статус `succeeded`
фиксируются одной транзакцией. Ошибки повторяются до 3 попыток с задержкой;
после исчерпания доступен ручной повтор. Смена прав/отключение преподавателя,
архивация ЕКП или отключение службы повторно проверяются перед сохранением.

Сохраняются исходный запрос, конкретные факты, сырой структурированный текст и
метрики вызова. Ученик не получает внутренние промпты и список рекомендованных
служб из задачи. Существенные факты добавляются к условию, чтобы пропущенное
моделью имя/адрес/признак не превратилось в скрытый критерий оценки.

Небольшая модель может ошибаться в формулировках и добавлять неточные детали:
учебная пригодность требует проверки преподавателем. Автоматическая структурная
проверка не подтверждает профессиональную корректность текста. Нейросетевое
оценивание, TTS и SIP эта функция не включает.

Проверки: `tests/test_card_generation.py`, браузерный
`e2e/card-generation-real.spec.ts` с `AUTH_ISOLATED_API=true` и `LLM_REAL_TEST=true`
только на отдельной тестовой БД. Последний действительно вызывает модель;
обычный набор unit-тестов сеть/модель не использует.
