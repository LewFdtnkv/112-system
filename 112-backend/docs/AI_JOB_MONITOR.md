# Монитор ИИ-задач администратора

Для новых отказов `context.inference_failures` хранит до трёх попыток: время,
класс ошибки, для оценивания также категорию (`timeout`, `response_schema`,
`incomplete_response` и т.д.), критерий, проход и длительность запроса.
Произвольный текст исключений с потенциальными сетевыми секретами не сохраняется.
Исторические причины отказов восстановить задним числом нельзя.

`context.assessment_checkpoint` содержит подтверждённые критерии и трассу до сбоя.
Повтор использует законченные критерии только при совпадении входного снимка,
модели, версии промпта и RAG-контекста. Незаконченный критерий проверяется заново;
один первый проход не считается подтверждённой оценкой. Частичный результат
не публикуется ученику как завершённая смысловая проверка.

Страница `/admin/ai-jobs` доступна из меню «Управление → ИИ-задачи» и кабинета
администратора. Показывает генерацию карточек, смысловое оценивание и рекомендации
всех пользователей. Чтение не меняет состояние очереди и не запускает модели.

- Сверху глобальные счётчики за всё время: в очереди, в работе, завершено.
  Завершено = успешно + с ошибкой, разбивка подписана. Фильтры на счётчики не влияют.
- Таблица по 20 задач, новые сверху; фильтры состояния и вида, поиск по ID задачи,
  имени учётной записи инициатора/ученика или модели. Фильтры и выбранная задача в URL.
- Клик по строке, Enter/пробел или «Подробнее» открывает сведения и вкладки входных
  данных, результата и контекста. JSON доступен для выделения и копирования,
  отображается как текст, а не HTML. Ошибка целиком доступна в подробностях.
- Обновление списка и открытой задачи раз в 5 с в активной вкладке, также вручную.
  Во время сбоя показывается ошибка; уже полученные данные остаются с временем снимка.
- Истёкшее удержание воркером отмечается отдельно; это не достоверное определение
  падения процесса. Число попыток — число запусков, включая первый. Время создания
  и завершения не выдаётся за время начала исполнения: отдельного started_at у AIJob нет.
- `succeeded` не означает, что модель дала подходящий текст. Для `template-fallback`
  явно показывается использование заготовки. Исторические способы генерации сохраняются.

API только для AdminDep, включая обычную проверку обязательной смены пароля:

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | `/api/v1/admin/ai-jobs` | Счётчики, время снимка, страница лёгких строк |
| GET | `/api/v1/admin/ai-jobs/{id}` | Поля выбранной задачи и JSON input/context/output |

Параметры списка: `status`, `purpose`, `q` до200 символов, `limit`1..100,
`offset`0..int64max. Страница за пределами списка возвращается к последней доступной.
Преподаватель/ученик получают403, без авторизации401, неизвестный ID404.
Оба ответа `Cache-Control: no-store`. В таблице нет полных input/context/output;
ошибка ограничена240символами. Два SQL-запроса на список со счётчиками, один на детали,
без N+1-запросов пользователей. Токен захвата worker_id не передаётся в браузер.

Миграций и seed не требуется. UI следует FSD; серверное состояние в TanStack Query,
фильтры в URL. Новых зависимостей, отдельной очереди и механизмов состояния не вводилось.

Проверки: `tests/test_ai_job_monitor.py` (на отдельной PostgreSQL) и
`112-frontend/e2e/ai-jobs.spec.ts` (API-фикстуры). Последний проверяет фильтры,
пагинацию, клавиатуру, детали, безопасный вывод JSON, автообновление, ошибки и роль.

Для оценивания описание не обязано дословно повторять речь заявителя. Если модель
всё же рекомендует дословное/точное воспроизведение, `recommendation_guard` в метриках
сохраняет её исходную рекомендацию, а ученику выводится заготовленный совет передать
смысл своими словами. Вердикт и доказательства эта защита не меняет; для структурированного
адреса она не применяется. У ДДС отдельный промпт проверяет комментарий в момент записи,
не полноту последующих этапов. При явном повторе старой отказавшей проверки преподавателем
обновляется версия оценщика с записью `prompt_upgrade`; рабочие данные ученика заморожены.
Для отклонённого чисто числового ответа в описании используется тот же подготовленный
совет: модель не должна объявлять случайное число кодом и отправлять его в выдуманное
«другое поле». Решение о балле по-прежнему принимает обычная двухпроходная проверка.
