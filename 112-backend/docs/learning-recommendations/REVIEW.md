`qwen3-embedding:0.6b`, PostgreSQL/pgvector. Действующие лимиты Ollama: 2 CPU / 4 GiB.
Промпт `study-advice-v1`, температура 0.1, seed 112, контекст 4096.
Рабочие данные не изменялись: отдельная тестовая БД, все записи откатываются.

Первый набор сохранён в `evaluation.json`: 132.29 / 98.03 / 114.00 секунды
включая извлечение материалов. Во всех трёх случаях сработал векторный поиск,
модель вернула допустимые ID, fallback не потребовался.

После проверки текст дополнен названиями повторяющихся полей. Повторный полный
путь seed → очередь → модель → сообщение записан в `seed-final.json`: 204.39 секунды,
векторный поиск, AI-выбор «сравнить разборы → повторение». Сервер подтвердил
расхождения в доме/корпусе в четырёх карточках; сообщение опубликовано.
Увеличение времени не интерпретируется как регрессия: параллельно выполнялись
проверки/сборка. После этого порядок полей в профиле стабилизирован сортировкой,
чтобы хеш профиля не зависел от Python hash seed между воркерами.

Это **три синтетических профиля и дополнительный повтор одного**, не оценка
педагогической эффективности. Факты/цифры во всех показанных сообщениях совпали
с входом. Это в первую очередь свойство ограничения вывода: модель выбирает
методику, но не пишет свободное утверждение об ученике. Качество её выбора
не гарантировано: пример с помощью показывает, что предпочтительный порядок
обучения она соблюдает не всегда. Для дальнейшей проверки нужны оценки методиста
и реальные результаты повторных занятий.

Первый технический запуск завершился отказом публикации из-за lease проверочного
скрипта; он исключён из этих результатов. Скрипт использует одну соединённую
тестовую транзакцию и теперь продлевает lease перед публикацией. В рабочем
воркере отдельный heartbeat уже продлевает lease во время RAG/LLM-запроса.

Автоматические тесты отдельно проверяют минимальный объём данных, отсутствие
проверки как отсутствие наблюдения, защиту от произвольного вывода модели,
fallback, устаревший lease, пересмотр оценки, идемпотентность, права получателя,
скрытие рекомендаций в АРМ и согласованность seed при повторном запуске.
