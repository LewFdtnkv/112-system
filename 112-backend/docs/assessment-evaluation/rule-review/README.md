# Ограниченный пересмотр полей по правилам

Новые проверки оператора 112 используют `semantic-v4-rule-review` и замороженную
политику `rule-review-v1`. Проверяются и совпавшие с эталоном поля, и расхождения:
тип происшествия, признаки ЕКП, отметки, сведения о заявителе, части адреса.
В упражнениях на отдельный навык в пересмотр попадают только оцениваемые поля.

ИИ оценивает одно поле по условию, **не видя эталонного значения и исходного
балла**. Иначе небольшая модель может повторять ошибку эталона. Вердикты:
соответствует / частично соответствует / противоречит / недостаточно сведений.
Числовую оценку модель не задаёт. Сервер сравнивает вердикт с формальной проверкой
и выбирает повышение, сохранение либо снижение на **25% веса этого поля**.

Пример: группа «Адрес» весит 30 баллов и включает два проверяемых поля. По правилам
ученик получил 15 баллов: дом совпал, «ул. Правды» не совпало с «Правды».
Если условие подтверждает ту же улицу и оба прохода ИИ это признают, прибавка —
30 / 2 × 0,25 = 3,75 балла. Группа получает 18,75 из 30. Это намеренно ограниченная
поправка, не полная замена правила: преподаватель может пересмотреть итоговый балл.
Снижение работает симметрично, например когда заполнение совпало с ошибочным
эталоном, но противоречит явно указанному дому или наличию пострадавших.

Для поправки нужны дословные цитаты из условия и ответа, уверенность ≥0,85 и
совпадающие вердикты двух проходов. Самооценка уверенности и два прохода одной
модели не являются доказательством правильности; влияние ограничивает сервер.
Если балл остаётся прежним, второй вызов не нужен. При расхождении проходов,
неоднозначности, отсутствующем доказательстве либо техническом отказе балл
по правилам сохраняется. Пустое обязательное поле не получает баллы за ответ,
который модель придумала вместо ученика. Пропуски не заполняются автоматически.

Нормативы времени, звонки, оповещение, назначение и статусы бригад остаются
проверками подтверждённых серверных действий. Для ДДС сохраняется смысловая
проверка комментариев. Проверка дополнительных служб тоже сохраняется.
Коррекция структурированного поля не входит повторно в отдельные 25% за смысл
свободного текста. Вес этой части и старые формулы не менялись.

Исходные Evaluation/CriterionResult не переписываются. Версия пересмотра
фиксируется при сдаче; прежние результаты и явные повторы старых ИИ-задач
не приобретают новую формулу задним числом. Поздний ИИ не заменяет оценку
преподавателя. Ученик и преподаватель видят причину, цитаты и исходную/новую долю
балла за поле. Через «Исправить вывод ИИ» преподаватель может сохранить разбор
в существующую память; подбор ограничен автором, ролью и конкретным критерием.
Профиль для дальнейших учебных рекомендаций учитывает ту же поправку ровно один
раз в исходном навыке, включая ошибки, найденные в совпавших с эталоном полях.
Он ждёт окончания смысловой проверки. Офлайн-примеры seed сохраняют формальную
оценку структурированных полей и явно обозначены как демонстрационные.

Проверка выполняется фоновым воркером. Число вызовов выросло: один на проверяемое
поле и ещё один при возможном изменении балла, плюс прежние текстовые критерии.
Оценка по правилам доступна сразу; смысловая проверка дополняет её позже.
На CPU не следует ожидать мгновенной проверки большой карточки.

## Проверки

- `tests/test_rule_review.py`: предел поправки, доля поля, отсутствие двойного
  веса, отказ от спорных выводов, исходный балл при сбое/старой политике,
  отсутствие эталона в промпте, предел используемых примеров памяти.
- `tests/test_semantic_assessment.py`: очередь, публикация новой редакции,
  корректная передача пересмотра обоим пользователям, защита оценки преподавателя.
- `tests/test_assessment_memory.py`: публикация и отзыв преподавательского разбора,
  изоляция памяти; включает новые критерии в результате реальной сдачи тестовой работы.
- Frontend `e2e/semantic-assessment.spec.ts`: результаты преподавателя и ученика,
  сохранённый АРМ и снимки компьютера/телефона в `docs/screenshots/rule-review`.

`cases.json` содержит целевые случаи, `holdout.json` — дополнительные проверки.
`initial-results.json` сохраняет исходный эксперимент с видимым эталоном,
включая нелогичный отказ засчитать «Пострадавшие: Да» при травме заявителя.
Это небольшая инженерная выборка, не оценка точности на реальных занятиях.

### Реальный прогон 28.09.2026

Модель стенда: `qwen3:4b-instruct-2507-q4_K_M`, два потока CPU, контекст 4096,
температура 0,1. Рабочие оценки и БД при экспериментах не изменялись.

Первый эксперимент остановлен после семи законченных примеров: шесть ожидаемых
вердиктов, один нелогичный отказ при правильной отметке о пострадавшем. Модель
одновременно объяснила наличие пострадавшего и объявила ответ «Да» неверным.
Отказ был ошибкой качества, не техническим сбоем; исходный нулевой балл остался.
После этого убраны эталон и исходный балл из входа модели. Сервер по-прежнему
хранит их для расчёта. Повторный проход оставлен только для возможной поправки.

Финальный прогон: 12 целевых и 6 дополнительных примеров. **18/18 вердиктов и
18/18 действий с баллом совпали с ожидаемыми.** Пять повышений, пять снижений,
восемь сохранений балла; технических отказов и ошибочных изменений балла не было.
Проверены сокращения адреса, перестановка ФИО, ошибочный эталон дома/телефона/типа,
косвенные пострадавшие, чужой и неизвестный возраст, пропуск поля, отрицания,
составной признак и вредоносная инструкция в ответе. Сырые ответы, промпты и
цитаты — `final-results.json`, сводка — `summary.json`.

При чтении всех 18 ответов найдена **одна ошибочная рекомендация**: для пустой
улицы модель предложила «Правда» вместо «Правды». Балл и основание при этом
выбраны верно. Поэтому советы по структурированным полям теперь составляет
сервер: сверить указанное поле с цитатой условия; правильный ответ не получает
лишнего совета, неизвестный факт предлагается уточнить с преподавателем.
Свободное объяснение ИИ и его первоначальный совет сохраняются в аудите.
`guarded-results.json` — повторная обработка всех 18 записанных ответов финальной
защитой **без новых вызовов модели**; все вердикты и баллы сохранены.
`guard-live.json` — дополнительный **реальный** повтор проблемного случая:
правильный нулевой балл, цитата «улице Правды» и безопасный совет без подмены адреса.

Медиана 45,17 с на поле, диапазон 17,83–110,96 с. Замеры проводились на общем
стенде вместе с другими проверками, поэтому это не тест пропускной способности.
Большая карточка может проверяться несколько минут. Оценка по правилам при этом
уже доступна. Есть стилистические недостатки: в объяснении пустого поля модель
назвала пропуск «противоречием», хотя вердикт и нулевой балл выбрала правильно.
Выборка короткая и авторская; 18/18 не означает безошибочность на реальных данных.

Повторить после запуска модели, из backend (Node не нужен; рабочая БД не используется):

```sh
docker compose run --rm --no-deps -v "$PWD/docs:/app/docs:ro" worker python -m scripts.evaluate_assessment --cases-file docs/assessment-evaluation/rule-review/cases.json
docker compose run --rm --no-deps -v "$PWD/docs:/app/docs:ro" worker python -m scripts.evaluate_assessment --cases-file docs/assessment-evaluation/rule-review/holdout.json
```

Команды печатают JSONL с входом, вердиктом, поправкой, промптами и временем.
Запускайте при свободной очереди: используется тот же локальный LLM-сервис.
