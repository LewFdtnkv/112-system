# PostgreSQL RAG: проверка смыслового оценивания, 24.09.2026

## Что именно проверяли

Пять **отдельных критериев**, а не пять полных карточек/занятий: парафраз о
затоплении подвала, противоречивые сведения очевидцев, обоснованная скорая,
необоснованная газовая служба и верный комментарий ДДС. Взяты из прежнего набора
15 проверок 8B; текст зафиксирован в `rag-five-cases.json`.

Использована текущая рабочая **Qwen3 4B Instruct-2507 Q4_K_M**, а не 8B.
Решение о смене основной модели в эту задачу не входит. Ollama 0.34.2,
CPU-only, отдельный контейнер 4 CPU / 4 GiB, num_ctx4096, num_predict650,
temperature0.1, think=false, seeds112/113. Embeddings —
`qwen3-embedding:0.6b`, 1024 измерения, официальный Q8_0 639MB.
Полные идентификаторы весов и хеш корпуса — в `rag-metadata.json`.

25 авторских синтетических разборов составлены до первого RAG-прогона.
Точные условия и ответы проверяемых примеров не включены в корпус
(названия служб, естественно, повторяются). Однако прежние ошибки были известны
автору корпуса: это **калибровка на известных случаях, не слепая независимая
оценка профессиональной точности**. Названия case, expected и cohort не
передаются модели. Поля label нейтральны. Разметка не подтверждена заказчиком.

## Сначала проверили только добавление RAG

`rag-five-results.json` содержит парные вызовы: прежние статические примеры и
подбор трёх разборов через реальный pgvector. Рубрика, основная модель, параметры,
проверка цитат и согласие двух ответов одинаковы. У RAG добавлены инструкции
не переносить факты из найденных примеров. Не используются новые ограничения
цитат через enum или серверная защита явной неоднозначности.

| Критерий | Ожидание | Статические примеры | Только RAG |
|---|---|---|---|
| Подвал: допустимый парафраз | Засчитать | Засчитано | Засчитано |
| Противоречивые очевидцы | Преподавателю | Отказ по несогласию двух ответов | **Ошибочный автоматический штраф** |
| Скорая при ожогах | Засчитать | Отказ из-за цитаты | Отказ из-за цитаты |
| Газовая без оснований | Не засчитывать | Не засчитано | Отказ из-за цитаты |
| ДДС: ограждение и ремонт | Засчитать | Засчитано | Отказ из-за цитаты |

Статические примеры: применено 3/5, все три вердикта совпали с разметкой; два
отказа, из них один ожидаемый по неоднозначности. Только RAG: применено 2/5,
один вердикт верен, один ошибочен; три отказа по цитатам. **На этой выборке
добавление RAG само по себе не улучшило качество и ухудшило принятие решений.**

Особенности ошибок:
- Для очевидцев найдены два релевантных примера об отказе при противоречии,
  но оба ответа модели всё равно дали incorrect с confidence0.98.
- Скорая определена правильно, но склеенная цитата не позволила применить балл.
  Рекомендация «уточнить, что ожоги — это травма» избыточна и не помогает ученику.
- Газовая определена правильно; в цитату добавлено оповещение основной службы,
  отсутствующее в текущем условии. Объяснение «газ не упоминается» неточно:
  условие прямо говорит, что сведений о газе нет.
- У ДДС вывод correct верен, но цитата искажена повторениями и служебными
  последовательностями. Ближайший найденный разбор был о конфликте сообщений,
  а не о равнозначной формулировке. Сходство embedding не гарантирует полезность.

Первый baseline-запрос по очевидцам оборвался по timeout300с; технический повтор
с теми же данными и seeds при timeout600с завершён и сохранён отдельной записью.
Повтор не выбирался по качеству ответа. Оба его вердикта противоречат политике
отказа (partial, incorrect), но существующее правило несогласия их заблокировало.

## Окончательный вариант

После первого сравнения добавлены две отдельные защиты:
1. JSON Schema разрешает цитаты только из дословных фрагментов текущего условия
   и ответа. Нельзя выбирать цитату из RAG. Это исправляет форму доказательства,
   но **не проверяет логическую связь цитаты и вывода**.
2. Узкая проверка явно написанных оговорок о противоречивых источниках в условии
   или эталонном решении сразу оставляет критерий преподавателю. Она не решает
   задачу общего обнаружения смысловых противоречий.

Повторный прогон — `rag-five-final-results.json`. Корпус и пять условий не менялись.
Начальная попытка была прервана во втором вызове первого примера: проверка кода
обнаружила, что оговорка о конфликте может находиться в эталоне. Успешный первый
ответ сохранён как прерванная попытка и исключён из итоговой метрики. После
исправления все пять примеров проходят через окончательную реализацию.

### Итог окончательного прогона

| Критерий | Итог | Применён | Вызовов LLM | Секунд |
|---|---|---|---:|---:|
| holdout_water_paraphrase | correct | Да | 2 | 239.57 |
| conflicting_sources | uncertain | Нет, серверная защита | 0 | 0.00 |
| extra_service | correct | Да | 2 | 284.48 |
| unsupported_service | incorrect | Да | 2 | 272.47 |
| holdout_dds | correct | Да | 2 | 160.60 |

Применены **4/5** решений, все четыре совпадают с авторской разметкой.
Один неоднозначный случай передан преподавателю **кодом без вызова LLM**.
Восемь итоговых ответов модели; ошибочных применённых вердиктов в этом маленьком
наборе не было. Нельзя называть это «точность ИИ 100%»: выборка известная,
синтетическая, всего четыре принятых решения; пятый случай решён защитой.
Нельзя приписывать результат одному RAG: одновременно изменились правила
выбора цитат и появилась серверная защита неоднозначности.

Сумма времени пяти итоговых проверок — **957.12 с**;
среди четырёх с вызовами модели диапазон160.60–284.48с, среднее239.28с.
Подготовка первых25 векторов и5 запросов заняла28.17с. Это наблюдаемые времена,
не чистый скоростной бенчмарк: параллельно выполнялись тесты, сборки и индексация
стенда; модель имела4CPU, рабочий лимит остался2CPU. Таймаут и прерванный прогон
в эти итоговые времена не включены. В тестовом контейнере OOMKilled=false;
наблюдалось около3.37GiB, это не непрерывно измеренный пик.

За два эксперимента сохранено26 завершённых ответов LLM:17 в первом,
8 в окончательном и1 в исключённой прерванной попытке. Дополнительно были
один timeout и один намеренно прерванный запрос без сохранённого ответа.

### Замечания к тексту окончательных ответов

В варианте с ограниченными цитатами сохранились недостатки свободного текста:
- У скорой вердикт correct и цитата правильные, но первый ответ всё ещё советует
  «уточнить, что ожоги — это травма». Это ненужное требование к ученику.
- У газовой incorrect обоснован отсутствием данных для её привлечения, однако
  фраза «газ не упоминается» неточна: отсутствие сведений о газе прямо упомянуто.
  Рекомендация требовать прямого указания повреждения сетей/оборудования слишком
  узкая как общее правило: её нельзя переносить на другие ситуации, например
  сообщение о запахе газа. Корректный вывод для этой карточки не делает такой
  совет универсальной профессиональной инструкцией.

- У ДДС первый вывод верен, но содержит грамматическую ошибку; во втором ответе
  модель безосновательно использует отсутствие уточнений как подтверждение
  неизменности действий. Этот второй текст не показывается как итоговое
  объяснение, однако сохранён в журнале проверки.

Эти замечания не исчезают от наличия RAG или confidence0.99. Наполнение памяти
и исправления преподавателя должны проходить методическую проверку.

## Воспроизведение

Нужны отдельная мигрированная PostgreSQL с pgvector и локальная Ollama с обеими
моделями. Не направляйте этот скрипт в рабочую БД: он наполняет память примерами.

```sh
DATABASE_URL=postgresql+asyncpg://postgres:rag-test@127.0.0.1:55440/rag_check \
LLM_BASE_URL=http://127.0.0.1:11436 \
LLM_TIMEOUT_SECONDS=600 \
uv run --locked python -m scripts.evaluate_assessment_rag \
  --cases-file docs/assessment-evaluation/rag-five-cases.json \
  --output docs/assessment-evaluation/my-rag-run.json --mode rag
```

`--resume` повторяет только незавершённые/технически неуспешные пары и сохраняет
первоначальные ошибки и успешные вызовы. `--mode both` сравнивает стандартные
примеры с RAG **на текущей реализации защит**. Первый исторический RAG-only
эксперимент был выполнен до добавления этих защит; его полный вход/выход сохранён
в артефакте. Технический timeout600с использован только в эксперименте;
производственная настройка по умолчанию осталась300с.

## Практический вывод и пределы проверки

RAG полезен как управляемая память преподавателя, но сам по себе не даёт гарантии
улучшения оценок. Буквальная цитата, два согласованных ответа и confidence0.99
тоже не доказывают правильность. Выбор ближайших примеров нуждается в дальнейшей
проверке на новых условиях: для ДДС здесь первым оказался отвлекающий пример.

Перед использованием оценки без выборочной проверки преподавателем нужна
зафиксированная экспертная выборка новых полных работ, отдельно от памяти и
калибровки. Следует считать ошибочные применённые штрафы, ошибочное принятие,
долю отказов и качество рекомендаций по каждому виду критериев. Отдельно
проверить реальные JSON-представления нескольких дополнительных служб и
хронологию нескольких бригад: данный короткий набор этого не покрывает.

Рабочая основная модель не увеличивалась. Ручной итоговый балл сохраняет приоритет;
точные ошибки в адресе/обязательных действиях RAG не отменяет. Настройки памяти
преподавателя влияют только на последующие подборы, уже сохранённые оценки и
их фактический контекст не переписываются.
