# Отметки карточки и молчаливые вызовы

Пять отметок над типом происшествия сохраняются в существующем JSONB:
`card_templates.data.additional_fields.details` и `incident_cards.additional_fields.details`.
Снимки сценария и аудит сохранений содержат те же данные.

| Ключ | Отметка АРМ | Параметр генерации |
| --- | --- | --- |
| `hasVictims` | Пострадавшие | `has_victims` |
| `refusedAmbulance` | Нет на месте / Отказ от скорой | `refused_ambulance` |
| `blocked` | Нет доступа / Заблокированные | `blocked` |
| `noContact` | Нет контакта | `no_contact` |
| `callDropped` | Срыв звонка | `call_dropped` |

Значения строго boolean, в эталоне допустимы null/отсутствие («Не оценивать»).
Строка `"false"` не допускается. Количество пострадавших остаётся отдельным
`features.victimsCount`: целое 0…100000 либо null, если неизвестно.
Наличие пострадавших можно отметить без известного числа.
Эталон не допускает противоречий между количеством, отметкой и булевыми
признаками ЕКП `injured`/`victims`. Черновики ученика сохраняют ошибочные ответы,
чтобы их можно было исправить и показать при разборе.

Каждая заданная в эталоне отметка даёт один проверяемый пункт в группе
«Классификация». Пропущенная учеником отметка означает выключенную кнопку.
Отсутствующие в прежних эталонах значения не становятся новыми критериями.
В АРМ «Пострадавшие» — только кнопка выбора, как на исходном скриншоте.
Отдельного ввода количества нет. Сохранённое количество остаётся сведением
условия/эталона, но не проверяется автоматически и не предлагается подсказками.
Подсказки и упражнения на классификацию используют эти же проверки; в отработке
других навыков отметки предзаполняются и защищаются сервером от изменения.

## Нет контакта

По уточнению пользователя это полностью молчаливый вызов: соединение установлено,
речи и сведений заявителя нет. Это не отсутствие обратной связи после разговора.
«Срыв звонка» — отдельный признак разрыва соединения, допустим вместе с тишиной.

Для такой карточки тип, адрес, координаты, личность и признаки происшествия
неизвестны, служб нет. Допустим технически определённый номер телефона.
В описании фиксируются наблюдения оператора. Сохранение завершает упражнение
без оповещения. API отклоняет сочетание молчаливого вызова с известными
структурированными сведениями или получателями при создании эталона/отправке
ответа. Содержание свободного текста семантически пока не проверяется.

Миграция `0019_silent_call_cards` разрешает null в
`card_templates.classifier_entry_id`. В ответах библиотеки, снимках сценариев,
подсказках и оценке такой тип поддержан. Опубликованная версия ЕКП по-прежнему
нужна для сценария. Обратная миграция откажется выполняться, пока есть карточки
без типа; она не удаляет их и не подставляет выдуманный тип.

## Генерация

Порядок: конкретные факты → проверка совместимости → запись задания в БД →
текст от модели → структурная проверка → черновик карточки в библиотеке.
Модель не меняет выбранные поля и получателей. Null в параметрах генерации
означает случайный выбор заново для каждой карточки пакета.

Количество и наличие пострадавших согласуются между собой и с известными
булевыми признаками ЕКП. Фиксированное противоречие возвращает 422 до постановки
задания. При случайном «Нет контакта» молчаливый вызов выбирается с вероятностью
10% только при отсутствии заданных несовместимых сведений; фиксированные
настройки преподавателя не теряются. В UI явный выбор «Нет контакта: Да»
сбрасывает и блокирует несовместимые настройки с пояснением.

Молчаливое сообщение готовится воркером по шаблону, без обращения к ЛЛМ.
Для остальных сообщений используется промпт `card-generation-v2` с конкретными
отметками и их значениями. Существующие задания v1 не оставляются в очереди.
Контрольные факты добавляются в условие, чтобы пропуск модели не превращался
в скрытый критерий. Полноценного поиска смысловых противоречий в тексте пока
нет: преподаватель проверяет материал перед включением в сценарий.

Проверки: `tests/test_card_flags.py`, `tests/test_card_generation.py`,
`tests/test_learning_workflows.py`; frontend `e2e/card-flags.spec.ts`.
