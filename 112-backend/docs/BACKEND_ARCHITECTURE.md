# Архитектура backend

Backend — модульный монолит FastAPI / SQLAlchemy. API и фоновые процессы используют общую PostgreSQL. Отдельные воркеры выполняют ИИ-задачи, синтез речи и телефонию.

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `api` | HTTP-параметры, роли, зависимости доступа и ответы |
| `services` | Прикладные операции, владение объектами, транзакции и чтение |
| `domain` | Общие предметные правила |
| `schemas` | Контракты и валидация входа/выхода |
| `models` | ORM-модели и ограничения хранения |
| `db` | Сессии и SQL-помощники |
| `core` | Настройки, безопасность и независимая инфраструктура |
| `scripts` | Команды через HTTP либо прямые вызовы сервисов |

Сервисы не импортируют API. Модели, схемы и инфраструктура не зависят от сервисов. Роутеры не вызывают друг друга, CLI не вызывает функции эндпоинтов в обход HTTP-проверок. Пакетные `__init__.py` не должны скрывать циклы массовыми реэкспортами.

## Основные процессы

| Область | Модули внутри `app/services` |
| --- | --- |
| Выполнение и сроки | `student/`, `lesson_clock.py`, `lesson_presence.py`, `deadlines.py` |
| Подготовка материалов | `authoring/` |
| Бригады и реагирование | `dds/` |
| Подсказки и сопровождение | `learning_hints/`, `interface_guide.py` |
| Оценивание | `automatic_assessment/`, `semantic_assessment/` |
| Память и рекомендации | `assessment_memory/`, `learning_recommendations/` |
| Генерация | `generation/`, `generation_worker.py` |
| Справочники | `catalog_admin.py`, `catalog_editor.py` |
| Телефония | `telephony/` |

Представления `/views/*` собирают нужные экрану данные без запроса на каждую строку. Небольшая SQL-проекция может оставаться в роутере: перенос одного SELECT в универсальную обёртку не улучшает архитектуру сам по себе.

## Транзакции и конкуренция

Коммит принадлежит операции целиком. Сохранение ответа, событие и оценка не превращаются в отдельные транзакции из-за декомпозиции файлов.

`student_lesson` проверяет владение и блокирует занятие: чтение может исполнить сроки или поступление карточек. `owned_attempt(lock=True)` обновляет попытку после ожидания блокировки. Просрочка фиксируется даже перед отказом запоздалой команде; общий rollback без анализа может нарушить это правило.

Роли проверяются зависимостями API, владение — сервисами. Учебный аудит и прокторинг имеют разные модели. Последовательность событий выделяется под блокировкой попытки. Конфликты редактирования обнаруживаются ревизиями.

## Инфраструктура ИИ

`core/ollama.py` отвечает за HTTP `/api/chat`, ограниченное чтение JSON и проверку завершённости ответа. Он не повторяет запросы сам. Промпты, схемы, ограничения контекста и резервные решения принадлежат конкретным процессам; эмбеддинги используют отдельный `/api/embed`.

`ai_jobs/handlers.py` явно регистрирует пять назначений: подготовку, вызов модели, публикацию и политику отказа. Неизвестное назначение отклоняется. Автоматического поиска плагинов и контейнера DI нет.

`generation_worker.py` управляет захватом, продлением, повторами и циклом очереди. `ai_jobs/lease.py` проверяет токен и срок захвата; перед изменением вызывающий код всё равно блокирует строку. Публикация карточки находится в `generation/publication.py`, публикация оценок — в своём процессе.

Медленные внешние операции выполняются вне транзакции. Перед публикацией проверяются захват и исходная версия данных. Результат старого воркера не должен перезаписывать актуальную работу или оценку преподавателя.

## Принципы изменений

SOLID здесь означает отдельную ответственность и явные зависимости, DRY — один источник предметного правила, KISS — минимум нужных уровней. Классы, Repository и UnitOfWork не вводятся только ради шаблона: AsyncSession уже представляет единицу работы.

Декомпозиция должна сохранять порядок блокировок, права, идемпотентность и исторические снимки. Разделение очередей, ослабление блокировки занятия или изменение формулы оценки — изменения поведения, требующие самостоятельных проверок.

Границы зависимостей проверяются `tests/test_architecture.py`, выбор обработчиков — `tests/test_worker_dispatch.py`. Интеграционные тесты используют настоящую PostgreSQL для ролей, ревизий, сроков и гонок. [Команды проверок](DEVELOPMENT.md).
