# Рекомендации по дальнейшему обучению

Это отдельный процесс после завершённых занятий. Он не выдаёт ответы на текущую
карточку, не изменяет оценки и не назначает новые занятия самостоятельно.

## Основания и границы

- Профиль строится отдельно для 112 и ДДС по семи профессиональным навыкам.
  Одна карточка даёт одно наблюдение по каждому проверенному навыку; отсутствие
  проверки не превращается в ноль.
- Для рекомендации по навыку нужны минимум три проверенные карточки в двух
  завершённых занятиях. Учитываются последние пять занятий; дополнительно
  сохраняются общие показатели и направление изменения результатов.
- Повторяющиеся расхождения (от двух), ухудшение результатов и успех только с
  помощью дают разные варианты дальнейшего обучения. Не более двух приоритетов
  в сообщении. Успешные самостоятельные работы отмечаются как сильная сторона.
  Повторяющиеся точные расхождения дополнены названиями полей и числом карточек,
  например «Дом» (4), «Корпус» (4); значения ответов в сообщение не копируются.
- Источник — сохранённые результаты правил и применённые смысловые решения.
  Наличие свободного текста само по себе не доказывает его правильность.
  Спорные или незавершённые смысловые проверки не используются для обвинений;
  неразрешённый вопрос о дополнительных службах исключает соответствующий вывод.
- Подсказки не штрафуются. Паузы, скорость печати, фокус вкладки и прокторинг
  не используются для вывода о навыках. Обучение интерфейсу и разбор примера
  не подтверждают самостоятельность. Незавершённые карточки не диагностируют
  конкретный навык.
- Итоговая ручная оценка не содержит разбивки по навыкам: такое занятие
  исключается из профиля, а основанные на прежней оценке сообщения помечаются
  устаревшими. Это консервативное ограничение текущего контракта.

## ИИ и методические материалы

`learning_guides` — отдельная от разборов оценивания коллекция PostgreSQL/pgvector:
35 подготовленных вариантов (7 навыков × 5 способов обучения). Они автоматически
добавляются при первой задаче, существующие отключённые записи не включаются заново.
Тексты и версия находятся в `app/services/learning_recommendations/materials.py`.
Пока это версионируемый разработчиком корпус; отдельного редактора в UI нет.

Сначала применяются строгие фильтры навыка, допустимой стратегии, версии и активности.
Qwen3 Embedding 0.6B ранжирует только подходящие варианты, векторы кэшируются по
идентификатору модели. При недоступности эмбеддингов остаётся фильтрация по метаданным.
Для столь малого корпуса векторное ранжирование вспомогательное.

Маленькая Qwen3 выбирает по одному ID способа обучения на приоритетный навык.
Промпт содержит агрегаты и методические варианты с примерами выбора. Ни ФИО,
ни телефоны, ни сырые ответы/клики/события прокторинга туда не передаются.
Сервер проверяет принадлежность ID и собирает сообщение из фактических чисел
и подготовленных текстов. Произвольный текст модели ученику не показывается.
Это сознательное ограничение: персонализирован выбор, но модель не может
придумать ошибку ученика или выдать опасную профессиональную инструкцию.

При сбое/некорректном ответе публикуется допустимый методический вариант с явной
меткой «Методическая рекомендация», без утверждения, что его выбрала ИИ.
Успешный выбор помечается «Подобрано с ИИ». Отзыв ученика сохраняется;
автоматического обучения модели по одному отзыву нет.

## Выполнение и интерфейс

Общий PostgreSQL worker проверяет новые основания при запуске и затем раз в
60 секунд между задачами. Загруженный worker сначала завершит предыдущую работу.
`AIJob.purpose=recommendation`, цель — `student_id`; сохраняются профиль,
материалы, версия промпта, результат и метрики. Действуют общий lease/heartbeat,
повтор после сбоя и защита от публикации устаревшим воркером.

Перед публикацией профиль перечитывается. Изменившиеся оценки не допускают
устаревшего сообщения. Один и тот же состав приоритетов не порождает совет
после каждого занятия. История сообщений сохраняется.

Сообщения находятся в кабинете ученика в блоке «Сообщения и рекомендации».
Внутри АРМ остаются только сообщения преподавателя. Ссылка ведёт только на
назначенное, доступное, ещё не оценённое занятие нужной роли/формата/навыка;
без подходящего занятия предлагается обратиться к преподавателю. Доступность
ссылки перепроверяется при чтении. Отзыв и отметка прочтения доступны только
получателю.

Настройки Compose: `LEARNING_RECOMMENDATIONS_ENABLED=true`,
`RECOMMENDATION_MODEL=qwen3:4b-instruct-2507-q4_K_M`. Используется существующий
LLM-сервис и `EMBEDDING_MODEL`, дополнительной модели/очереди не нужно.
Изменение схемы — миграция `0026_learning_recommendations`.

## Проверка через seed

`--with-training --recommendation-cards 6` создаёт шесть дополнительных карточек
и три завершённых занятия (по две карточки). Четыре ответа содержат пропуски
частей адреса, классификация заполнена правильно. Ответы проходят обычные
команды сохранения/завершения и оценивание, оценки не вставляются вручную.

Число карточек: `3..30`, `0` отключает этот набор. По умолчанию — 6.
Повтор с тем же state-file не сбрасывает результаты. Уменьшение числа не удаляет
уже созданную историю. После наполнения работающий worker сам поставит задачу;
если он запускается позже, обнаружит результаты при запуске.

Пример и пароли тестовых пользователей описаны в [DEMO.md](DEMO.md).
Для воспроизводимого реального прогона предусмотрен
`scripts/evaluate_learning_recommendations.py`: обязательный `TEST_DATABASE_URL`
на отдельную мигрированную БД, `--output` и `--work-directory` внутри workspace.
Все изменения БД откатываются; рабочий каталог содержит закрытый тестовый state-file
и не должен коммититься. Результаты проверки — в `learning-recommendations/`.
