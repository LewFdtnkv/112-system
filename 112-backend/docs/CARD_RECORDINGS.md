# Записи в учебных карточках

Готовые WAV теперь загружаются в редакторе карточки. В разделе «Оператор 112»
можно выбрать до десяти вариантов сообщения заявителя. Они должны передавать
одни и те же сведения: система проверяет формат файла, но не распознаёт речь
и не сверяет содержание записи с эталоном.

Для ДДС, если включено требование звонка новой бригаде, можно выбрать до десяти
пар «приветствие — подтверждение». Желательно одним голосом в каждой паре.
Без собственных пар остаётся встроенный набор голосов. Приветствие/подтверждение
до 20 секунд, чтобы не превышать ожидание воспроизведения. Между ними остаётся
прежняя проверка факта речи ученика; распознавание смысла не добавлено.

Формат: WAV PCM, моно, 8000 Гц, 16 бит, не более 1 МиБ на файл. Для заявителя
это примерно 65 секунд. Проверяется содержимое, а не расширение.

Загрузка создаёт неизменяемую запись в личной библиотеке преподавателя.
Отмена редактора не удаляет файл; его можно выбрать позднее. Привязки меняются
при сохранении карточки с обычной проверкой revision и запретом редактирования
уже использованных карточек. Выбор аудио сохраняется в снимке сценария.

На каждую попытку и контакт вариант вычисляется по SHA-256 от случайных UUID
попытки и контакта. Распределение псевдослучайное, повторное открытие/повторный
звонок/перезапуск worker сохраняют выбор. TrainingCall хранит конкретный audio_id,
а для ДДС также ключи обеих реплик. Встроенные голоса сохраняют прежний случайный
выбор при каждом новом звонке.

## Библиотека и API

`GET /api/v1/telephony/recordings` — свои записи, поиск, назначение, пагинация,
использование в карточках и версиях сценариев. `POST` туда же — raw WAV,
параметры title и purpose (caller/greeting/acknowledgment). GET `/{id}` и
`/{id}/wav` — сведения и прослушивание. Только преподаватель-владелец;
ученик получает аудио через телефонный сервер, а не доступ к библиотеке.

CardCreate/CardUpdate/CardRead: `audio.caller_ids` и
`audio.crew_variants[{greeting_id, acknowledgment_id}]`. Доступность, готовность,
назначение и отсутствие дубликатов проверяет сервер. Неизменяемые записи
переиспользуются без копирования файлов. TTS-контракт сохраняется; новый экран
предназначен для готовых записей и не обещает неподключённого генератора.

Миграция 0033 импортирует прежние записи контактов в библиотеки их преподавателей.
Старые CallCue, снимки, вызовы и оценки не переписываются. В библиотеке видны
ссылки использования прежних записей в сценариях. Неподготовленные старые записи
помечены как неготовые и не предлагаются для новых карточек.

При подготовке ДДС теперь читается требование звонка из dds_exercise карточки,
а для прежних сценариев — из dds_policy. Отсутствие старого списка steps больше
не мешает подготовить стандартное приветствие обязательного звонка.

## Проверка

`tests/test_recordings.py`: содержимое и лимит файла, права, назначение реплик,
использование, неизменяемый снимок, карточечный ДДС, выбор пары при повторном
звонке. Старые тесты телефонии и диалога сохраняются. Браузерный сценарий
`e2e/card-recordings.spec.ts`: загрузка, прослушивание, обе роли, сохранение,
библиотека, повторное открытие, desktop/mobile. Браузер использует API-фикстуры;
телефонные команды и хранение проверены отдельно на PostgreSQL.
