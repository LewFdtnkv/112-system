# Заранее подготовленные реплики руководителей бригад

Два синтетических голоса Piper: `ru_RU-denis-medium`, `ru_RU-dmitri-medium`.
Для каждого три пары приветствие/подтверждение. Обе реплики разговора всегда одним
голосом. Фиксация варианта в `TrainingCall.dialogue` происходит до звонка.
Во время разговора TTS/LLM не вызываются; модель не входит в образ приложения.

Источник моделей и конфигураций: [rhasspy/piper-voices](https://huggingface.co/rhasspy/piper-voices),
commit `c10ece1aade47bb51c153c893d14e5bf8e5b7117`.
Карточка репозитория указывает MIT, обе карточки датасетов — CC0; исходные
`MODEL_CARD` сохранены рядом. SHA256 ONNX, WAV и широкополосного PCM в manifest.json.
Синтезатор Piper 1.8.0 (GPL-3.0) используется отдельным инструментом сборки,
не импортируется backend. Тексты реплик написаны для этого тренажёра.

Исходный синтез 22050 Гц, моно; нормализация с запасом по уровню и полифазная
передискретизация. `.sln16`: 16-битный signed little-endian PCM, 16000 Гц для Asterisk
с G.722. `.wav`: PCM 8000 Гц для существующего интерфейса записей и узкополосных
аппаратов. Это разные кодировки одной реплики. Возможности телефона/кодека могут
ограничить слышимое качество независимо от исходной записи.

Воспроизводимый инструмент: `scripts/voices/generate.py`. Его зависимости
`piper-tts==1.8.0`, `scipy==1.17.1` устанавливаются только в одноразовый контейнер.
Пути моделей передаются через `--models`, итоговый каталог через `--output`.
После изменения реплик необходимо прослушать варианты и обновить manifest вместе
с файлами; приложение проверяет хеши. Нельзя заменять речь тоном/тишиной в рабочем пакете.
